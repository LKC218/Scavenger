# 原作群尸运行检验台

> 现行规划见[正式策划书](../../docs/大地图肃清-正式策划书.md)与[开发目标及人工验收](../../docs/大地图肃清-开发目标与人工验收.md)。新主线采用《断箭》尸群、完全弃用卡通，以大规模表现和优化为优先；本文件记录已有候选实现及其证据，旧模型、动作和性能通过不代表新规则验收。当前仅整理文档，后续每目标先审设计再实现。

原作防线用`python -X utf8 -B scripts/原作群尸/启动.py --defense`独立进入8798，群体仍由原群体入口进入8797。根目录“打开载具靶场.cmd”已作为8784“战术演训原型”的兼容入口；本模块源码、版本及验收身份保持。见[统一命名说明](../../docs/地图与载具/战术演训原型统一命名-实施记录.md)。

独立验证Walker、Runner的原作LOD2运行候选，默认8797；原作防线候选8798复用已通过V003冻结代码，仅由独立适配接入新角色。该候选不覆盖8794的通过身份。

## 数据和姿态

两款保留46个骨架节点；它包含辅助节点，源蒙皮引用仍分别为39／40。每款9段原生Action保留，待机、移动、攻击、死亡采用显式名称映射；共享降落伞、游泳或坐姿片段的保留不代表战斗中会触发这些行为。

运行坐标Y向上、Z向前，未删骨或重制动作。首次载入从原片段烘焙GPU骨矩阵，运行时仅更新各实例的相位、状态、位置和朝向。矩阵插值与原SkinnedMesh在关键帧及帧间分别核对；96Hz烘焙是运行近似，不把矩阵线性混合称为原游戏状态机等价。初轮48Hz和后续96Hz的样本分开冻结，不混为同一参数下的性能结果。

同型共享网格、材质、贴图和骨骼姿态纹理。原作活体两批，旧十三款对照十三批；额外的地面、脚底阴影与场景图元独立计数。全部同屏时不能靠视锥剔除减少目标数量。示范的攻击死亡按钮是动作检视，不新增原游戏战斗机制。

## 采样边界

默认内部640×360，UI按显示尺寸布局，像素画面最近邻放大。复用既有正交镜头、群体流场和局部避让，30Hz模拟、显示插值。六组180秒测试的资源来源、数量、相机、源码摘要及真实WebGL GPU必须留证；无窗口压力对比与实际前台验收分别标注。

旧卡通对照使用独立冻结副本，默认运行入口迁移后只作为历史比较。013原工程及必要来源不作为网页运行依赖。服务、资源和制作说明见[制作工具](../../scripts/原作群尸/README.md)。

## 跨模块依赖

`入口.mjs`显式复用旧群体模块的纯数值逻辑、视图和统计，`防线适配.mjs`继承本轮冻结V003视图；运行不读取research资料。白名单路由固定具体源码身份，当前不改已通过V003文件以免混入新身份。原作候选验收及旧服务交接后，后续可把两处消费者共用的群体和统计接口抽到共享目录，再保留兼容适配；这是后续解耦落点，本轮未擅自迁移旧源码。
