# 本地工作项看板状态流转与多 Agent 协作规程

本文件为 [workboard-item-exec](../SKILL.md) 的执行细则，与 [本地工作项看板-实施计划](../../../../docs/研发协作/本地工作项看板-实施计划.md) 及 [看板工具.py](../../../../scripts/工作项看板/看板工具.py) 保持一致。

---

## 一、 8 列人机双闸门状态流转表

```text
[待规划 backlog] → [待开始 todo] → [方案待审 plan_review 🚧] → [进行中 in_progress 🤖]
                                                                        ↓
[已完成 done] ← [测试中 testing] ← [待测试 qa_wait 🚧] ←────────────────┘
                       ↓
                 [不通过 rejected ↩️] ──→ 返回 [待开始] / [进行中]
```

| 阶段 | 状态值 | 触发角色 | 推荐 CLI 命令 | 闸门要求 |
| :--- | :--- | :--- | :--- | :--- |
| 认领登记 | `todo` | AI Agent | `claim <KEY> --branch ... --scope ...` | 锁定 `agent_id`、`agent_branch` 与精确 `scope_paths` |
| 方案待审 | `plan_review` 🚧 | AI Agent | `submit-plan <KEY> --plan-file ...` | **人工卡点**：未获工程师确认严禁修改业务代码 |
| 批准开工 | `in_progress` 🤖 | 工程师 / 获批后 Agent | `approve-plan <KEY> --note ...` | 同步摘除 `需评审` 标签（如有） |
| 执行心跳 | `in_progress` | AI Agent | `heartbeat <KEY> --note ...` | 关键里程碑刷新，防止看板显示超时失联 |
| 提交测试 | `qa_wait` 🚧 | AI Agent | `submit-qa <KEY> --note ...` | 必须附通过的验证命令结果；UI/视觉单补前后对比图 |
| 人工测试 | `testing` | 工程师 / QA | `start-testing <KEY>` | 实机核验画面、交互与边缘用例 |
| 打回返工 | `rejected` ↩️ | 工程师 / QA | `reject <KEY> --reason ...` | 严格模式下强制填写具体打回原因 |
| 验收结单 | `done` | 仅工程师确认后 | `done <KEY> --note ...` | 严禁 AI 跳过人工确认自行结单 |

## 二、 实施方案（`plan_md`）标准模板

`plan_md` 与正文 `description_md` 严格分工：正文只写 What，实施方案只写 How，控制在精炼可读范围内：

```markdown
### 1. 现状与根因定位
- <结合模块 entry_paths 与附件截图定位到的核心文件与原因>

### 2. 模块红线与冲突核对
- 所属模块：<模块名>（红线核对：无越界 / 已规避 ...）
- 作用域路径：<拟改相对路径列表>（路径冲突：无冲突 / 已与 SCAV-X 错开）

### 3. 拟改文件与改造步骤
1. `<项目相对路径 1>`：<具体改动要点>
2. `<项目相对路径 2>`：<具体改动要点>

### 4. 验证与验收方式
- 自动校验：<模块 verify_cmd + python -X utf8 -B scripts/检查项目结构.py>
- 人工核验：<工程师需确认的画面/交互/数据点>
```

## 三、 标签驱动计划与验收策略

执行 Agent 应根据 `pull` 返回的实时标签动态调整方案与交付重点：

| 命中标签 | 方案阶段重点 | 提测 / 交付阶段重点 |
| :--- | :--- | :--- |
| `缺陷修复` | 根因定位 + 最小影响面修复 + 防回归检查 | 必须说明复现链路已消除，避免顺带做大范围重构 |
| `功能需求` | 核对验收标准、数据契约变更、边界兜底 | 逐条对照正文 `- [ ]` 验收标准说明验证结果 |
| `性能优化` | 明确优化前基线数据与热路径约束（禁每帧堆分配） | 必须给出优化前后量化对比（帧率/耗时/内存） |
| `UI/UX` | 核对 Code SSOT V2.2 令牌、16:9 & 21:9 双画幅与无滤镜 HUD 层 | 必传修复前后截图（`attach`），同步核查 `/ui-spec` 三向同步 |
| `资产管线` | 明确只读输入来源、独立批次目录与规格目标 | 核验六视角/听感/IoU；涉及替换时走 `清理工具.py stage/accept` 7 天退役 |
| `数值/规则` | 严格核对 `ba-source-ssot-v1` 唯一基底与 `GLOBAL_BALANCE_SCALES` | 禁止私写局部换算系数，必过 `检查项目结构.py` 基线门禁 |
| `需评审` | **必须给出 ≥ 2 套可选方案对比（含优缺点与推荐项）** | 方案拍板开工后，用 `update <KEY> --remove-label "需评审"` 摘除 |

## 四、 冲突、父子联动、打回与清理交接规程

1. **父子工作项协同规则**：
   - 执行**子工作项**时，`pull <KEY>` 会自动注入 `[所属父工作项]` 总目标与 `[同父兄弟子项]` 的状态/模块/作用域；制定方案前须核对兄弟单的接口口径与文件路径，严禁越界修改兄弟单的代码目录。
   - 若子单存在未完成的前置依赖（`blocked_by_details` 非 `done`），须先向工程师确认是否等待前置单交付后再推进，避免基于过期接口返工。
   - 结单**父工作项**时，看板会拦截存在未完成子项的 `done` 请求；常规情况下须等全部子项验收通过后再对父单执行联合验收结单（仅当工程师明确要求跳过未完成项时才使用 `done <KEY> --force`）。
2. **路径冲突处理**：
   - 若 `pull` 提示与其他 `plan_review` / `in_progress` 单据 `scope_paths` 重叠，优先与工程师确认：串行等待（追加 `--blocked-by`）或缩小作用域拆分文件边界，避免多 Agent 覆盖彼此改动（直接父子关系已自动豁免假冲突）。
3. **乐观锁（HTTP `409 Conflict`）处理**：
   - 若 `update` 或流转报 `409`，说明他人或其他 Agent 刚更新了卡片，必须重新 `pull <KEY>` 阅读最新评论与状态后再决定下一步，严禁盲目覆盖。
4. **跨会话清理保护收口**：
   - 遵循 `AGENTS.md` 与 [版本退役与缓存清理规则](../../../../docs/版本退役与缓存清理规则.md)：
     - 提测阶段若尚待工程师人工验收，本轮清理保护任务保持 `active` 并明确汇报「等待验收暂缓 `close`」；
     - 涉及历史载荷替换时先 `stage` 出摘要，仅在工程师明确确认该具体新版通过后再执行 `accept` 与 `close`。
