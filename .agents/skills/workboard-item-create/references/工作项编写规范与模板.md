# Scavenger 工作项编写规范与标准模板（SSOT）

本文件是 [workboard-item-create](../SKILL.md) 的配套详细规范，同时与 [看板工具.py](../../../../scripts/工作项看板/看板工具.py) 的机械门禁及 18800 网页端新建模板保持 100% 同源。

---

## 一、 标题命名规范

**公式**：`[类型] 对象/场景 + 核心目标或异常现象`

| 类型前缀 | 适用场景 | 推荐默认标签 | 规范示例 |
| :--- | :--- | :--- | :--- |
| `[需求]` | 新增玩法机制、界面能力、系统模块 | `功能需求` | `[需求] 战术沙盘新增三区占领进度条与失守警报` |
| `[缺陷]` | Bug、逻辑错乱、渲染异常、崩溃、门禁失败 | `缺陷修复` | `[缺陷] 21:9画幅下固定翼投弹圈偏移且闪烁` |
| `[优化]` | 体验打磨、帧率/内存性能提升、视觉/音效微调 | `性能优化` 或 `UI/UX` | `[优化] 减少500只丧尸同屏时的骨骼更新耗时` |
| `[任务]` | 工程基建、工具脚本、文档治理、清理与门禁 | `AI协作` | `[任务] 补齐主服务全链路回归脚本的21:9用例` |
| `[资产]` | 断箭只读提取、模型/贴图/音效入库、离线编译替换 | `资产管线` | `[资产] 重编M1A2主战坦克三档LOD并验证IoU` |

- **长度约束**：建议 **≤ 32 字**，机械门禁硬上限 **42 字**，前缀后有效描述至少 4 字。
- **反例（禁止）**：`修复bug`、`优化地图性能问题并且把编辑器里的按钮也顺便改一下颜色和边距`、`A-10C不对`。

## 二、 五类极简正文模板（`description_md`）

> 统一字数预算：有效正文 **150 ~ 350 字**（不含截图），每小节 ≤ 4 条、每条 ≤ 2 句；**只写 What，禁写 How，严禁出现本机盘符绝对路径**。

### 1. 缺陷（`[缺陷]`）

必填小节：`触发场景`、`复现步骤`、`实际表现`、`预期表现`

```markdown
### 触发场景
- 路由 / 模式：<如 /play 9km 实战 · 21:9 680p>
- 前置条件：<如 编组 3 辆 M1A2 + 1 架 A-10C>

### 复现步骤
1. <触发前置操作>
2. <关键交互步骤>
3. <观察位置>

### 实际表现
<1~2 句话客观描述异常现象，截图通过附件上传>

### 预期表现
<1~2 句话描述正确行为，直接作为测试验收口径>
```

### 2. 需求（`[需求]`）

必填小节：`背景与目标`、`核心变更`、`验收标准`（`架构约束` 按需填写）

```markdown
### 背景与目标
<1~2 句话说明痛点、玩法价值或关联的 G00–G08 目标>

### 核心变更
- <外部可见的界面、交互或规则变化 1>
- <外部可见的界面、交互或规则变化 2>

### 架构约束
- <如：严格遵循 680p 基线 / ba-source-ssot-v1 / Code SSOT V2.2 / 8800 单端口>

### 验收标准
- [ ] <可客观验证的验收条件 1>
- [ ] <可客观验证的验收条件 2>
```

### 3. 优化（`[优化]`）

必填小节：`背景与目标`、`核心变更`、`验收标准`

```markdown
### 背景与目标
<1~2 句话说明当前体验/性能瓶颈及预期量化提升>

### 核心变更
- <体验、渲染或性能改进项 1>
- <体验、渲染或性能改进项 2>

### 验收标准
- [ ] <可量化或实机核验的达标指标>
- [ ] <既有主流程与视觉风格零回归>
```

### 4. 技术任务（`[任务]`）

必填小节：`任务目标`、`执行范围`、`完成标准`

```markdown
### 任务目标
<1~2 句话说明要达成的工程、脚本或文档治理目标>

### 执行范围
- <明确纳入项与产出落点>
- <明确不修改范围，防止越界联动>

### 完成标准
- [ ] <可运行的自动化脚本或全仓门禁通过，如 scripts/检查项目结构.py>
```

### 5. 游戏资产（`[资产]`）

必填小节：`资产对象与来源`、`交付规格`、`验收与退役要求`

```markdown
### 资产对象与来源
- 目标资产：<型号 / 稳定 ID / 批次>
- 输入来源：<只读来源或资料库 ID，严禁写本机绝对路径>

### 交付规格
- <LOD / 贴图档位 / 声道规格 / IoU 或帧率基准指标>

### 验收与退役要求
- [ ] <视觉六视角 / 听感 / 引擎实机人工验收项>
- [ ] <涉及旧版替换时：登记清理工具 stage/accept 7 天退役流程>
```

## 三、 结构化侧栏字段填写指南

### 1. 初始状态（`state`）
- `todo`（**默认**）：已确认要推进的工作项，可直接等待认领或排期开发。
- `backlog`：纯远期构想、备忘或待拆解的大议题，暂不进入活跃开发队列（仅 `backlog` 允许暂缓填写 `scope_paths`）。

### 2. 优先级分级（`priority`）
- `urgent`（紧急）：主链路崩溃、服务无法启动、全仓门禁红灯、阻断多 Agent 协作。
- `high`（高）：当前主线（G00–G08）核心功能或影响面广的显性缺陷。
- `medium`（中，**默认**）：常规功能需求、体验优化、工具补齐。
- `low`（低）：锦上添花的细节打磨或远期整理任务。

### 3. 标签选配（严禁自造）
SCAV 预置 8 个标准标签（建单前务必用 `meta` 核对实时列表）：
- **性质类（优先选 1 个）**：`功能需求`、`缺陷修复`、`性能优化`、`资产管线`
- **领域/流转类（按需选 0~1 个）**：`UI/UX`、`数值/规则`、`AI协作`、`需评审`（方案尚有分歧、需要 ≥2 套方案对比拍板时必挂）

### 4. 作用域路径（`scope_paths`）填写红线
- 必须是**项目相对路径**（正斜杠 `/`），禁止 `E:\...`、`C:\...` 或 `..`。
- 非 `backlog` 状态**必填 1~3 条**，推荐精确到具体业务子目录或核心文件：
  - 好例子：`src/交互系统/指令与标绘层.mjs`、`src/工作项看板/`、`scripts/断箭/`
  - 坏例子：`src/`、`scripts/`、`docs/`（过宽目录会导致多 Agent 并行误报冲突）
- 若存在强先后顺序，务必通过 `--blocked-by SCAV-X` 声明前置阻塞单号。

## 四、 机械门禁阈值总表（对应 `看板工具.py`）

| 检查项 | 阻断错误（Error） | 提醒警告（Warning） |
| :--- | :--- | :--- |
| 标题前缀 | 不属于 5 类前缀之一，或前缀后有效描述 < 4 字 | — |
| 标题长度 | > 42 字 | 33 ~ 42 字 |
| 正文有效字数 | < 25 字 或 > 650 字 | 25 ~ 89 字 或 421 ~ 650 字 |
| 必填小节 | 缺失该类型任一必填 `### 小节` | — |
| 正文禁区 | 出现盘符/用户目录等本机绝对路径 | 包含 ≥ 2 处多行代码块 |
| 作用域路径 | 非 `backlog` 且为空；或含盘符/`..` | 写了 `src`/`scripts`/`docs` 等根目录 |
| 所属模块/标签 | 传参名称不存在于当前项目 | 留空未填 |

## 五、 提交前预览卡片参考格式

在调用真实建单前，向工程师展示如下紧凑预览卡并等待确认：

```markdown
### 新建工作项预览（SCAV）
- **标题**：`[缺陷] 21:9画幅下固定翼投弹圈偏移`
- **属性**：状态 `待开始 (todo)` ｜ 优先级 `高 (high)` ｜ 模块 `操作交互与战术标绘` ｜ 标签 `缺陷修复, UI/UX`
- **归属**：负责人 `工程师` ｜ AI Agent `待认领`
- **作用域路径**：`src/交互系统/指令与标绘层.mjs`（冲突校验：无冲突 / ⚠ 与 SCAV-X 重叠）
- **附件 / 外置线索**：无 / 1 张截图 + 首条源码线索评论

> **精简正文（198 字 · 门禁通过）**
> （此处展示完整 Markdown 正文）

请确认是否按上述内容创建工作项？
```
