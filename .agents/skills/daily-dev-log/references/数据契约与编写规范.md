# 每日开发日志数据契约与编写规范

本参考文档定义 `reports/开发日志/数据/YYYY-MM/YYYY-MM-DD-开发日志.json` 的精确字段结构与提炼标准，配套 [SKILL.md](../SKILL.md) 使用。

## 1. 顶层 JSON 结构

```json
{
  "date": "2026-11-22",
  "timezone": "Asia/Shanghai (UTC+8)",
  "mode": "curated",
  "generated_at": "2026-11-23 00:45:00 +0800",
  "headline": "一句话概括全天几条主线的核心突破与里程碑（建议 50~90 字）。",
  "kpis": {
    "goals_achieved": 2,
    "goals_total": 6,
    "pending_actions": 4,
    "repo_files": 56,
    "git_dirty": 145
  },
  "goals": [],
  "actions": [],
  "cleanup_summary": {
    "closed_count": 9,
    "active_count": 11,
    "waiting_acceptance": []
  },
  "repo_snapshot": {
    "commits": 0,
    "dirty_count": 145
  }
}
```

## 2. 目标项 `goals[]` 字段规范

每条对象对应看板中的一张卡片（按逻辑目标归并，不要按单次聊天轮次拆碎）：

| 字段 | 类型 | 说明与写法要求 |
| --- | --- | --- |
| `id` | `string` | 唯一短 ID，如 `"goal-hud-minimap"`（用于拖拽与状态持久化） |
| `title` | `string` | 干练目标标题（建议 14~28 字，卡片首行主视觉） |
| `category` | `string` | 简短模块分类（2~5 字），如 `界面与交互`、`材质与表现`、`工程基建`、`玩法与规范`、`资产提取`、`性能优化` |
| `status` | `string` | 严格枚举 4 选 1，决定默认落入哪个泳道：<br>- `"waiting_accept"` → 左列「待验收 / 待拍板」（胶囊：`待验收`）<br>- `"waiting_decision"` → 左列「待验收 / 待拍板」（胶囊：`待拍板`）<br>- `"in_progress"` → 中列「进行中 / 跨天跟进」（胶囊：`进行中`）<br>- `"done"` → 右列「已完成 / 已验证」（胶囊：`已通过`） |
| `status_label` | `string` | 简短中文状态说明，如 `"已通过双端验证"`、`"待你实机验收"`、`"方案已出 · 待确认开工"` |
| `summary` | `string` | 1~2 句人话总结“完成了什么目标、解决了什么问题”（≤ 90 字，展示在抽屉与简报视图） |
| `highlights` | `string[]` | 2~3 条简短进展亮点（每条 ≤ 35 字，展示在右侧详情抽屉） |
| `metrics` | `object[]` | 1~3 项量化对比，第 1 项会直接高亮显示在看板卡片上：<br>`{"label": "3KM 矢量构建耗时", "before": "2628.3 ms", "after": "45.2 ms"}`<br>无旧值对比时 `"before"` 填 `"-"`，禁止把实测现状写成删除线旧值 |
| `sessions` | `object[]` | 关联会话时段（用于计算左/顶栏「精力分布」占比与卡片底栏时长）：<br>`{"tool": "Antigravity"\|"Codex", "id": "8位短ID", "start": "HH:MM", "end": "HH:MM", "label": "简短阶段名"}` |
| `files` | `string[]` | 涉及的核心项目相对路径列表（仅列关键改动文件，通常 3~8 个；纯只读分析填 `[]`） |
| `verification` | `string` | 一句话如实说明验证方式与结果（区分技术验证通过与待工程师人工验收） |

## 3. 待拍板与验收项 `actions[]` 字段规范

汇集散落在各会话中需要工程师下一步处理的事项，展示在顶栏 `待办 (N)` 抽屉中：

```json
{
  "id": "act-blender-accept",
  "type": "accept",
  "title": "检查并验收 15 款原作丧尸 Blender 总场景（V001-r02）",
  "detail": "打开工程核对 14 款蒙皮角色与 126 个动作，确认通过后执行 accept 收口。",
  "ref": "local-data/维护清理/验收待确认/d4d53176a06c49b090abda21bc299f7d.json"
}
```

- `type` 取值：`"accept"`（验收确认）或 `"decision"`（方案拍板）。

## 4. 质量自检清单

- 文件路径严格满足 `reports/开发日志/数据/YYYY-MM/YYYY-MM-DD-开发日志.json`；
- JSON 中 `"date"` 与文件名一致，`"mode"` 为 `"curated"`；
- 全文无本机用户目录盘符路径、Steam 盘符绝对路径或私人敏感信息；
- `metrics[0]` 简短有力（`after` 字段 ≤ 20 字符），避免在卡片单行指标条内折行挤压；
- `kpis.goals_achieved`、`goals_total`、`pending_actions` 与实际数组统计一致。
