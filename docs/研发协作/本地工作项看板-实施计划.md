# 本地工作项看板与多 AI Agent 任务分配系统 — 完整实施计划（V001）

> **核心定位**：参考 [Plane](https://github.com/makeplane/plane) 的多项目工作项与看板交互体系，构建一套 **单人零摩擦、局域网团队零重构、原生面向多 AI Agent 并行协作** 的独立本地协作基础设施。
>
> **专属端口与隔离红线**：锁定专属端口 **`18800`**（进程、端口、数据与 Scavenger 游戏主服 `127.0.0.1:8800` 彻底拆分），单人默认监听 `127.0.0.1:18800`，局域网模式按需切 `0.0.0.0:18800`；游戏 `local-data/` 资产永不暴露至局域网。

---

## 一、 架构边界与核心设计原则

### 1.1 端口与进程独立拆分
- **专属端口锁定 `18800`**（避开 Scavenger `8766–8814`、常规开发 `3000/5173/8000/8080/8090/9000` 及 Windows 常见 Hyper-V/TCP 保留排除段 `10001–14950`、`50000–50059`）。
- **禁止静默飘移端口**：端口被外部进程占用时只诊断并报告 PID 与可执行路径，不强杀外部进程、也不自动递增随机端口，保证团队书签与 AI Agent 环境变量稳定。
- **身份指纹与复用**：`/healthz` 返回 `service: "scavenger-workboard"`、`pid`、`port`、`host`、`auth_mode`、`data_dir_sha256`、`uptime_seconds`；启动脚本检测到自身已在运行则直接复用。
- **可随时整目录迁出**：源码集中在 `scripts/工作项看板/` 与 `src/工作项看板/`，全部运行态数据位于 `local-data/工作项看板/`（Git 忽略）；未来团队启用独立局域网主机或独立仓库时，可直接整目录迁移运行。

### 1.2 单人零摩擦 → 局域网团队零重构（5 条底层底线）
1. **乐观锁版本号（`rev`）**：每张工作项维护整型 `rev`，所有更新/拖拽/CLI 回写支持 `expected_rev`，冲突返回 HTTP `409 Conflict` 并附带最新卡片快照，杜绝人与 Agent 或局域网多人并发覆盖。
2. **双轨身份模型（`members`）**：底层统一建模 `human`（人类成员）与 `agent`（AI 执行槽位，带独立 `api_token`）。
   - `local_single`（默认）：本机网页免登录，支持顶部一键切换操作视角；
   - `lan_pin`（局域网模式）：成员选名 + 个人 PIN 登录（HttpOnly Cookie 记住 30 天），AI Agent 通过 `X-Board-Token` 鉴权，评论与事件审计清晰区分“某同事本人”与“某同事挂载的某 Agent”。
3. **全链路项目相对路径**：工作项 `scope_paths`、模块 `entry_paths` 与验证命令统一记录项目相对路径（如 `src/交互系统/`），不写死本机盘符绝对路径。
4. **附件 HTTP 内容寻址托管**：网页 `Ctrl+V` 贴图、拖拽上传或 CLI `--image` 均经 `/api/v1/attachments` 上传至 `local-data/工作项看板/附件/`，按 SHA-256 去重并以 `/api/v1/attachments/<sha256>.<ext>` 访问。
5. **时间口径统一**：SQLite 内部一律存 UTC ISO-8601（`Z` 结尾），前端与导出展示统一换算为北京时间（`UTC+8`）。

## 二、 8 列人机闸门状态流与防撞机制

### 2.1 状态流转（兼容 Plane 7 列 + 显式方案闸门）

```text
[待规划 backlog] → [待开始 todo] → [方案待审 plan_review 🚧] → [进行中 in_progress 🤖]
                                                                        ↓
[已完成 done] ← [测试中 testing] ← [待测试 qa_wait 🚧] ←────────────────┘
                       ↓
                 [不通过 rejected ↩️] ──→ 返回 [待开始] / [进行中]
```

- **严格模式（`strict_mode`）可按项目开关**：
  - 关闭（单人默认）：自由跨列拖拽，高效推进；
  - 开启（局域网团队推荐）：拖入 `rejected`（不通过）强制填写打回原因，进入 `done` 提示确认验收意见。

### 2.2 多 AI Agent 核心生产力能力
1. **双轨归属与实时心跳**：卡片同时记录 `owner_id`（人类责任人）与 `agent_id` + `agent_branch` + `agent_host` + `agent_heartbeat_at`（AI 执行态），超时未刷新心跳自动灰显提醒。
2. **作用域路径防撞雷达（`scope_paths`）**：后端自动检测同一项目内所有处于 `plan_review` / `in_progress` 状态的工作项 `scope_paths` 是否存在前缀包含或路径重叠，实时在看板卡面、抽屉与「Agent 雷达」视图标出黄色预警。
3. **模块即 AI 上下文包（`modules`）**：每个模块结构化维护 `职责范围`、`现有能力`、`架构红线`、`入口路径`、`验证命令`；AI Agent 执行 `看板工具.py pull <KEY>` 时自动聚合单据正文 + 附件清单 + 所属模块上下文包 + 阻塞依赖摘要。
4. **一键复制 Agent 开工指令**：卡面与抽屉右上角一键生成标准化 Prompt，直接贴入任意新会话即可按规程拉单、写方案并停在 `plan_review` 等待确认。

## 三、 存储层与接口契约

### 3.1 SQLite（WAL 模式）核心表结构
位于 `local-data/工作项看板/数据/workboard.db`（开启 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`）：
- `projects`：`id, key, name, description, strict_mode, next_seq, created_at, updated_at`
- `members`：`id, name, display_name, kind(human|agent), role, avatar_color, pin_hash, api_token, is_active, created_at`
- `modules`：`id, project_id, category, name, summary, scope_desc, capabilities, redlines, entry_paths_json, verify_cmd, color, created_at, updated_at`
  - Scavenger 默认按 5 大业务域分类预置 13 个实战模块：`核心玩法与战斗`（载具战斗与数值基底 / 尸群系统与动画分级 / 大地图任务与后勤经济）、`交互与界面`（操作交互与战术标绘 / 全局UI规范与主入口）、`地图、载具与视听表现`（9km程序化大地图与编辑器 / 129车程序化载具与动效 / 写实爆炸与战场特效 / 战场声学与空间音效）、`资产管线与主服务`（断箭资产提取与前线库 / 8800主服务与工程门禁）、`团队协作与研发工具`（工作项看板与多Agent协作 / 每日开发日志与简报），支持自由扩展与自定义分类。
- `labels`：`id, project_id, name, color`
- `work_items`：`id, project_id, seq_num, item_key, title, description_md, plan_md, state, priority(urgent|high|medium|low|none), module_id, owner_id, agent_id, agent_host, agent_branch, agent_heartbeat_at, scope_paths_json, blocked_by_json, sort_order, rev, created_by, created_at, updated_at`
- `work_item_labels`：`work_item_id, label_id`
- `comments`：`id, work_item_id, author_id, body_md, comment_type(comment|plan|qa|reject|system), created_at`
- `attachments`：`id, work_item_id, sha256, filename, mime_type, size_bytes, uploaded_by, created_at`
- `activity_events`：`seq(AUTOINCREMENT), project_id, work_item_id, actor_id, event_type, payload_json, created_at`

### 3.2 REST API & SSE 实时同步
- **基础探活与鉴权**：`GET /healthz`、`GET /api/v1/bootstrap`、`POST /api/v1/auth/login`、`POST /api/v1/auth/logout`
- **多项目与成员**：`GET/POST /api/v1/projects`、`PATCH /api/v1/projects/<id>`、`GET/POST /api/v1/members`、`PATCH /api/v1/members/<id>`
- **模块与标签**：`GET/POST /api/v1/projects/<id>/modules`、`PATCH/DELETE /api/v1/modules/<id>`、`POST /api/v1/projects/<id>/labels`
- **工作项闭环**：
  - `GET /api/v1/projects/<id>/items`（返回卡片列表 + 实时路径冲突映射 `conflicts`）
  - `POST /api/v1/projects/<id>/items`
  - `GET /api/v1/items/<id_or_key>`（含评论、附件、模块上下文包、前置依赖状态、冲突列表）
  - `PATCH /api/v1/items/<id_or_key>`（支持 `expected_rev` 乐观锁校验）
  - `POST /api/v1/items/<id_or_key>/transition`（显式状态机闸门：认领 / 提交方案 / 批准开工 / 提交测试 / 打回 / 结单）
  - `POST /api/v1/items/<id_or_key>/heartbeat`（AI Agent 心跳与分支汇报）
  - `POST /api/v1/items/<id_or_key>/comments`
  - `DELETE /api/v1/items/<id_or_key>`
- **附件与事件流**：
  - `POST /api/v1/items/<id_or_key>/attachments`（支持 Raw/JSON Base64/Multipart，SHA-256 去重）
  - `GET /api/v1/attachments/<sha256>.<ext>`（Immutable 强缓存）
  - `GET /api/v1/events`（SSE 长连接，推送 `board_update` 事件携带 `seq`、`project_id`、`item_key`，多端 1 秒内无感同步）

### 3.3 AI Agent CLI（`scripts/工作项看板/看板工具.py`）
与 Web 前端共享同一套 `/api/v1/*` 接口，零第三方依赖（仅 Python 标准库）：
- `meta`：查看项目、状态、模块与成员
- `list`：按项目/状态/负责人筛选工作项
- `pull <KEY>`：拉取精简 What 需求、附件、所属模块上下文包、冲突警告与历史评论
- `create`：新建工作项（支持 `--module --priority --owner --scope --desc --image`）
- `claim <KEY>`：认领工作项并登记 `agent_branch` / `agent_host`
- `submit-plan <KEY>`：提交实施计划并流转至 `plan_review`
- `approve-plan <KEY>` / `start <KEY>` / `submit-qa <KEY>` / `reject <KEY>` / `done <KEY>`：完整人机闸门流转
- `heartbeat <KEY>`：更新当前执行心跳与分支信息
- `comment <KEY>` / `attach <KEY> <图片路径>` / `conflicts`：追加交付说明、上传截图与冲突排查

3. **本机实机启动验证**：启动 `http://127.0.0.1:18800/`，核对 `/healthz` 指纹、零报错渲染与交互可用，随后交由工程师实机测试并反馈体验。
