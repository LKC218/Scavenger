1. 按G00至G08的依赖推进：**确认实施卡→制作与集成→技术检查→具体版本人工验收**。当前只推进G01，原三线并行授权不用于继续G02及后续目标；分工协作须限于当前批准范围。
2. 本目标未通过先回改，不以技术检查替代可玩性。恢复后续目标前明确当前阶段人工结论；对空／专用待补项单列，不算完整通过，也不让前后阶段互等。
3. G05本阶段范围经人工通过即可进入G06；G06开工不授权敌方空中或其他未批准专项，相关补验仍先交设计。
4. 每次交付固定候选入口、短步骤、逐项表、已知问题，绑定版本、源码及资产身份；变化后按影响复验。

6. 不预建空卡、目录或脚本；开工待定项先在当前设计卡锁定。

## 二、性能贯穿要求

- 开发电脑、键鼠、Chrome／Edge，目标稳定60帧；大规模尸群优先，近景为战术尺度，不追求个体特写。
- 近景保识别，远景简化动画／特效；真实移动、伤害、弹药、敌情权限及占区判定不变。
- 每卡先定数量、模型组合、镜头、画质、声音、指标与持续时间再测，不自设数量或门槛。
- G01起随功能记录帧时间、模拟／显示成本及异常；后续组合复验，不用单项成绩代替完整战斗。

- [ ] 近完整远简化不改真实战斗；获准目标条件确认后补验防空，不自动扩系统。

开工前待定：逐车顺序、返航／费用、高度／航线、诱饵／视野参数、飞行表现、对空补验范围。

### G07-三区玩法闭环整合

状态：未开工。

交付：侦察、诱导、后勤、增援接入三区无倒计时任务，复验真实行为／声源／视野连接。

人工验收：

- [ ] 三区自由顺序；原属全灭，区外杀也算，原属剩余可查。
- [ ] 区内外来清空，移动地面战斗车驻守；补给车／固定平台不算。
- [ ] 入侵中断／失守，重占不重复奖励，同时控三区胜利。
- [ ] 已探索地形、当前敌情、带时间最后位置分清，所有标签／群声／选取／火力守权限。
- [ ] 首奖买部队／物资仍运输；首区弹药与收益可推进，不等待或反复占区刷点。
- [ ] 无力量且无补给／在途或可召集增援能恢复才失败，暂时弹尽不误判。

开工前待定：区域／原属边界、驻守／占领／失守条件、初始编成、奖励／预算、入口和胜负显示。

### G08-全组合复验

状态：未开工。

交付：冻结全组合候选、逐车结果与已知问题，按设计卡矩阵复验。

人工验收：

- [ ] 入口、版本、源／资产身份一致，短步骤复现，未验专项仍清楚列出。
- [ ] 两浏览器键鼠完成任务、镜头、地空混选和后勤，无操作回归。
- [ ] 远景战斗、追逐、死亡／爆炸、返航／增援和重开不漏算、重算或泄情。
- [ ] 按约定负载对照稳定60帧目标，近景识别、远景简化、画面和声音经人工确认，长帧等问题如实列明。
- [ ] 工程师确认具体候选；本范围问题回所属目标，待补专项不冒充完整通过。

开工前待定：组合数量／镜头／指标／时长、最终阻塞项、待补清单和依赖交接。

## 五、风险登记

- 规模／分级：先锁样本，远景简化不改战斗，不承诺未测数量。
- 资源缺陷：列清骨架、动作、声音、特效及适配缺项，不假通过。
- 经济软锁：核算首区预算、运输恢复及购车替代补给风险，不改已确认首弹含价。
- 范围依赖：对空、运兵、工程、两栖、牵引等逐项另审，明确本阶段阻塞或待补，避免互等。
- 版本交接：按[项目约定](项目结构与开发约定.md)、[退役规则](版本退役与缓存清理规则.md)和[维护说明](../scripts/维护清理/README.md)保护原件及活动依赖；实现时同步导航和近模块说明。
