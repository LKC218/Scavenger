# 靶场阴影优化实施计划

## 已确认范围

工程师确认：保持像素风，车底扎实、边缘轻微渐淡并有短方向感；固定白天和太阳方向；首轮允许建筑遮光简化。优化以当前相同条件实测性能不退化为目标，不将绘制批次数不变等同于零开销。

本轮修改载具靶场现有地面假阴影和两盏灯参数。镜头、操作、战斗、音频和资源原件保持现有设置。车身先核查现有材质并校准光照，单独AO烘焙不在本轮实现范围。

## 实现方案

- 保存改前场景源码与摘要，在独立验证浏览器中拦截该模块生成真实改前对照，不在游戏增加开发切换控件。
- 以带顶点透明度的低面数网格替换实心椭圆，保留每型号一个实例批、每单位一份阴影；纹理和渲染通道数量不增加。
- 按车型设置轮廓、跟随车身朝向，按固定太阳方向产生有限地面偏移；空中载具按高度改变偏移与浓淡。平面影只适用于当前平地，不提供建筑挡光、墙面接收或真实自阴影。
- 用现有半球光和方向光校准车身层次，保持内部像素渲染和清晰界面。

## 验收口径

视觉需要工程师最终试玩确认；自动检查不替代观感验收。性能对比必须使用相同视口、画质、镜头和资源版本。帧时间受刷新率限制时另查GPU计时能力；不可用则明确标注，不据此宣称GPU成本完全不变。若对照出现可重复退化，先调整实现再交付。

## 实施中确认的边界

- 现有主要材质已有AO及法线贴图；保持原信息，没有额外烘焙。
- 验证遇到旧服务清单与路由不一致，以及8770与资源验证端口冲突。自动审批拒绝重启旧8768的组合操作后，未再终止该旧服务；本轮新建系统分配端口的独立服务。修复预览脚本，将清单冻结在每服务内存；只关闭了本轮自行启动的两个中间服务。
- 平面二维转角经车身世界轴核对后修正符号，再执行最终采样；修正前的中止回执只作排障。
- Chrome500单位首测GPU分位出现异常，追加改后／改前反序复测；首测和复测同时保留，不改写为单一较优样本。

## 实际完成与验收边界

两浏览器视觉、斜向轴、真实右键移动跟影、道路与连续重置通过；最终固定30单位对照画面绘制46到43、纹理52不变、几何对象41到43。8组正式交战加2组反序复测的帧P95均约7.20毫秒，最长14.30毫秒，超过33.34毫秒为0。当前使用同一版本压缩运行资产，不能直接与旧资产阶段容量比较。

额外完成4组同上下文冻结场景GPU隔离：每组16轮改前／改后／改后／改前，每侧32份查询、每份4次渲染均值。中位数接近，500单位尾部分位仍有波动，不能声明所有时刻GPU零开销。具体数值见[验证报告](../reports/载具靶场/阴影优化验证.md)。当前本机60FPS帧预算通过，工程师视觉观感、可见窗口长期试玩及其他设备仍待验收。

全项目结构检查仍有其他资源优化脚本缺导航及一个本机路径检查项；本轮未代改其他对话源码，靶场文件与报告未列入失败项。
