# Scavenger 网页端性能优化完整实施计划

> **文档定位**：本实施计划基于 RX 7900 XTX 真机硬件 WebGL 全景基准采数与全链路热路径源码审计编制，为正式主干（`http://127.0.0.1:8800/`）提供**四阶段、按投入产出比（ROI）与现行策划主线优先级排序、逐阶段独立可验收**的性能优化工程蓝图、精确代码改造方案、量化回归门槛与 18800 看板拆单草案。
>
> **立项与排期策略（经评审校准）**：
> - **Phase 1（P0 必做 · 0.5 天）**：优先落地，消除战争迷雾 10Hz 同步阻塞（补齐混编样本身份与阵营过滤 + 纯建筑 OBB 遮挡缓存 + 静止射线复用）、清零热路径强制回流与 CSS 查询、修复全精度升级并发重入，并在任务 1C 落地后**补采 50 车满编与单次正常玩家冷启动真实基线**；
> - **Phase 2（P1 可选专项 · 0.5 天）**：仅聚焦真机实测可感的 `242.5ms` 首次切近景卡顿与低风险 `4×4` 远景分块，不抢占核心玩法排期，待 `SCAV-8/9/12/13` 验收结单并获授权解冻 [地图编辑器.mjs](../src/程序化地图/地图编辑器.mjs) 后择机实施；
> - **Phase 3（P1 闸门驱动 · 暂置 `backlog`）**：在 Phase 1 并发锁修复后按单次真实玩家升级基线复测判定；若仍存在 `> 60ms` 后台升级长任务或峰值堆超标，先用轻量让帧与分阶段消费释放收口，仅在仍不达标时引入 `SCVH` 单职责 Worker；
> - **Phase 4（P2 远期按需 · 排在核心玩法 `SCAV-2 / SCAV-3` 落地后）**：统一承接面向中端显卡与轻薄本核显的深度减负（近景建筑/树木旋转 2D OBB 裁剪、太阳阴影强度渐变与按需脏标节流、Live PiP WebGL2 双缓冲 PBO 异步回读与 9km 道面分块）。
>
> **强约束基线（绝对红线）**：
> - **唯一服务与主干**：统一运行于 `http://127.0.0.1:8800/`（[启动主服务.py](../scripts/启动主服务.py)），严禁新开独立业务 HTTP 端口或复制平行试验 `src/` 目录；
> - **唯一渲染基线**：严格零改动保留 [渲染风格与分辨率基线规范](渲染风格与分辨率基线规范.md) 及 [渲染基线.mjs](../src/程序化地图/渲染基线.mjs)（`stylized-680p-v1`、`680px` 高度、`16:9 / 21:9 / full` Hor+、暖调微缩滤镜、`UnrealBloomPass` 阈值 `1.35` 与移轴景深参数）；
> - **唯一数值与迷雾规则**：严禁改变 [数值基底与全局倍率规范](地图与载具/数值基底与全局倍率规范.md)（`ba-source-ssot-v1`）与 `fog-of-war-v1` 的任何视野半径、穿透档位、战斗数值或遮挡判定语义（不引入会造成半秒遮挡轮廓滞后的有损分帧）；
> - **全局 UI 规范**：遵循 [全局UI-UX规范](全局UI-UX规范.md)（Code SSOT V2.2）；Phase 1 仅在标绘层内部缓存调色盘，**零改动** [图标与标绘.mjs](../src/界面规范/图标与标绘.mjs) 公开接口；
> - **跨会话并发与红线授权**：当前 18800 看板存在 `qa_wait` 待测单据（`SCAV-8`、`SCAV-9`、`SCAV-12`、`SCAV-13`），与 Phase 1–3 部分源码路径重叠；动码前须确认先验收结单或获工程师显式授权叠加。Phase 2 修改并行红线文件 [地图编辑器.mjs](../src/程序化地图/地图编辑器.mjs)（以及 Phase 4 扩展 [平滑过渡与加载.mjs](../src/程序化地图/平滑过渡与加载.mjs)）前须获得工程师书面授权；全过程不改动 [过渡动画管线.mjs](../src/程序化地图/过渡动画管线.mjs) 既有参数。

### 1.2 细粒度剖面实证（直击四处真根因）

1. **根因 A（P0）— 战争迷雾 10Hz 同步遮挡查询放大链 + 混编样本缺失身份与阵营字段**：
   - 隔离渲染、实测 100 混编连续 12 步纯模拟耗时：`[0.3, 0.0, 0.1, 0.1, 0.1, `**`59.7`**`, 0.1, 0.2, 0.1, 0.1, 0.1, 0.0]` ms——平时仅 **`0.1 ms`**，每到 `10Hz` 节拍飙升至 **`59.7 ms`**。
   - 精确代码链：[场景运行.mjs](../src/程序化地图/场景运行.mjs)（`L201-210`、`L1318-1330`、`L1624-1627`）→ [战争迷雾引擎.mjs](../src/程序化地图/战争迷雾引擎.mjs)（`L99-106`、`L262`、`L363-408`、`L413-478`）→ [自动物理派生.mjs](../src/程序化地图/自动物理派生.mjs)（`L268-355`）。
   - 双重诱因：
     1. `setLoadMode()` 构造的 `squadUnits` 仅含 `index / team / kind` 而无 `id` 与 `role`，导致 `extractUnitVisionEmitter()` 为全部 100 个单位生成空 `unitId === ""`，且把 50 个敌方单位与 24 架空中单位全按己方地面单位发射 36 条遮挡射线；
     2. 每次射线步进回调 `physics.isPointBlocked(x1, z1, 3.0)`，内部重复执行 `support.query` + 4 次 `support.heightAt` 算坡度 + `getActiveOBBsInBounds` 数组分配与 OBB 遍历，叠加外层 `heightAt`、每单位 `.bind()` 及开阔地逐像素 `Math.atan2`——即便在正式玩法满编 50 车（`MAX_HERO_UNITS = 50`）全地面场景下，单次 10Hz 仍会触发 `21,600` 次冗余查询，消耗 ~30 ms 拖垮 60 FPS 帧预算。
   - *边界澄清*：后续 `SCAV-3`（9km 尸群）属于敌方单位，仅走 `syncContacts()` 点查表而**不发射地面 36 射线**，因此本项治理的是**己方大编队迷雾刷新主线程瓶颈**，而非尸群本身。

2. **根因 B（P1/P2）— 首次切近景 `242.5ms` 突刺与中远景 `9.79M` 三角形构成**：
   - WebGL 按渲染目标（RenderTarget）拆解 `460m` 中景：
     - **太阳阴影通道（`RT_2048x2048`）**：`64` 次实例化绘制 = **`2.01 M`**；
     - **主色彩通道（`RT_1208x680`）**：`184` DC = **`7.78 M`**，其中 `macroFarKitGroup`（[地图编辑器.mjs](../src/程序化地图/地图编辑器.mjs) `L314-379`）仅前 5 个岩石/储罐原型就占 **`3.23 M`**（全图 9km `frustumCulled = false`，且 `460m > macroHideSpan(340m)` 时与 `nearGroup` 叠画）；`macroMesh`（34,610 栋建筑盒）占 **`0.42 M`**；`nearGroup` 与植被/道面占 **`~4.13 M`**。
   - **首次切近景 `242.5ms` 突刺**：除 [地图编辑器.mjs](../src/程序化地图/地图编辑器.mjs)（`L567-609`）CPU 侧创建实例与写矩阵外，真正易形成百毫秒阻塞的还包括 `L558` 无并发上限的 `Promise.all(ensurePrototypeLoaded)` GLB/KTX2 解码，以及 `L614` 将隐藏态 `nearGroup.visible` 一次性翻为 `true` 后首帧集中触发的 KTX2 纹理上传与定制材质着色器编译。

3. **根因 C（P0 锁修复 + P1 闸门复测）— 全精度升级并发重入缺陷与升级期同步长任务**：
   - **并发重入实锤**：[预览入口.html](../src/程序化地图/预览入口.html)（`L5609-5618`、`L5721`、`L6249`）中 `upgradeToFullPrecision()` 直到 `L5714` 才置 `state.fullPrecisionReady = true`，缺少进行中 Promise 锁。外部调用 `waitForFullPrecision()` 会引发并发双倍下载/解码与两次 `scene.add(roadsGlb.scene)`（WebGL 探针在三视角均抓到两条完全相同的 `cnt=491,229 / 163.7K tris` 绘制调用）。
   - **升级期内存与阻塞来源**：`upgradeToFullPrecision` 用 5 路 `Promise.all` 让全部大包与 `roadsGlb`（经 `fetchBlobUrl` 留存 `sliceCache`）并存；`decodeSCVHHeightfield` 需遍历 2,000 万像素差分还原；`minimapEngine.bakeBaseLayer`（[战术小地图.mjs](../src/程序化地图/战术小地图.mjs) `L724-960`）同步跑全图 `1024×1024` 像素与路网分桶。

4. **根因 D（P0 顺手清零）— 热循环每帧强制布局回流、4,290 次/秒 CSS 查询与临时堆分配**：
   - [场景运行.mjs](../src/程序化地图/场景运行.mjs)（`L1362-1364`、`L1536-1612`、`L1632`、`L1662`）：每帧读 `hostElement.clientWidth/Height`、无脏值比对反复写名牌 DOM、循环内新建 `FW_STATE_LABELS` 与 `Vector3`/`Matrix4`；
   - [镜头控制.mjs](../src/交互系统/镜头控制.mjs)（`L122-125`、`L321-322`）：`updateCameraAndSun()` 与 `panByPixels()` 在检查 `state.forcedAspect` 之前无条件读取 `host.clientWidth/Height`，镜头平移/缩放/跟随时每帧触发强制回流；
   - [指令与标绘层.mjs](../src/交互系统/指令与标绘层.mjs)（`L964-977`、`L1227`、`L1261`）：紧随名牌 DOM 写入后读 `host.clientWidth/Height` 触发强制回流，并每帧调用 [图标与标绘.mjs](../src/界面规范/图标与标绘.mjs) `readSemanticPalette()` 执行 `getComputedStyle` + 26 次 `getPropertyValue`（实查 [令牌.css](../src/界面规范/令牌.css) 中 26 个语义色均为 `:root` 静态常量，`[data-ui-size]` 仅改尺码不改颜色）。

### 1.3 明确**暂不优化**项（避免过早优化）

- **`/` 作战大厅与 `/armory` 武器库**：稳跑 165 FPS、内存 6–20 MB、47 Draw Calls，无需改造；
- **`680p` 后处理管线本身（HDR Bloom + 移轴景深 + 迷雾 + 热浪）**：在 `1208×680` / `1588×680` 下填充压力极低，严禁为省 FBO 绑定牺牲画质；
- **`/play` HUD DOM 结构**：全页仅 `561` 节点，结构健康，只需清零热路径无脏值写与强制回流。

## 三、Phase 1 详细实施设计（P0 必做 · 0.5 天）

> **核心价值**：投入最小、零触碰红线文件 `地图编辑器.mjs`、`过渡动画管线.mjs` 与 `图标与标绘.mjs` 公开接口；解决己方大编队迷雾 10Hz 阻塞、清零热路径强制回流与 CSS 轮询、根治全精度升级并发重入，并为 Phase 3 产出干净的单次真实基线。

### 3.1 任务 1A：战争迷雾纯建筑 OBB 遮挡缓存 + 静止射线复用 + 混编样本规范化

**涉及文件**：
- [自动物理派生.mjs](../src/程序化地图/自动物理派生.mjs)（新增零分配纯建筑 OBB 遮挡查询 / 覆盖光栅化接口）
- [战争迷雾引擎.mjs](../src/程序化地图/战争迷雾引擎.mjs)（`L90-107`、`L237-285`、`L363-478`、`L502-590`）
- [场景运行.mjs](../src/程序化地图/场景运行.mjs)（`L201-212`、`L1306-1335`、`L1622-1628`）
- [预览入口.html](../src/程序化地图/预览入口.html)（`L5639-5644` 全精度升级后刷新缓存 + 编辑器增删/笔刷回调接线局部失效）

**核心设计（零启动卡顿 + 零遮挡语义滞后 + 公开契约与单测 100% 兼容）**：
1. **修正 `squadUnits` 身份、兵种与阵营传参（消除空键碰撞与无效射线）**：
