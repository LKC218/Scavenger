# 版本退役与缓存清理规则

## 已确认的执行原则

新版验收应同时处理旧版退役。当前确认通过版作为统一入口；被替代的上一版进入七天回收期，更早的中间版及失败尝试按清单退役。验收绑定具体文件摘要及版本，按模块要求完成技术、画面、听感或工程师确认，不能把生成成功视作最终验收。

工程师已进一步批准后续自动执行：新任务通过`stage`冻结具体旧文件、新版文件、验收凭证及依赖核查说明，工程师确认该具体版本通过后才登记`accept`。无依赖后自动回收，逐文件满七天再复核清除；同一已确认清单不重复索取删除批准。本次全局启用不能代替任何具体新版验收。

启用时冻结项目已有文件路径作为存量边界，保留全部未知和活动任务登记。旧登记、旧候选及旧回收回执不自动接管；未审核存量必须单独审核，不能因年龄、目录名、版本号较旧或全局授权而自动获得清理资格。

本规则替代一般性的“永久保留所有历史输出”要求。旧报告、冻结清单和已完成删除回执保留原意；原件、来源、必要验收证据、当前可编辑工程及仍有用途的回退档继续按职责保留。256、512、不同细节层和完整材质回退版属于并存功能版本，不能按编号新旧清除。

## 正在进行的任务

所有项目内会话在开始、续做、上下文恢复和新轮次时重读项目根指令及本规则。新轮次使用独立任务名，开始及交付时运行`status`／`status --task`核对登记。交付须列出具体验收状态、旧版清单或无需退役原因、缓存登记或无需登记原因、仍有依赖及任务结束状态；工程师确认后由负责会话执行`accept`并报告结果。查询只汇总已登记内容，不代替产物核对。已运行会话不被假定中途自动刷新指令；现有活动任务继续按原范围保护。

1. 启动任务、服务或续跑前，用清理工具的`protect`登记任务读取、写入的全部路径；只读依赖也要登记。登记成功后才使用资源。
2. 开发聊天结束一轮回复不代表任务结束。只有明确完成或停止使用该范围，才用`close`登记完成依据。保护记录不按时间或PID自动失效。
3. 未登记目录不能进入自动清理；现有断箭、原型、丧尸、资源优化和临时目录以“状态不明”预先保护。整组保护不关闭。仅对启用后新任务显式冻结的新增缓存，或新任务经工程师具体验收批准的旧文件，在精确指纹范围内细化启用时原样的未知目录保护；其他活动保护、新增或变化的未知保护继续阻止清理。
4. 任务准备重用已结束范围时，先重新`protect`；清理和任务登记使用同一执行锁。中断锁须核对PID及命令行后人工处理，定时任务不得自动删除锁。
5. 工具不声称能推断任意第三方进程的文件读取情况。未接入登记的旧任务继续由预置保护兜底；发现未知占用时维持保护。

## 清理准入与回收

- 缓存只允许`tmp/`、`temp/`的明确子项以及`src/`、`scripts/`内的Python缓存；由启用后新任务登记为可再生成并说明生成方法，冻结准确文件集合，所属任务已结束且无依赖后，取文件修改、登记及任务结束三者最晚时间计算七天闲置。拒绝把启用存量边界内的路径自动登记为缓存。
- 历史版本必须有工程师确认的具体新版、替代件摘要、验收证据摘要和依赖审查记录；新版验收绑定该份冻结旧版清单，确认后自动退役。原件、正式资料库、工具及冷归档使用专项工具审核，通用工具拒绝处理。源码、文档及JSON元数据不作为通用历史载荷。
- 仅当正式版已经迁走全部交付与必要证据时，完整的丧尸群体候选目录`local-data/丧尸模型/发布/ZOM-SHARE-YYMMDD-NNN/`可在`stage`中显式启用`--release-bundle`，逐文件退役该目录内重复的源码、文档和JSON。其他目录不得使用该开关；文件身份、依赖审查、清单摘要批准、占用检查和七天回收仍全部执行。
- 当前通过版和必要凭证由登记保护；连续新版通过后，沿已确认的后继关系核对当前版，避免为验证旧版退役而永久保留全部中间载荷。被明确恢复的自动条目暂停退役，重新核查登记前不再次回收。
- 预览冻结逐文件路径、大小、修改时间、SHA256和任务登记摘要。批准针对清单摘要；任何候选或任务登记变化须重新预览。
- 清理先回收，至少七天后才永久清除。回收操作按文件保存原路径及回执，可显式恢复，原位置存在文件时拒绝覆盖。回收区不是长期备份；新任务应先处理到期回收及同模块上一代，避免积累多代。因占用或未审批暂缓时记录原因，不能覆盖上一代回收。
- 每次执行核对路径边界、链接和目录联接、任务状态及文件摘要；拒绝整目录递归删除，保留小型回执。历史替代件和证据在回收及最终清除时再次核对。
- 自动回收前和永久清除前查询Windows文件占用；原路径重建、回收文件被使用、替代件或凭证变化均停止该范围。其他系统或查询失败保持保护，不结束外部进程。
- 部分执行失败立即停止，保留回执供人工核对；不自动扩大范围或重试中断回执。

## 首次存量审核

首次只输出目录摘要和逐文件存量清单，全部保护待审；目录体积不等于可释放空间。先检查恢复验证临时副本，再检查结束任务的缓存，最后审查历史载荷。模型提取批次并非九个互相替代的整库版本，须按文件用途及引用审查。

工程师审核首轮范围后，明确完成所属任务、迁移引用并登记候选，生成带摘要的执行预览；批准具体执行预览后才回收。旧的956份删除回执及历史清单不能用于重复删除或扩大授权。

## 定时执行

每天04:00按客户端时区`America/Los_Angeles`运行清理工具`tick`。电脑休眠或应用未运行时不保证准点执行；下次运行仍按时间戳计算七天期限。

当前工程师已授权启用后续自动维护。`enable-auto`建立独立策略身份和存量边界，`first_review`保持原值；这不表示旧存量已经全部审核通过。`tick`只执行当前策略标记的冻结条目及其回收回执：已确认旧版自动回收，合格缓存按闲置七天准入，两者在回收七天后复核清除。定时任务不推断验收通过、不运行`accept`、不关闭任务、不登记新范围，也不引用旧清单扩大授权。

初始容量警戒线为已登记缓存5GiB、该策略回收区10GiB。超限时仅提示及处理本来就满足准入条件的文件，不能缩短七天或扩大范围。代码、脚本和文档的提交历史建议由版本控制管理，不通过清理工具抹除；已标记的交付里程碑独立留档，原件和必要凭证持续保护。

相同状态只保留最近一份定时预览，避免审计工具自身持续生成重复快照。有实际回收、清除、失败或新增需要人工处理的事项时通知，候选与保护状态无变化时保持安静。
