# 开发者阅读说明书

本说明书帮助开发者完成三件事：把项目运行起来、找到需要修改的代码、用可复查的方式验证修改。阅读时以运行包根目录为工作目录。

首次在 WorkBuddy 中打开项目时，先查看包根`使用指南.html`：它说明如何解压、新建任务，并通过带红箭头的 WorkBuddy 操作截图指示“打开本地文件夹”的位置。

## 1. 项目用途

这是一个独立的 Three.js 群体模拟与性能实验，不是正式游戏。它负责：

- 生成 100 至 5000 个平面移动角色。
- 让十三款蒙皮角色按固定种子均匀混合。
- 提供静态、原地动画、开阔移动和障碍通道四种负载。
- 记录帧时间、逐款可见数、逐款动画数和移动状态。
- 导出 JSON／CSV，并按源码与资源摘要归档样本。

项目没有载具战斗、攻击伤害、死亡、完整人群物理或正式胜负规则。

## 2. 五分钟启动

环境要求：

- Python 3.11 或更高版本。
- 支持 WebGL 2 的 Chrome 或 Edge。
- 运行数值规则检查与包内核验中的规则检查时，需要 Node.js 18 或更高版本。

在 Windows 双击：

```text
启动丧尸群体测试.cmd
```

在 macOS／Linux 运行：

```sh
sh start.sh
```

终端出现以下地址后保持窗口开启：

```text
http://127.0.0.1:8769/
```

页面默认加载十三款角色，共 500 只。按 `Ctrl+C` 或关闭终端可停止服务。

如果 8769 已被占用：

```text
python -X utf8 -B scripts/发布服务.py --port 8770
```

## 3. 目录与入口

```text
data/发布资源清单.json       角色文件路径、摘要、骨骼与动作身份
src/丧尸群体测试/            页面和模拟源码
src/资源加载/                GLB、KTX2与Meshopt共享加载器
scripts/发布服务.py          本机服务、资源路由和采样归档
scripts/刷新发布身份.py      修改后刷新源码与资源摘要
scripts/核验发布包.py        文件、服务和浏览器冒烟入口
tests/验证群体规则.mjs       不依赖浏览器的长程数值检查
runtime/assets/              十三款256／512模型
runtime/vendor/              Three.js固定运行文件
运行数据/样本/               页面采样后生成的JSON与CSV
```

先启动服务，再在浏览器访问页面。直接双击 `index.html` 无法可靠加载 ES Module 和模型。

## 4. 一次运行发生了什么

```text
读取发布资源清单
  → 校验十三款角色和文件摘要
  → 页面加载256档GLB
  → 克隆500个独立骨架
  → 固定30Hz推进群体规则
  → 每个显示帧混合待机与移动动作
  → 场景同步矩阵和视锥计数
  → 渲染并记录帧时间
  → 采样完成后提交JSON并由服务保存JSON／CSV
```

页面主循环位于 `src/丧尸群体测试/入口.mjs`：

1. `main()` 读取 `/manifest.json`。
2. `Crowd` 生成群体并计算导航。
3. `Actors` 加载角色、克隆骨架并控制动作混合。
4. `View` 更新镜头、投影和场景。
5. `Metrics` 记录每帧数据。
6. `requestAnimationFrame()` 持续驱动显示循环。

群体固定步长为：

```js
const step = 1 / 30;
```

一个显示帧最多补七个模拟步长，剩余时间写入 `dropped`。不要用累计 `setTimeout()` 假设模拟时间。

## 5. 五个核心模块

### 5.1 入口

文件：`src/丧尸群体测试/入口.mjs`

职责：

- 加载资源清单。
- 创建群体、角色、场景和统计对象。
- 连接页面按钮与键盘输入。
- 协调固定步长、动画、渲染和采样。
- 暴露只读 `window.horde` 调试接口。

常见修改：

- 默认数量：同时检查 `Crowd()` 默认值和页面数量下拉框的 `selected` 项。
- 默认模式：检查 `Crowd.reset()` 和页面模式下拉框。
- 采样时长：检查 `quick-sample`、`sample`、`long-sample` 三个按钮绑定。
- 页面状态文字：搜索对应 DOM 元素 ID。

### 5.2 群体

文件：`src/丧尸群体测试/群体.mjs`

职责：

- 场地边界 `WORLD`。
- 障碍定义 `OBSTACLES`。
- 固定距离场和目标落点。
- 空间网格邻居查询。
- 局部分离、速度平滑和障碍约束。

常见修改：

- 移动速度：找到角色初始化中的 `speed`。
- 分离距离：搜索分离距离 `0.85`。
- 分离力度：搜索 `sx*1.8`、`sz*1.8`。
- 往返周期：搜索每 24 秒切换目标的逻辑。
- 场地与障碍：修改 `WORLD`、`OBSTACLES`，然后重新检查生成点和目标边界。

群体规则修改后先运行：

```text
node tests/验证群体规则.mjs
```

该检查验证长程到达、反向返回、坐标有限、不穿越障碍、固定种子和统计口径。它不提供浏览器帧率结果。

### 5.3 角色

文件：`src/丧尸群体测试/角色.mjs`

职责：

- 用共享 GLB 加载十三款角色。
- 检查骨骼、材质、三角形和两个动作片段。
- 为每只角色克隆独立骨架。
- 在待机和移动动作间平滑混合。
- 统计每款实际数量、可见数和动画数。

角色几何、材质、贴图和动画片段在同类实例间共享；骨架、Mixer 和动作相位独立。500 只仍会产生 500 套骨架和逐只蒙皮绘制。

### 5.4 场景

文件：`src/丧尸群体测试/场景.mjs`

职责：

- 正交相机、镜头平移、缩放、旋转和聚焦。
- 光照、地面、障碍与实例投影。
- 群体中心的屏幕拾取。
- 视锥内角色计数。

性能采样期间镜头会锁定。要修改镜头手感，先调整 `updateCamera()` 中的时间常数，再用实际鼠标检查，不要只依赖静态截图。

### 5.5 统计

文件：`src/丧尸群体测试/统计.mjs`

职责：

- FPS 按总帧数除以实际帧间隔总和计算。
- P95、P99、最大帧和长帧比例使用真实帧样本。
- GPU 计时通过异步 WebGL2 查询获得。
- 采样完成后生成 JSON 和 CSV。

新增统计字段时，需要同步检查：

1. 逐帧数据是否在 `入口.mjs` 产生。
2. 摘要是否在 `统计.mjs` 计算。
3. `scripts/发布服务.py` 的 CSV 字段是否保存。
4. 报告和资料文件是否采用同一字段含义。

只增加页面显示而漏掉服务归档，会让自动样本与导出文件不一致。

## 6. 角色资源清单

文件：`data/发布资源清单.json`

每款角色至少包含：

- 稳定 ID 与源网格编号。
- 骨骼数、材质数和三角形数。
- 待机、移动片段名与时长。
- 坐标系、朝向和站立高度。
- 256／512 文件路径、字节和 SHA-256。

每条记录必须与真实 GLB 一致。修改资源后运行：

```text
python -X utf8 -B scripts/刷新发布身份.py
```

脚本会重新计算资源摘要、源码摘要和 `SHA256SUMS.txt`，并将包标记为局部修改。完成后重新启动服务。

扩展为第十四款时，不只修改清单。角色配置校验、服务采样分母和报告逻辑当前都按十三款设计，需要同步修改并重新建立性能证据。

## 7. 单款与混合模式

页面“角色组合”有两个值：

- `mixed`：十三款按固定随机种子均匀分配。
- `single`：全部使用编号 0，作为同源码对照。

分配入口位于 `src/丧尸群体测试/角色配置.mjs`：

```text
assignModels()
modelDistribution()
summarizeModelRows()
```

角色随机流不消耗群体导航种子，因此相同群体种子下，单款和混合模式的位置负载应保持一致。修改分配算法后要检查这个约束。

## 8. 采样与文件

页面点击“采样60秒”或“长测180秒”后：

1. 重置群体。
2. 锁定镜头和控件。
3. 预热 10 秒。
4. 记录固定时长。
5. 下载 JSON／CSV。
6. 向 `/api/samples` 提交同一结果。
7. 服务保存到 `运行数据/样本/`。

FPS、P95 和长帧比例必须一起看。稳定 60 帧的技术判据还要求：

- 180 秒平均 FPS 不低于 60。
- P95 不高于 16.7 毫秒。
- 超过 33.3 毫秒的帧少于 0.1%。
- 所有角色持续位于视锥内。
- 动画更新数为配置数量。
- 模拟欠时为 0。
- Windows 原生前台观察覆盖完整。

页面隐藏、失焦或未完成前台观察时，样本可以保留，但不能标为稳定 60 帧验收。

## 9. 修改后的最小流程

修改任何源码或角色资源后按顺序执行：

1. 停止旧服务。
2. 修改源码或替换 GLB。
3. 如果资源变化，更新资源身份信息。
4. 运行 `python -X utf8 -B scripts/刷新发布身份.py`。
5. 运行 `node tests/验证群体规则.mjs`。
6. 启动服务并检查页面加载。
7. 运行包内核验。
8. 重新采样，不沿用旧结果。

完整核验：

```text
python -X utf8 -B scripts/核验发布包.py --rules
python -X utf8 -B scripts/核验发布包.py --rules --resolution 512
```

无窗口浏览器冒烟：

```text
python -X utf8 -B scripts/核验发布包.py --rules --browser-channel chrome
python -X utf8 -B scripts/核验发布包.py --rules --browser-channel chrome --resolution 512
```

`--resolution` 可选择 `256` 或 `512`。将 `chrome` 改为 `msedge` 可检查 Edge。无窗口冒烟不能代替独立可见窗口的原生前台性能矩阵。

## 10. 常见问题

### 页面没有打开

检查终端是否仍有服务。直接访问：

```text
http://127.0.0.1:8769/api/status
```

正常结果包含：

```json
{"app":"scavenger-horde"}
```

### 端口已被占用

换一个端口，例如：

```text
python -X utf8 -B scripts/发布服务.py --port 8770
```

不要结束未知来源的进程。

### 模型加载失败

依次检查：

- 浏览器开发者工具的 Network 面板。
- `data/发布资源清单.json` 中的相对路径。
- `runtime/assets/` 是否存在对应 GLB。
- 文件摘要是否与清单一致。

### 自动归档提示源码变化

停止服务，重新启动。若源码确实已修改，先运行 `刷新发布身份.py`。不要在运行中修改源码后继续采样。

### 动画不动

检查：

- 当前模式是否为“静态角色”。
- 页面是否处于暂停状态。
- GLB 是否同时包含 `待机` 和 `移动`。
- 浏览器控制台是否报告 Mixer 或骨架错误。

### 群体进入障碍

先运行数值规则检查，再检查 `WORLD`、`OBSTACLES`、生成区域和角色半径是否同步调整。

## 11. 性能结论边界

当前报告中的具体 FPS 只适用于报告列出的机器、浏览器、版本、内部渲染尺寸、角色数量和镜头。修改角色、源码、贴图、场景或采样条件后，需要新样本。

5000 是界面保护上限。100、300、500 是矩阵验收档位，其他数量用于容量探索。

内置浏览器、外部 Chrome 和 Edge 是不同采样环境。不能把内置浏览器结果写成独立 Chrome／Edge 原生前台验收。
