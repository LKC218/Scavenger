# 多人协作方案

可视化阅读入口：[多人协作方案 HTML](../reports/多人协作/多人协作方案.html)。直接用浏览器打开，支持按资源去向筛选、按角色阅读接入流程和打印；本文为内容依据，变更时同步 HTML。页面仅辅助理解，不执行实际交付操作。

## 状态与范围

工程师已确认协作方案方向；当前仅整理方案文档和阅读入口。初始化 Git、上传 GitHub、资源打包、依赖安装、脚本实现及跨机验证均未在本任务执行。

本方案依据当前[项目约定](项目结构与开发约定.md)、[靶场模块](../src/载具靶场/README.md)、[资源准备脚本](../scripts/检查载具原型资源.py)、[靶场服务](../scripts/预览载具靶场.py)及[资料库核心](../scripts/断箭/资料库核心.py)整理。已有能力指代码中存在的功能，不表示已通过另一台电脑的验收。

首轮目标是让合作者通过代码仓库、最小运行资源包和本机路径导入独立运行靶场；资料库完整交付及提取研究复现作为后续范围，实施前另行确认。

## 一、交付组成

| 部分 | 内容 | 管理方式 |
| --- | --- | --- |
| GitHub 代码仓库 | 自有源码、维护脚本、开发文档、配置模板及资产版本清单 | 建议先建私有仓库，通过功能分支和 PR 合作；尚未建库 |
| 独立资源包 | 允许共享的模型、声音、必要运行文件 | 团队共享存储，按不可覆盖的版本发布；尚未打包 |
| 本机配置 | 绝对路径、私有路由、日志、缓存 | 接收端生成，保存在被忽略的本地目录 |

普通玩法和 UI 开发者默认无需游戏安装目录、Blender 或整套提取工具。私有仓库、网盘或加密压缩包不替代资源再分发许可。

## 二、GitHub 文件边界

### 建议纳入

| --- | --- |
| `src/` | 靶场、资料库、音效索引源码和就近 README |

| `AGENTS.md` | 团队共同规则；个人专属路径或要求需先审核 |
| `.gitignore` | 本地数据、依赖、缓存和凭据排除规则 |
| 根目录两个 `.cmd` 启动器 | 靶场和资料库的便捷入口 |
| `research/` | 经审核的来源台账、观察记录和核验结论 |
| `reports/` | 经审核的报告及必要展示资源；控制图片和媒体体积 |

目录允许提交不代表所有文件已获得上传许可。首次入库逐项检查第三方图片、视频帧、模型预览、私人信息、绝对路径及大文件。不对整个项目目录直接执行无审核上传。

### 继续排除

- `local-data/`：工具、运行时、路径配置、输入快照、提取批次、媒体、Blender 工程、验证回执和私有路由。
- `tmp/`、`temp/`：可再生成的临时文件。
- 依赖安装目录、虚拟环境、缓存、日志及个人编辑器配置。
- 密钥、Cookie、账号凭据及带真实值的环境配置；示例配置仅保留无敏感值字段。

沿用现有[忽略规则](../.gitignore)，不按 `.glb`、`.png`、`.wav` 等扩展名全局排除。未来如明确采用可分发的正式运行资产，应按确认后的目标目录和存储策略纳入。Git 忽略规则不会移除已经跟踪的文件，建库后须结合暂存区和历史再次核验。

## 三、独立资源包

### 分包范围

| 包 | 必要内容 | 接收对象 |
| --- | --- | --- |
| 靶场运行资源包 | 两款可分发模型、8项动作声音所需的实际媒体、运行清单和许可说明 | 普通玩法及 UI 开发者 |
| 固定运行依赖包 | 固定 Three.js 文件、许可证、来源、校验元数据和版本指针；也可按官方来源安装同一内容 | 靶场或资料库使用者 |
| 模型编辑资源包 | 允许共享的源模型、Blender 工程、贴图、修改说明及软件版本 | 模型制作人员 |
| 资料库资源包 | 选定版本索引、该版本实际引用的媒体和必要来源记录；接收端重建路由 | 资料库维护及使用者 |
| 研究复现资料包 | 经确认可交付的必要输入记录、工具版本和核验证据 | 确需复现研究的人员 |

8项声音动作不强制对应8个不同文件；按内容摘要去重，并保留所有动作绑定。包从清单选择文件，不直接压缩整个 `local-data/`。普通运行包不附带历史批次、失败输出、缓存或全部原始输入。

### 资源准入

- 《断箭》提取的模型、贴图、音频及派生工程：未确认团队再分发授权前不进入共享包。首轮优先采用自制或许可明确的替代素材；替代模型还需满足靶场的部件和运行数据约定，不能只替换文件名便认为兼容。
- 游戏安装文件、资源包和游戏随附 DLL 不进入通用资源包；研究人员从合法来源准备所需输入，具体操作仍须符合适用许可。
- 丧尸素材当前[资源清单](../research/丧尸模型/资源清单.json)记录为 CC BY 4.0；首次对外交付前核对原始来源许可，并附作者、来源、许可及修改说明。当前记录不等于已经完成共享包授权审核。
- 第三方工具优先提供官方来源、固定版本与摘要，不搬运现有虚拟环境。确需再分发的工具逐项核对许可。
- 密钥和账号凭据不放入任何普通资源包，按人员单独授予必要访问权限。

### 资源包清单

每个包附带包编号、不可覆盖的版本、兼容代码提交或标签、稳定资产 ID、包内相对路径、安装目标、字节数、SHA-256、来源、许可和修改说明。实际字段格式待实现时确定，不将本节视为现有工具接口。

媒体引用使用相对路径，本机绝对路径由导入流程生成。包发布后不覆盖旧版本；代码变更通过清单声明兼容资源版本。涉及内容替换或重建时保留新旧对应关系。

## 五、接收端路径配置

### 靶场

合作者可自行选择项目目录。首版将媒体安装在项目内被忽略的本地目录，保持现有服务边界：

```text
项目根目录/
├─ src/
├─ scripts/
└─ local-data/
   ├─ tools/three/
   │  ├─ 当前版本.json
   │  └─ 0.187.0/                 固定运行文件、许可证及来源与校验.json
   └─ 原型/载具靶场/
      ├─ 资源清单.json
      ├─ 私有路由.json             接收端生成
      └─ 媒体文件                  具体布局由包清单指定
```

| 文件 | 接收端处理 |
| --- | --- |
| `资源清单.json` | 安装与代码兼容的运行信息和媒体 URL |
| `私有路由.json` | 以当前项目根目录解析包内相对位置，生成媒体绝对路径、字节数及摘要 |
| `输入核验.json` | 来源证据与运行校验分开处理；普通运行人员无需取得所有原始输入，不改写历史来源指纹 |
| Three.js `当前版本.json` | 与安装版本及元数据 SHA-256 一致 |
| Three.js `来源与校验.json` | 与实际安装文件摘要一致 |

拟实现的导入工具应检查包版本、代码兼容性、文件摘要和路径边界，拒绝绝对路径输入、路径穿越及逃逸目标目录的链接；遇到不同内容的已有文件时停止并提示。导入成功后生成本机路由，重新计算摘要并进行运行资源检查。工具名称和命令尚未实现，本方案不提供虚构命令。

### 资料库与研究配置

资料库保存绝对路径和版本记录。导出时记录包内相对映射，导入时生成接收端路由及对应版本记录；保留来源端历史快照，不全局替换路径后继续沿用旧指纹。只导入需要的当前资源范围，不要求普通开发者复刻全部历史批次。

游戏、Blender、提取工具位置由确需研究的人员各自配置，本机游戏路径配置不作为靶场运行前提。正式研究文档继续使用目录别名或相对路径。

## 六、合作者配置与运行

### 拟交付后的首次接入流程

以下流程依赖尚未实现的资源导入及检查工具，当前不能仅克隆源码完成全流程：

1. 克隆仓库并切换到交付指定的代码提交或标签。
2. 安装 Python；团队建议统一 Python 3.12，浏览器使用 Chrome 或 Edge。
3. 获取许可已核对且与代码兼容的运行资源包。
4. 安装固定 Three.js 0.187.0、许可证及配套校验元数据。
5. 通过待实现的导入工具安装媒体并生成本机路由。
6. 执行待实现的独立运行资源检查，确认全部通过。
7. 使用下方已有命令启动，检查模型、声音、移动和攻击。

### 已有启动命令及前提

以下命令均从项目根目录执行。前提是资源、Three.js 元数据和本机路由已准备完整；命令本身不下载或导入资源。

靶场前台启动，便于查看错误：

```powershell
python -X utf8 -B scripts/预览载具靶场.py --serve
```

浏览器访问 `http://127.0.0.1:8768/`，前台服务用 Ctrl+C 结束。也可双击根目录 `打开载具靶场.cmd`，它会按现有逻辑后台启动并打开浏览器。

已准备资料库资源及接收端路由时：

```powershell
python -X utf8 -B scripts/断箭/启动正式资料库.py --open
```

访问 `http://127.0.0.1:8767/`。资料库和靶场独立运行。不得用通用静态服务器暴露整个项目根目录。

### 按职责安装依赖

| 工作 | 依赖与前提 |
| --- | --- |
| 运行准备好的靶场 | Python 标准库、浏览器、固定 Three.js、运行资源和本机路由 |
| 模型重新派生 | 上述环境、NumPy、Pillow、现有资料库中的指定源资产 |
| 模型编辑 | 已确认可用的 Blender 版本及对应源工程 |
| 规则自动检查 | Node.js，具体步骤见靶场模块说明 |
| 浏览器自动验证 | Playwright、对应浏览器及准备好的运行资源 |
| 提取研究复现 | 单独确认工具和输入范围，参照脚本维护说明准备隔离环境 |

当前靶场没有 npm 安装步骤。后续依赖获取方式和版本清单实现后补充实际命令。

### 初步排错

| 现象 | 优先检查 |
| --- | --- |
| 提示缺少资源清单 | 是否完成对应运行资源包导入，不直接要求新人运行 `--prepare` |
| 找不到媒体、摘要错误或媒体越界 | 是否使用了原机绝对路径、包是否完整、目标是否在本项目 `local-data/` 内 |
| Three.js 元数据或文件变化 | 版本指针、元数据摘要、实际文件是否来自同一固定版本 |
| 端口无法启动 | 查看前台错误或本地日志，核对端口所属程序，不批量结束其他服务 |
| 有画面但无声 | 先检查浏览器用户交互和播放状态，再检查媒体；程序解码不等于人工听审 |

## 七、协作约定

- 建库后采用功能分支和 PR，保持 `main` 可运行；PR 写明修改模块、兼容资源版本和验证范围。
- 新增或修改源码同步 `docs/apps-code-map.md` 与就近模块说明，导航只记录入口、职责和文档落点。
- 媒体更新发布新资源版本，并更新代码侧兼容清单；共享存储账号及访问凭据不写入清单。
- 同一个 Blender 工程指定主要编辑者，并行修改用新版本文件交接，避免同时覆盖同一二进制工程。
- 普通开发流程不包含批量提取、历史迁移、删除或清理；这些操作需要单独确认范围。
- 自动检查使用可分发测试素材，不依赖个人游戏目录。结构检查、浏览器操作、实际听审、长时间性能和发布验收分别记录。
