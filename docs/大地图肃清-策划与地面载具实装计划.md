## 三、候选细则与范围边界

- 核心循环候选：观察地图→侦察确认敌情→布置火力与运输补给→诱导并肃清→地面部队占领→花费首次奖励补充兵力或物资→推进下一区。
- 地面阶段先验证地面战斗与后勤，再设计地面侦察和区域任务；诱饵空运、无人机及其他空中单位排在地面阶段之后，不为测试提前制作伪空运。
- 当前只明确尸群敌人；敌方载具、敌方空中单位、步兵装卸、工兵破障、建筑破坏、两栖渡水、牵引部署均为待定系统。
- 已确认防空保留对空用途，先接共通状态和部署，对空战斗等空中目标；纯防空导弹不改为对地，机炮只有核实合法对地配置和瞄准限制后才可接入。
- 已确认运输与工程型号先接共通能力及已核实武器，专用系统逐车交方案；不擅自把所有运输车改成补给车，也不把工程装置改成攻击技能。
- 无当前合法任务的装备按已确认范围先完成共通状态和部署，标“基础接入完成／专用玩法待定”；不能标完整专用玩法实装，首关可召集名单和具体部署方式仍逐车评审。
- 点数与后方物资分开核算；补给购买仍走实体装载运输，单位购入时的初始弹药是否额外占库存、是否有召集上限待定，避免低价买新单位替代补给。
- 首区预算候选：按保守命中率和容错核算开局弹药；首次奖励至少覆盖下一步必需支出，不能仅在完美命中且零损失时可继续。
- 补给动作候选：双方停稳且处于范围内才交付；移动、越距、取消或任一方被摧毁即中断，已交付保留，未交付不扣除，禁止多车重复结算。
- 失败候选：仍有必清／必占目标时，完成任务所需能力已失去，且补给、在途增援与可购买替代都无法恢复，判失败；暂时弹尽或正在返补不立即失败。
- 不依赖等待、击杀和重新占领刷点；是否允许购买次数无限但受有限点数约束，须与首关平衡一并确定。
- 所有具体数值先标候选、记录来源及测试范围；未确认前不把候选写成正式值。

## 四、每车设计卡与完成状态

每个稳定ID独立设计卡；同底盘可复用已核验共通逻辑，但变体仍须明确差异。设计卡不预建77个空文件，先在本计划或实际批次记录中维护。

| 字段 | 最少记录内容 |
| --- | --- |
| 身份与范围 | 稳定ID、资源修订及摘要、整车／部件／变体判断、轮履与可玩形态核验 |
| 战术职责 | 对尸群的用途、优势与限制、为何需要该型号；无合法用途时写待定 |
| 武器与合法目标 | 源装配／节点／弹药证据、可攻击目标、射界／俯仰、直射／间瞄、无适用目标时行为 |
| 移动与表现 | 速度候选、碰撞占地、转弯、炮塔／炮管／轮履节点、坡面与地图支撑；不新增两栖或牵引 |
| 生存与损失 | 耐久候选、尸群伤害接收、摧毁一次性结算、选择／命令／占区参与的退出 |
| 弹药与补给 | 各武器容量／消耗、装填、空弹行为、维修与补弹兑换、装载运输及中断规则 |
| 经济与召集 | 价格候选、初始配发、召集位置与可达性、有限点数和库存关系 |
| 交互与声音 | 单位卡、命令、状态反馈、机械／发射／命中声音确证关系、缺项与回退 |
| 性能与验收 | 真实数量与视野、渲染／模拟预算、规则与浏览器凭证、工程师确认对象和摘要 |

逐车状态链统一为：**设计评审→资源／节点／武器核验→实装→规则／浏览器验收→人工验收**。
每一步记录“待办／进行中／通过／阻塞”及证据；静态`passed`不能跳过第二步，技术通过不能跳过人工验收。
模型能显示、能移动只算基础接入；需获准玩法实际可用并完成状态链，才能称该车完整实装。
以下77条已完成目录登记，75条通过资源开放基础部署候选，2条partial禁止部署；共通状态、M1A2主炮和M548A3补给已有G1检验代码。其余逐车武器／差异和专用设计仍待核验评审；表内“未实装”指未完成该条专用玩法，不把开放部署当作整车完整玩法或逐车浏览器验收完成。

## 七、最少验收案例与脚本计划

- 每车共通：身份与装配相符，点选／框选／队列可用，地形支撑与碰撞正确；固定组件不假造行驶，非法命令有明确反馈。
- 每种获准武器：实际炮口发射、合法目标筛选、射程／射界／装填、最后一发扣至零且停止；取消命令不能复制弹药或重置冷却。
- 耐久／摧毁：损伤来源明确、仅摧毁一次、退出命令与区域占领；已离膛弹丸继续正常结算，不能修复复活。
- 后勤：有限库存→车载→已交付数量守恒；移动／越距／取消／摧毁中断不吞货；多车不重复交付，空载拒绝供给，维修不超上限。
- 任务与经济：三指定区全部可达、区域外尸群归属清晰、首次奖励仅一次；买补给必须运输，增援落点不可用时不静默扣费，失败与重开清理状态。
- 侦察：未知地形、已探索地形、当前可见敌情分别验证；屏幕标签、选择、自动开火、小地图不得泄露不可见敌情。
- 回归与性能：Chrome／Edge串行真实键鼠测试、跨区往返、补给中断、重开、声音与资源释放；记录真实单位／尸群／可见数量，不继承单独模型或群体成绩。
- 已落地[服务.py](../scripts/地面载具/服务.py)负责精确清单、资源白名单与冻结身份，[验证规则.mjs](../scripts/地面载具/验证规则.mjs)负责弹药／耐久／补给库存及能力边界，运行说明见[地面工具](../scripts/地面载具/README.md)；原先拆分清单与补给脚本的建议已合并到实际入口。
- 已落地[验证页面.py](../scripts/地面载具/验证页面.py)，由主任务执行并归档浏览器结果；须读取真实服务身份并验证实际输入，不能用直接改状态冒充交互。`--all-models`逐项加载／部署不等于逐车完整玩法通过；完整地图、尸群、任务和性能专项仍待对应阶段新增，不预建空目录。
