# 项目轻量化与定时清理规范

本规范与[版本退役与缓存清理规则](版本退役与缓存清理规则.md)配套执行：**前者维护项目空间边界、日常防堆积纪律与系统级定时自动维护流程；后者维持七天回收缓冲、任务占用保护、具体新版验收与历史存量不可盲删底线**。两者共同保证项目在不影响日常开发的前提下长期轻量化运行。

## 一、四层空间边界

| 层级 | 位置 | 目标定位 | 变更与清理原则 |
| --- | --- | --- | --- |
| **代码轻仓** | `src/`、`scripts/`、`docs/`、`research/`、`reports/` | Git 跟踪源（目标 `< 50 MB`） | 由 [.gitignore](../.gitignore) 屏蔽运行产物；本地 `.git/hooks/pre-commit` 拦截 `> 5 MB` 文件、缓存目录、禁用二进制后缀及敏感路径 |
| **热运行库** | `local-data/资源库/当前资源/`（含模型、音效、场景）、`local-data/tools/three/` | 当前在用运行资产与最新主工程 | 只保留现用稳定版本与当前可编辑主工程；被新版替代且迁移完所有消费者后，按 `stage` + `accept` 退役旧版 |
| **可代谢缓存** | `tmp/`、`temp/`、Python `__pycache__/` | 解压临时副本、截图、逐帧日志、导出中间文件 | 必须写入 `tmp/<独立任务名>/`；任务结束后通过 `enroll --kind cache` 冻结登记，由定时 `tick` 满 7 天自动回收并清除 |
| **冷归档与原件** | `local-data/资源归档/`、原始 7z 与来源凭证 | 只读备份、母包与验收回执 | 不入 Git、不入热缓存清理；仅存留一份权威母本或移至项目外独立冷备目录并保留 SHA-256 记录 |

## 二、日常开发防堆积 5 条硬规则

1. **可再生缓存严禁写入 `local-data/`**：任何脚本生成的临时解压副本（如从 `.7z` 解出的原件目录）、贴图转码缓存、调试截图与回归对比帧，一律写入 `tmp/<独立任务名>/` 或 `tmp/运行/`，不得长期滞留于 `local-data/` 绕过缓存治理。
2. **超大调试日志默认降噪或压缩**：浏览器自动化、性能采样或逐帧记录脚本，默认只输出轻量汇总 JSON 与失败帧切片；确需保留完整逐帧数据时，使用 Python 标准库 `gzip` 写为 `.json.gz` 并输出到 `tmp/运行/`，避免单文件上百 MB 的未压缩 `.json` 长期驻留 `local-data/`。
3. **同模块迭代只留最新 1 代与当前母版**：地图提取、模型批处理等管线推进到 `rN` 时，旧中间层 `r01..r(N-1)` 与重复依赖收集副本必须在验收后登记退役，不再长期并行保留多套完整复制。
4. **同盘中间拷贝优先使用只读引用或清单索引**：下游加载或编译阶段直接读取上游稳定目录或清单指针；不把数 GB 的上游素材整目录复制到临时工作目录。
5. **任务收尾同步 `enroll` 与 `close`**：除明确标明的长驻服务或等待工程师人工验收的交付任务外，开发/测试轮次结束交付时须当场对 `tmp/` 产物执行 `enroll --kind cache` 并执行 `close`，避免形成僵尸 `active` 任务阻断每日自动回收。

## 三、双轨清理 SOP

### 轨道 A：日常无人值守自动维护（安全白名单内自动执行）

1. **每日定时触发**：由 [定时清理维护.py](../scripts/维护清理/定时清理维护.py) 驱动 Windows 计划任务每日 `04:00` 自动运行（不依赖编辑器或 AI 会话开启）。
2. **第一段（`tick`）**：调用 [清理工具.py](../scripts/维护清理/清理工具.py) `tick`，仅处理**启用自动策略后新任务**登记且已满足条件的条目——已确认退役的旧版进入 7 天回收、已登记且闲置满 7 天的 `tmp/` 缓存进入 7 天回收、回收满 7 天且无 Windows 占用的文件永久清除；结果写入 `local-data/维护清理/自动维护/最近执行结果.json`。
3. **第二段（`audit`）**：紧接执行只读防堆积体检 `audit`，更新单一报告 `local-data/维护清理/自动维护/最近体检结果.json`（无变化不重复写盘）并追加精简状态行到 `定时维护.log`（超过 `512 KiB` 自动滚动截断）。
4. **边界铁律**：定时任务**只清理已授权到期条目、只输出未登记堆积告警**，绝不自动删除未登记存量、绝不自动关闭他人 `active` 任务、绝不强制删除执行锁。

### 轨道 B：存量及大体积旧副本专项清理（人工批复执行）

当体检发现大体积未登记存量或跨批次冗余副本（如 `68.00 GB → 33.15 GB` 专项治理）时，必须按以下 6 步逐项落实，严禁整目录 `rm`：

1. **只读依赖排查**：全仓检索源码与正式库索引，确认待删路径无现用网页服务、脚本或现行版本引用；区分“现用依赖”与“可再生旧副本”。
2. **独立任务登记**：使用 `清理工具.py protect` 为本轮审核建立独立任务名与独立输出目录（`local-data/维护清理/<专项目录>/`），不修改他人旧任务。
3. **只读扫描与清单冻结**：只读遍历目标目录，逐级拒绝符号链接与目录联接（`0x400` 重解析点），流式计算全量逐文件 `(path, bytes, mtime_ns, sha256)` 生成冻结清单（`.jsonl`/`.json`）与摘要文件，同时做 Windows Restart Manager 全量只读占用检查。
4. **提交摘要待工程师批复**：向工程师展示分类明细、保留边界声明及**冻结清单完整 SHA-256**；未收到明确批复口令前 0 删除。
5. **执行锁内逐文件释放与核验**：收到批复后，在 `清理工具.py` 互斥锁 `lock()` 内二次校验清单摘要、文件大小/修改时间、白名单前缀、保留锚点摘要与 Windows 占用状态，逐文件 `unlink()` 清除（保留目录骨架）并实时写入逐文件及总回执 JSON，若任意一条失败立即中断保留现场。
6. **任务收尾**：核对残留文件数为 `0` 且保留锚点摘要未变后，仅对本轮审核任务执行 `close`，并复核项目最新体积与 [检查项目结构.py](../scripts/检查项目结构.py)。

## 四、防堆积体检阈值与定时管理命令

### 默认体检预警阈值（只读告警，不主动删文件）

| 检查项 | 默认阈值 | 参数覆盖 | 处理建议 |
| --- | --- | --- | --- |
| 僵尸 `active` 任务 | 注册路径超过 **7 天**无文件写入（区分长驻服务） | `--stale-days` | 核实已结束则补全 `enroll` 并 `close` |
| `tmp/` 未登记孤儿目录 | 一级目录未冻结部分 **≥ 50 MB** | `--orphan-mb` | 确认为临时输出则 `enroll --kind cache` |
| 超大未压缩 JSON | `local-data/` 与 `tmp/` 单文件 **≥ 50 MB** | `--big-json-mb` | 改为摘要 JSON + 按需 `.json.gz` |
| 多代重复修订目录 | 同父目录下 `≥ 3` 个修订版且合计 **≥ 200 MiB** | 内置阈值 | 保留最新与当前母版，旧代走专项清理 |

### 常用维护命令（项目根目录运行）

```powershell
# 立即运行一次「定时清理 + 防堆积体检」
python -X utf8 -B scripts/维护清理/定时清理维护.py --run-now

# 单独只读体检（不写入最近体检结果文件）
python -X utf8 -B scripts/维护清理/清理工具.py audit --no-write

# 注册 / 查询 / 卸载本机 Windows 每日 04:00 定时任务
python -X utf8 -B scripts/维护清理/定时清理维护.py --install --time 04:00
python -X utf8 -B scripts/维护清理/定时清理维护.py --status
python -X utf8 -B scripts/维护清理/定时清理维护.py --uninstall
```
