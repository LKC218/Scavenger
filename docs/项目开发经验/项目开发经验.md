# 项目开发经验

## 实战HUD、Live PiP小窗与战术小地图性能

- **矢量战术地图不能单路径全量描边。** 对 3.6 万+ 道路三角使用单 Path `ctx.stroke()`（尤其开启 `lineJoin = 'round'`）会触发 Skia CPU 卡死至 `2628ms / 0FPS`。须采用 1024px 离屏底图托底、次像素（`< 0.55px`）剔除、每 512 三角分批纯 `fill()`、`<= 3.6px` 小建筑跳过矩阵栈、动画期复用烘焙缓存以及停稳后 `vectorCacheCanvas` 硬件位块拷贝（`3KM` 首次 `45.2ms`、稳态 `0.13ms`）。
- **场景内 Live PiP 小窗必须零拷贝隔离并走球面最短弧。** 共用主 WebGLRenderer 与主场景真实载具节点，渲染前原子隐藏地形/建筑/同袍并关闭 2048px 阴影图重算，压至低开销；切单位与反复换向用 `wrapAngleRad()` 球面阻尼防跨 `±PI` 跳动，并提供切静态即只绘 1 帧冻结 `0 FPS` 的省电切换。
- **小地图无级缩放与原地展开要防穿透与防底栏跳位。** 画布内 `wheel` 以归一化光标点为锚点缩放并阻止穿透主 3D 场景；按 `M` 键向右上展开大号战术图前须先锁定父占位容器 `.scv-bl-wing` 宽高防卡片坞抽动，禁用 `transform: scale()` 并纳入 `escStack` 优先收回。
- **底栏三舱严格守住型号清洗与 Code SSOT V2.2。** 同型多车聚合卡片角标上弹独立浮卡防裁切、移除冗余昵称与副标题、禁用原生 `<select>`（用 `bindUiSelect` 向上弹出）及常驻 `.ui-pod` 零 `backdrop-filter`，同时验 `1208×680` 与 `2560×1080` 双画幅。
- **Node 纯规则、微基准与双端 E2E 协同清退旧预览。** 先跑 39 条纯规则单测与微基准定位帧耗，再运行 Chrome + Edge 双端 HUD 与操作交互验证并人工审图；验收合并后及时清退旧对照页与 `?embed=1` 死路由，验证旧地址 `404` 与全仓链接零断链。

详尽实施数据与避坑清单见[实战HUD与战术小地图工程经验](实战HUD与战术小地图工程经验.md)。

## 日常测试产物交接

- 在独立目录输出完毕并确认测试进程退出后，再冻结逐文件摘要。任务关闭结果保留在登记和终端，不回写已经冻结的报告，否则清理复核会误判文件变化。
- 正式或人工复核所需文件先保留保护；登记失败、文件继续变化或进程退出不明时维持保护。七天规则在隔离沙盒验证，真实试运行按实际工作日计数。见[战术演训工具说明](../../scripts/战术演训/README.md)。

## 标签稳定与可操作过渡

- 标签避让不能每帧重新抢首个空位。固定优先级和缓存槽位，使用旋翼完整转动包络，并将布局包络与真实拾取边界分开；稳定构图锚点也不能随旋翼动态AABB跳动。
- 短过渡只影响地图表现，不接管模拟或输入。预算不足以双驻重层时，保留真实总览底层，下载等待与淡出／淡入时长分别记录；过期准备件只能释放自己的引用。
- 事件捕获中的微任务不保证在目标监听器之后运行。用同一事件的捕获前状态及window冒泡后状态核对命令ID和选择集合，避免把实际执行误判成输入被锁。
- 自动化下令应从当前视口反投影选真实合法地面，不能用固定65米目标误判近景不可操作；动画取证必须有真实中间覆盖帧，等待状态不能冒充动画。
- 帧间运动核对使用原生rAF时间；GPU读回后的观测时间另记，不能混作动画dt。短窗口的即时响应按真实持键帧核对，不能硬要求在最后5毫秒内累计转满任意角度；未采到的子项可在同源独立补充，但不得改写原failed报告。


## 空地高度与镜头标定

- 全图最高表面加安全量适合原全图验证空域，不能直接当低地直升机的离地巡航；运行基准点、模型包围盒中心及地面高度须区分，显示与辅助线使用同一口径。
- 飞行不能只避树干。现有树干碰撞与完整树冠范围不同，局部原实例边界可作保守安全包络，不能冒充精确碰撞；保持有界前瞻与缓存，未知时悬停。
- 正交镜头的单位大小主要由可见范围决定，不能只抬降相机绝对高度来模仿参考。以同画幅、近中远层次与空地关系标定，保留原操作语义。
- 世界内单位标签上的滚轮属于战场镜头操作，侧栏和表单则继续隔离；自动化滚轮需等待目标视野实际变化，不能在事件未处理时判收敛。
- 自动地面聚焦须统一粗略／精细高度来源与到达判定，显式空中Y独立处理；否则画面已到总览，聚焦状态仍可能永久不结束。
- 正常到达与手动停止分开：正常到达须完成高度尾段，不能在约30.2米时结束并永久停留“下降”状态；统一高度后还须复核原错层摆场是否变成完全重叠。
- 标签布局的数学候选通过不代表实景可读：后排机身可能封住全部近邻空位，须用真实DOM与截图复核，并给有界空位搜索及明确单位关联；不能缩小拾取框来放行文字。

实现见[演训高度与镜头模块](../../src/战术演训/README.md)，当前人工验收见[高度镜头V002](../地图与载具/战术演训-G01高度与镜头验收.md)。

## 大地图移动候选的终点与异步状态

- 用户终点与寻路网格点分开保存：最终终点不可被边界钳位或附近格替代；粗路径中继点只负责继续求路，不能当作已经到达。
- 地形准备必须有就绪、等待和真正失败三个结果。下载或工作器失败不能无限等待；旧命令回调须核对任务令牌，不能覆盖新命令或释放其租约。
- 沿用旧负载工具时，手动待命不能进入压力测试的出生点重排或自动任务逻辑；默认无任务、无发射需单独核对。
- 鼠标点击操作按钮后可将焦点交回战场，键盘激活按钮或编辑表单则保留控件焦点；否则跟随按钮后按WASD可能失效。界面操作仍不得向地图透传命令。
- 技术验证应覆盖实际移动和到达、队列顺序、真实机身选取及跟随后的屏幕稳定，不能只检查状态文字或布尔值；无窗口回归不代表正式前台性能或人工手感通过。

实现与隔离范围见[战术演训模块](../../src/战术演训/README.md)，具体候选与人工结论见[验收页](../地图与载具/战术演训-G01移动指挥验收.md)。旧共享源码及旧服务保持原身份。

## 空地指挥与尸群分级协作

1. **显示位置与拾取共用一个来源。** 30Hz规则与60Hz显示分别更新，载具与尸群保留前态并插值；标签、点选与框选读取插值后的机身中心。标签布局须避让其他单位机身，特别检查最远缩放下地车标签覆盖飞机的情况。
2. **表现模块不拥有结算。** 旧动画适配中的固定零高度、数组索引绑定和反写模拟不能直接迁入新主线。稳定逻辑ID、本轮身份和真实支撑高度由规则统一提供，声音、动画和特效只消费结果。
3. **先定义人数口径再测性能。** 总逻辑、视野隐藏、视锥外、近景个体、远替身成员与画外交战分别记；内部缓冲像素不能用CSS像素代替。构型名称不代替实际绘制计数，纯规则耗时不代替浏览器整帧。
4. **廉价替身保留可读的来源轮廓。** 大群代理只减少图元而变成土丘会丢失尸群识别。可从原作GLB烘焙少量姿态／朝向图集，合批绘制轮廓平面，同时保持真实成员ID、位置与独立规则。
5. **逐条核对状态到反馈的连接。** 数据字段和音频解码成功不代表玩家能听到群声或看见诱饵阶段。可见尸群与迷雾粗方位分别验音源，诱饵等待、发声、损毁和到时退出须有可观察反馈；反馈只读规则，不能反向改变听觉和伤害。
6. **静态合并网格先核拓扑再派生。** 炮管可能与炮塔共用网格但仍有完整独立连接分量。以固定源摘要、稳定三角集合、零姿态顶点、极限角与炮口一致性证明可分离后再做运行派生；不凭空间平面硬切三角，不改原GLB或假转空骨节点。
7. **恢复先对比完整逻辑，不按字段名猜缺陷。** 群中心可能已在每轮感知更新，不能因初始化取出生点就称其固定不变。误判触发的可选重构先留完整原文和差异，再按范围回到已测基线；恢复不自动成为新功能通过。
8. **所有侧回执都要跟随本轮目录。** 只让总回执接受新路径，仍固定写回旧CPU证明，会破坏版本证据。统一输出目录、预检加排他创建、重复执行拒覆盖，并核对旧凭证摘要；不要为更正汇总计数而重复整轮测试或覆盖原始错误记录。

复用入口：[首批候选](../../src/大地图肃清/README.md)、[工具与测量](../../scripts/大地图肃清/README.md)。

## 地面型号登记与后勤共通能力

1. **资源分类不等于可玩车型分类。** 地面库同时包含完整车型、同底盘变体、固定平台、旧参考车体及待修资源。保留稳定ID，并分别记录资源状态、合法部署、移动能力和专用玩法验收；静态通过不能代替武器与驾驶验证。
2. **型号身份与行为分开。** 补给车不能通过冒用坦克类型再隐藏炮管接入。型号、移动方式、职责和能力分别记录；无已核验武器时明确拒绝攻击，固定平台不得自动拥有自行移动能力。
3. **补给按实际交付结算。** 后方库存、车载物资、已补弹量与维修量分别守恒；移动或取消立即中断，未交付部分不扣费，不积攒满弹时的补给进度。购买只进入后方，不绕过运输直接补满前线。
4. **加载通过与逐车玩法通过分开。** 逐项真实加载、部署能发现解码和克隆问题，不能替代每车外观、炮口、弹道、导航和人工手感。按需加载并限制未使用模板缓存，骨骼克隆与重开释放单独处理。

## 冻结原型的归档与服务退役

1. **端口和命令行都不足以单独证明版本。** 长驻Python服务可能仍在执行磁盘脚本的旧版本；先核对监听PID、进程创建时间、API版本、源码集合摘要及实际HTTP内容。当前脚本改用旧端口也可能提供新版，不能照抄旧命令行当作旧版恢复方法。
2. **停止进程后核对真实端口释放。** 停止调用返回时监听项可能尚未消失，使用绝对截止时间继续核对；归档工具在旧端口仍开放时拒绝迁移，不依据发出停止命令就判断完成。
3. **归档保留与回收销毁分别处理。** 有用源码、JSON、正式回执、失败证据逐文件移入当前版本历史资料，保留字节摘要与修改时间，用旧新路径映射维持追溯。阶段截图只按明确清单进入统一七天流程，不能把源码快照伪装成缓存或扩大图片删除授权。
4. **新的回归不能覆盖通过凭证。** 验收替代件绑定具体文件身份；当前验证与诊断写入独立UTC时间戳目录，历史成绩继续绑定原版本。修改测试脚本的默认端口时，保留独立数值与原骨骼对照，不为截图而长期依赖旧服务。
5. **由依赖负责人完成真实阶段交接。** 过宽目录登记由其负责人核查并在新阶段建立实际需要的保护，原阶段明确停止使用后才能关闭；实施会话不替其他会话解除保护。单机GPU短回归与并行长测先协调空档，避免污染性能样本。
6. **核对回收回执是否真正接入后续策略。** 命令显示回收成功仍需检查策略身份和逐文件回收时间；手动入口与定时入口应遵循相同授权链。修复漏标必须显式核对当前注册、验收和实际载荷，只补元数据，不重置七天期限、不接管旧回执；通过沙盒跨越时间边界验证后再处理本次具体回执。

## 参考视频与原生连续音效迁移

1. **把事实和适配值分别存档。** 视频证明可观察的流程，原表证明字段，资源指针证明媒体关系；三个证据都不能单独证明完整运行公式。把未见的鼠标语义、武器评分及循环点明确列为未知或网页适配。
2. **先看指令链，再画按钮。** 取消、停火、武器关闭、手选与自动择优各有语义；Shift队列必须连上当前任务，预览与提交必须共用编队落点计算，不能显示一套、执行另一套。浏览器保留快捷键要提供可实际使用的替代键。
3. **原生非一次性事件不能逐弹重播。** GAU8需要持续发声、连射续活和停火尾音。持续声和尾音独立分组，并按资产ID寻找新声部；只按射手分组会把尚未结束的尾音误设为循环，必须覆盖“尾音未结束再次开火”的回归。源FMOD事件参数、渲染产物和网页循环派生分别记录；接缝淡化不得冒称原PCM完全未变或原作循环点。
4. **声音必须服从物理终止类型。** 飞到预测点、超出寿命、撞建筑、撞地与击中实体分开处理。非空爆弹不能在空中预测点结算范围伤害，也不能播放虚假命中声；命中长尾预算按射手与武器分组，不按每弹新建无限独立组。
5. **验证承诺的保护范围。** 本轮只承诺镜头不变，应逐方法和参数核对镜头；输入和战斗已主动修改，不再沿用整个输入文件摘要不变的旧声明。实际键鼠、受控音频调度、真实攻击流程和180秒性能样本分别报告。

## 换波与骨骼合批及机炮事件

1. **先分阶段定位。** 防线V001实测逐只动画与绘制提交是主要成本，750只换波的角色重建约146毫秒。不能因画面低分辨率就只减贴图，也不能把CPU绘制方法计时称为GPU耗时。临时CPU剖析与正式无剖析器采样独立留档。
2. **动作可共享数据，角色仍独立。** GPU按原片段采样姿态并按型号实例提交，位置、生命、胶囊碰撞和相位继续独立。角色／尸体实例、纹理和着色器在加载阶段准备，换波只写入已分配范围，避免整批释放和克隆骨架。
3. **姿态比较必须统一世界单位。** 作者网格单位和内部变换不同，局部顶点误差不能直接当米。对照原SkinnedMesh与合批计算的世界空间顶点，区分精确关键帧、插值和动作混合，再实际查看同相机截图，不能只看无报错或绘制次数。
4. **有限事件渲染不等于单枪片段。** M230源事件长约10.26秒，含前导渲染空白和长尾占位；逐弹播放会挤满声部。保留正确源事件，按原PCM对齐并采用同单位尾音替换，真实触发、实际播放、声部上限与人工听感分别验证，不通过变调或换通用机枪掩盖问题。
5. **对照时保留操作与负载身份。** 镜头、输入和战斗文件以摘要证明未变；同样视口、内部像素、种子、声音和阴影下串行测量。首波500会增长到750／1000，必须报告实际存活范围、长帧与欠时；不能用不同数量或隐藏角色来取得更好的成绩。

## 载具与尸群合并战斗

1. **导航等价方向不能盲目相加。** 墙前左右距离场相同，两个向量求和会抵消；若回退到正前方向，个别丧尸可永久卡住并阻断波次。等价邻居应采用稳定择路，完整波次验证保留墙前残留与数量守恒检查。
2. **渲染序号与战斗ID分别管理。** 既有角色分配按数字序号索引，战斗需要跨波唯一字符串ID。适配器传数字渲染序号，规则保留稳定战斗ID，不能把字符串直接用于数组索引，也不能让新波复用旧导弹目标ID。
3. **伤害、动画与显示预算独立。** 死亡后立即退出活体查询与导航，程序倒地和有限尸体继续显示。共享材质不能直接改变单个尸体透明度，单独克隆死亡材质并在重开时释放，保留共享纹理和片段。
4. **动目标需要实际弹丸提前量。** 子弹指向发射瞬间的位置会系统性落在移动丧尸后方。先求相对运动的截击时间，普通弹离膛后固定飞行；制导弹另设角速度上限，反向目标不能因插值抵消而永远无法转弯。
5. **合并后重新测完整负载。** 固定角色资源、源码、种子、镜头、内部尺寸、声音与数量，分别保留模拟CPU、帧P95、存活数量、可见尸体和声部预算。循环压力中的存活数量会变化，不能写成全程固定500只；前台试玩与无窗口技术检查分别验收。

复用入口：[防线原型说明](../../src/载具靶场/README.md)、[实施计划](../地图与载具/载具丧尸战斗原型-第一版-01a1a2af-实施计划.md)。

## 参考游戏参数向丧尸战斗迁移

1. **先固定配装，再读参数。** 单位、选项、炮塔、武器和弹药需要同时关联，弹药还要限定UnitId及正Quantity。一个型号的全部可选武器不能当成一套已装配配置；挂架复用与弹药关系数量分别记录，未核对调用前不推导整机总备弹。
2. **原值、当前值和建议值分别维护。** 原作Damage不等于本项目生命值，未确认的单位、枚举和位掩码保留原值。当前参数读取实际规则导出，建议基于工程师确认的100生命基准独立设计，避免把手感调整写回原始证据。
3. **方法声明不能证明算法。** 命中检测、穿深和伤害方法签名只证明声明存在。调用顺序、分支、公式和实战行为需要独立证据；网页建议流程明确标成项目设计，不伪装原作还原。
4. **弹丸碰撞和爆炸遮挡分别验证。** 弹丸先撞建筑不代表爆炸对墙后目标无伤害。群体战斗应检查范围候选、距离、墙体、同弹去重与唯一死亡事件；特效显示上限不能造成伤害漏算。
5. **任务目标决定火力取舍。** 没有敌方载具且丧尸冲击基地时，清群范围、命中次数、重定位和出动周期更直接影响体验。原穿甲系统保存为参考，不必接入普通尸群；合并车辆、动画、弹丸、伤害和死亡表现后重新测性能。

复用入口：[战斗设计建议](../地图与载具/三车对丧尸战斗设计建议.md)、[参数研究脚本](../../scripts/断箭/玩法参数研究说明.md)。本轮为研究沉淀，未把建议记录成已经实现的能力。

## 地图组件来源与材质回读

- 源三角形数一致仍可能产生重合面自遮挡。Airbase城市楼房在完整源面策略下出现三角黑块，白模诊断确认来自同材质、同绕序、全部角点属性相同的完全重合面；仅对此类面归并并记录逐源面映射，保留反向面和属性差异面，不能靠改为OPAQUE消除问题。133种原型源面2357969，渲染派生2276422，81547面显式归并，独立回读仍严格核对派生面数及绕序。
- 裁切贴图的RGB与Alpha读取语义须一致。源工程按STRAIGHT读取、GLB按CHANNEL_PACKED读取时，围栏插值会有亮暗偏差；统一独立通道读取后再对照。Cycles还会因源中重合正反面产生与栅格化不同的遮挡，不能只设置视口背面剔除就声称光线追踪也已剔除。源面不动，改用与网页一致的栅格审图后，133种工程与GLB四向最大前景平均差异为0.0064／255；这是原型比较，不代表完整原Shader或网页性能通过。
- 自定义Shader不能机械读取通用Alpha字段。BloodTree真实参数反射中`_AlphaClip`在UnityPerMaterial偏移48字节，`_BurnClip`在196字节；编译程序在正常状态使用前者。对各材质读取原0.15至0.4阈值，避免套用0.5裁掉枝叶。Building_shader_V2同样已有独立`_AlphaClip`依据。毁伤与正常状态不能混用。
- 链接工程的可移植性要靠实际收集后重开。A1按包内层级收集34份原型工程和1份总装配，独立Blender逐份核对相对链接、内嵌图像及摘要，35份均通过。源级2公里预览实际读取240871008字节GLB，不能把本机约4秒完成查询及加载的冒烟记录当作全图20MiB地图预算或限速网络成绩。

- UnityPy标准组件头与外部生成类型树须逐对象对照。本机构建中TypeTreeGeneratorAPI0.0.10直接IL2CPP读取失败，既有Cpp2IL恢复带序列化属性的空方法程序集后可生成载荷类型树；生成头的对齐仍会读错脚本PPtr。使用UnityPy原生头替换，并严格核对完整字节，187个场景组件通过；原轮廓后处理和HDRP反射的两项差异保留原字节与范围说明。方法只证明本机构建，不推广为所有Unity版本通用兼容。
- 编辑器初始禁用不等于游戏运行时不使用。Airbase树管理器在场景初始禁用，但原生加载方法读取TreeManager并调用`SetActive(true)`；Terrain中467331条树木来源应继续对账，不能仅凭活动标记排除。草丛密度与源树木位置是两类数据，非零密度格不等于最终实例数。
- 几何回读通过仍须看实际材质。18种样本首次回读中，岩石的不透明底色被Alpha预乘且GLB漏掉底色因子；修正为通道打包读取并冻结因子后，72组四向图最大前景平均像素差约0.441／255，几何包围盒最大差约0.00000048米。该结果属于原型样本，不能继承为全图、浏览器或工程师人工验收。
- 源UV异常先全量盘点再局部修复。当前6个网格共83个NaN顶点都有同源三角形内有限邻点，最远约8.97厘米；原始数据保留，派生副本记录具体邻点、距离和摘要，几何不变。局部UV修复不能表述为恢复了失效值，仍须单独审图。

实际入口见[地图提取说明](../../scripts/断箭/地图提取说明.md)，逐关口结果见[全图验证报告](../../reports/断箭/Airbase全图与双层入库验证报告.md)。

## 十三款角色拆分与动作证据

- 加权骨骼的语义映射先取该网格加权骨与祖先的闭包，再解析源骨名。编号11没有实际加权头颈，精简为21骨且约0.967米；其余独立角色为23骨。用必需动作关节校验，不能为统一计数补假骨或把所有角色强行等高。
- 原包各款朝向不同。根据每款肩线和脚朝向建立身体坐标，再将动作轴由骨架空间转换到骨骼静置局部空间。复用编号0的固定朝向和动作轴会让其他款朝侧面或背面；多视角图能发现纯计数检查漏掉的问题。
- 拆分保真与新动作分别取证。新增12款各721个原动作采样点逐顶点比较；待机与移动是项目自制循环，逐帧校正整体脚底高度，不声称足部IK、无滑步或原生运动捕捉。
- 动作测试夹具也需要复核。Three.js缓存的Action在单次结束后可能仍处于暂停，混合后还可能保留0权重；取动作截图前显式恢复循环、重置并设置有效权重1。否则真实资源有动画，截图仍会是T姿态。不能用该截图把资源判作动画通过或失败。
- Meshopt可循环移位三角形的三个索引。比较有绕序的三元组、节点、权重及动作访问器，数值误差容差单独定义；不要把数组字节变化直接判为拓扑变化。本轮新12款用Meshopt与嵌入PNG以便Blender直接重开，既有编号0的KTX2资源保持身份，由双浏览器直接核验；两类证据不能混称为26份都由Blender直接导入。
- 统一库增量先验证排他锁、竞争版本、输入摘要变化不切换及成功提交；独立目录写完后才原子切换指针。Windows对只读描述符调用fsync会报无效描述符，落盘临时指针应使用可读写描述符。旧索引、既有模型、声音、原件和靶场清单逐项保留。
- 资源和性能对话按唯一写入方交接，JSON同时冻结库指针、目录索引、13种源网格及每档文件身份。Blender、整库WebGL回归与前台长测串行；窗口释放须明确通知。复用同一冻结身份的已有证据，只补实际缺口。

## 多任务交叠清单的精确回收

- 冻结清单保持原字节；执行子集另存预检与摘要。另一个任务已回收的文件按原路径、大小、摘要及实际载荷逐项去重，不能重复移动或把同内容不同路径视为同一审批项。
- 明确活动保护优先：本次旧固实归档被另一任务要求保留，即使进入原批准清单也暂缓。六个早期未知范围不能整组关闭；只对经依赖与任务证据复核的获批文件限定处理，新增任务保护始终阻止执行。
- 预检冻结任务登记，执行用共享锁；每文件复核身份，每批查询Windows占用，移动前后记录并同步日志。进程未持锁不代表没有未来依赖，需要同时核对任务、服务路由和当前资料入口。
- 回收使用项目内逐文件移动，保留原相对路径和完整指纹；恢复拒绝覆盖。七天用实际移动时间戳计算，不靠累计休眠，不自动永久清除。
- 同盘回收不释放空间。分别报告本批、并行已处理、保护保留和永久删除；回收后再做完整模型解析、音频解码及固定8768实测，不能只验证目录存在。

## 多款骨骼角色交接与性能准备

- 同一来源包中的角色不一定共享朝向。源动画逐顶点检查通过后，仍须逐款核对身体前向、动作轴与逐帧落地；中间技术通过批次不能直接冻结为性能输入。

- 混合分配先按款均分再用独立随机流洗牌，保持同源码单款对照的导航种子。逐款统计应记录分母并检查每帧完整性，总数500不能证明13款都实际更新。
- 配置规则和交付摘要检查属于功能准备；实际GLB解析、动画轴与落地、可见前台180秒性能分别验证。旧单款700只不等于新资源混合容量。
- 交付接入后，使用固定种子的原地动画观察逐款蒙皮顶点与骨旋转变化，避免把根节点移动当动画。混合500只可逐款核对38或39只、13份共享几何与500独立骨架；共享不会自动减少蒙皮绘制调用。
- 正式矩阵在页面内串行驱动，逐组自动归档后再开始下一组；页面失焦、Windows前台不合格或写入失败即停止，不抢焦点。单独运行报告JSON／CSV逐帧分析，避免与正式采样争用CPU及磁盘。
- 前端源码字节与服务清单一同冻结，源码变动后拒收样本，避免旧进程清单摘要配上新文件内容。容量配对需要相同浏览器、源码、镜头、画质、显示尺寸、种子及窗口环境，不把不同条件的开阔和通道各一组拼成通过。
- 十三款混合在本机内置Chromium 156完成15组正式矩阵：500只开阔180秒140.10 FPS／P95 7.3毫秒，通道136.82 FPS／P95 13.5毫秒，双场景模拟欠时0、最低视锥和动画数500、Windows前台观察100%。结果仅覆盖RX 7900 XTX、Ryzen 7 9800X3D、640×360与冻结源码`473ee85a…5805ace`；未探索相邻数量，不将500称为绝对上限，也不继承旧单款700成绩。
- 异步GPU查询可能晚于样本完成回填。正式报告采用自动归档时的有效查询快照；手动晚下载时应比较帧间隔、CPU及各款计数，并单列GPU晚到差异。本次通道最后2帧属于晚回填，不能用手动数组的GPU数量配上旧摘要计算新的均值。

## 五百只丧尸的真实动态实验

适用范围：单款低面数角色、固定30Hz平面群体、独立Three.js测试场。实现入口见[模块说明](../../src/丧尸群体测试/README.md)，数据见[动态记录](../../research/丧尸模型/性能测试记录.json)，可视化见[实测报告](../../reports/丧尸模型/五百只同屏性能测试报告.html)。

### 先确认动画是否真的适合移动

原始GLB把13只角色放在一个287骨骼蒙皮中，不能直接复制整组500次。编号0实际加权骨及祖先共23根，旧脚本已证明拆分可保持原动作；新准备脚本复用这一拆分函数，未复制旧摄影棚与静态百只场景。

约30秒原动作包含踉跄和转向，首尾不连续，因此本轮另在原骨架上制作2秒待机与1.25秒移动测试循环，明确记录为自制动作。准备前先读取真实骨名、静置姿态与坐标轴：当前骨名是`CC_Base_L_Thigh_0279`等，并非通用LeftUpLeg命名；旋转必须转换到各骨静置局部坐标，不能按猜测轴统一套旋转。

导出后在全新Blender进程重新导入检查，而不只检查导出返回值。当前回读23骨骼、659顶点、两片段首尾最大误差0，移动动作四分之一周期实际蒙皮顶点最大变化约0.249米。浏览器还检查不同时间的蒙皮顶点与独立动作相位；整体模型平移不能替代骨骼动画证据。基础循环没有足部IK或专业动作质量验收，正式动画仍需另行制作。

### 共享资源与独立状态要分清

用官方SkeletonUtils进行骨架安全克隆，每只保留独立骨架、Mixer、动作权重和时间；网格、纹理与动画片段共享，只缓存8份配色材质。500只约40万角色三角形、11500根骨骼，仍约500次角色绘制；共享几何不会自动合并蒙皮绘制。

重置时停止并解除旧Mixer绑定，释放旧骨架的骨纹理，保留共享资源。纹理计数约500可能来自独立骨纹理，不应误报为原始贴图复制500次或据此推算显存。文件压缩、JS堆、纹理数量、GPU显存是不同指标。

### 群体导航先共享全局方向

目标改变时重算一个流场，能直达个人落点时直接前进；目标区域分散落点，避免所有人追同一点。空间网格减少邻居候选，局部分离限制有效邻居数，速度和转向平滑。窄通道使用膨胀障碍及移动约束检查通行，不能只绘制障碍而让逻辑穿过。

模拟固定30Hz、显示插值；自动往返每24秒换向保持可复现负载。拥挤时允许身体轻微交叠，局部分离不是完整人群物理。通过者数量、是否有无效坐标、是否进入障碍分别验证，不用一张拥挤截图证明寻路正确。

### 用真实帧时间解释性能

记录静态、原地动画、开阔移动、通道移动四种负载；100、300、500逐级比较。默认640×360，480×270与1600×900明确标注，不把低内部尺寸写成高分辨率渲染。镜头与像素手感参考已有靶场，视野按人群尺度重新校准，不能照搬载具的96米跨度。

CPU按群体模拟、动画更新、位置与矩阵同步、渲染提交拆分。模拟平均数以每显示帧计算，部分帧没有模拟步；不能把该数当作单次30Hz模拟耗时。总帧间隔还包含调度、UI及垃圾回收，不能用CPU分项相加取代真实帧时间。

GPU采用异步计时查询，丢弃disjoint结果，限制在途查询，避免同步等待制造停顿。CPU的render调用耗时不能冒充GPU时间。FPS按帧数除以实际总间隔，保留P95、P99、最长帧和长帧比例。

长帧不能只截断后报漂亮结果：模拟追帧上限与丢弃时间累计为欠时，原始帧间隔保留。标准采样锁定500只总览，记录最小视锥内和动画更新数量；静态模式动画更新为0，其余模式应持续更新全部角色。

### 前台验收要能发现中断

功能回归使用独立无窗口浏览器，前台性能计划使用独立可见Chrome和Edge串行运行，明确记录版本、GPU、视口、内部尺寸、DPR、种子、源码和资源摘要。采样预热10秒，常规60秒，关键场景180秒；页面隐藏、失焦或外部取消不能作为有效样本。首轮前台试跑曾超时，后续原生检查发现连续窗口中断，均未纳入正式前台结果；工程师暂需使用电脑，桌面矩阵延期。

Playwright可能模拟页面焦点，即使`document.hasFocus()`为true，原生窗口仍可能最小化或处于后台。独立窗口增加原生可见、最小化和前台检查。改用内置浏览器后，页面可见性与宿主窗口前台仍是两回事：每0.5秒只读观察宿主，公开样本前台比例，不抢焦点、不记录其他应用身份。宿主混合条件可保留真实压力数据，不能写成全程原生前台验收；内置Chromium的结果也不能改名为桌面Chrome／Edge结果。

性能采样不同时录屏；完成后再截图。JSON和CSV通过实际按钮下载检查。报告从有效固定样本生成，时间曲线采用等长窗口内最长帧，保留尖峰并说明采样口径；全量逐帧数据留在本地，正式研究摘要保存原文件名及指纹。

### 寻找稳定60帧的数量边界

工程师确认的判据为180秒平均≥60 FPS、P95≤16.7毫秒、>33.3毫秒比例<0.1%、全群位于视锥内且持续动画、模拟欠时0。20秒探索用于找通过与失败区间，随后缩小到50只步长，候选最高数量分别做开阔和通道180秒复核；平均FPS略过60仍可能因尾部帧时间失败。

数量扩展必须检查生成范围与配套实例缓冲。原500只布阵用固定23列，直接改成1000以上会越出场地；新版把额外数量收紧在有效左侧矩形，目标区间距随数量缩小，地面投影实例缓冲按实际容量重建。因场地不扩大，密度及拥堵增加，这是本场景的压力条件，不能外推成同等密度的大地图。

扩容前保存源码快照，扩容后重载并记录新SHA-256。原500只基线与新数量结果可以并列阅读，跨版本不能当作严格增量对照。当前机器在日常工作并行条件下采样，所得最高已通过档需要连同GPU、内部尺寸、浏览器、窗口条件和场景说明；不能承诺完整战斗、其他设备或其他时段的绝对上限。

当前容量版900只通道180秒记录约69.91 FPS，但P95约20.9毫秒，未达到稳定标准。CPU平均每显示帧的动画约5.70毫秒、渲染提交约5.86毫秒、同步约2.09毫秒、模拟约0.23毫秒；GPU异步查询约2.74毫秒。这指向CPU动画与提交优先，不能仅继续降低内部像素或继续减少已很低的角色面数。后续可评估共享烘焙骨骼动画纹理与实例化蒙皮绘制，仍需独立实现和同条件复测，不能预报优化后的容量。

最终700只在两场景180秒均通过：开阔73.57 FPS、P95 14.3毫秒，通道78.96 FPS、P95 14.2毫秒；全群入镜与动画最小值700、模拟欠时0、宿主前台观察100%。相邻750只开阔P95约20.6毫秒失败。800只通道通过而开阔失败，说明不能用单场景通过值代表整轮容量。700只是本次机器、内置浏览器、640×360、当前版本及工作并行条件下的最高已通过档；换设备、加入战斗或优化架构后应重测。

### 保持模块边界与来源

实验源码独立于载具靶场和资料库，只有固定本地Three.js及官方addons共享依赖；研究目录不作为运行依赖。8769只提供白名单文件，校验引擎和GLB摘要，不暴露整个项目目录。原件、旧工程不覆盖，派生GLB、Blender工程和完整采样在独立本地批次，来源、CC BY 4.0及自制动作说明随资源保留。

## 静态载具到可玩靶场

当前样例见[靶场模块说明](../../src/载具靶场/README.md)及[实现与验证报告](../../reports/载具靶场/原型实现与验证.md)。适用于已有高面数静态模型、俯视战术镜头、网页单机打靶验证；不代表全库通用资产优化或完整RTS导航。

1. **先确认可见几何再驱动空节点。** AH源旋翼标记没有网格后代，转标记不会带动叶片。对焊接位置连通分区，保留原索引三角形，分别拆出主旋翼、尾旋翼、机炮；坦克独立炮塔仍需分出炮管。新枢轴用保持世界变换的挂接方式，源静态模型只读，程序动作明确标注。
2. **先缩纹理、共享资源，按实测决定减面。** 本次两款GLB体积合计减少35.9%，所有三角形保留；五份同型号共享几何、材质、纹理。像素化只减少填充像素，约573K场景三角形和约217次末帧绘制仍真实存在，不能把像素画面等同低模拟成本。
3. **把命令、武器与弹丸拆开计时。** 模拟无DOM，按固定步长推进，装填从发射计时；已发导弹与射手新命令独立。E清任务，Esc清预览，暂停冻结模拟但允许收命令。音频由移动／射击／命中事件驱动，重置使旧异步播放失效，有限WAV不冒充无缝循环。移动片段的重播间隔由状态调度控制，不叠加长动作冷却，否则停止后立即重启会静音。
4. **界面自动化要验证真实动作，等待真实完成条件。** 首次浏览器验证曾在坦克刚走到墙角时立即重发攻击，仍受遮挡是正确规则；改为等待移动任务完成再攻击。等待“坐标开始变化”不能代替“已到达射位”。Three.js 0.187.0的GLTFLoader还依赖SkeletonUtils，白名单必须覆盖真实导入链；不为自动化字符串求值放宽页面CSP。
5. **记录负载与验收条件。** Chrome／Edge各做10单位攻击与两档采样，P95约6.1至6.2毫秒只适用于本机短时无窗口条件。480档要重置后重新攻击，不能用640档销毁目标后的空闲段冒充战斗。资源哈希、规则检查、真实键鼠、长时可见窗口和人工听审分开验收。

## 低面数角色包先检查绑定与动作组织

每只约800三角形不代表整包可以直接复制为运行角色。本次13只共用287骨骼，实际每只加权18至20骨；编号0保留必要祖先后为23骨。应按顶点权重和祖先链拆分，再在整段动画上比较变形顶点，保存后用新进程复核。只数骨骼、看首帧或文件成功保存都不足以证明动作保真。

动画名为CameraAction仍可能包含骨骼、相机及形态键多个槽。导入后检查真实目标；本次空形态键确证为零位移才从测试副本删除。24 FPS下约29.98秒的动作首尾顶点最大差约0.732米，整段循环会跳变；需要按实际姿态挑选和整理动作，不能仅把动画改名为行走。

贴图整体乘色会同时改变皮肤与衣服，分区变化需要遮罩或重新整理调色板。100只静态姿态用于检查风格、轮廓和重复感，不能转作动态蒙皮、寻路或Three.js帧率证据。候选源GLB、派生工程、渲染图与后续正式运行包分别管理。案例与边界见[模型测试报告](../../reports/丧尸模型/模型测试报告.md)。

## 群体性能先拆分成本并建立真实基线

500只、每只约800三角形，只能推算基础几何约40万三角形，不能由此判断稳定60 FPS。动画插值与矩阵、绘制提交、GPU蒙皮与像素、寻路避让、阴影和特效分开测量。普通蒙皮的顶点变形通常已在GPU，进一步烘焙动作主要减少CPU姿态计算；普通实例化也不自动提供独立骨骼动作。共享材质不等于减少Draw Call，合并图集不等于合并不同几何。

先用已精简的常规骨骼做基线，按静态、动画、移动避让、攻击死亡、完整地图逐项加入开销，证据表明有瓶颈再增加烘焙或实例化适配。群体可共享方向或路径缓存，用二维空间网格查询局部邻居，感知和重寻路分批执行；具体频率、流场方案和并发数量仍是建议，不视作已确认游戏规则。

100只静态预览、500只同屏讨论目标、真实动态性能验收分别登记。全部角色同屏时不能只靠视锥剔除解决问题；还需看屏幕尺寸、缩放、交战重要性和拥挤退化。记录设备、实际渲染GPU、浏览器、分辨率、帧时间分布和峰值，避免只有平均FPS。完整建议、官方出处与未验证项见[丧尸群体设计与性能研究](../丧尸群体设计与性能研究.md)。

## 断箭操作参考与载具靶场交互

**适用场景：** 参考成熟RTS的操作设计，使用已有静态模型和音效搭建网页载具打靶原型。

**决策入口：** [断箭交互设计经验与原型约定](../地图与载具/断箭交互设计经验与原型约定.md)集中保存官方来源、已确认范围、操作设计和分层验证条件。工程师于2026-11-03确认五条规则：超射程自动接近；指定攻击或Q攻击移动才交战；视线受阻停下提示；AH-64D手选机炮或导弹；停车或悬停后瞄准开火。目前已在独立靶场实现，自动化结果与后续试玩分开记录。

**补充约定：** 工程师随后确认首轮电脑键鼠与Chrome／Edge、按游戏手感调整射程及等待、友军不拦弹不受伤。浏览器分别验收，具体参数仍需实测；友军弹道规则不替代载具行驶避让。按[原型实施计划](../地图与载具/载具打靶原型-实施计划.md)先检查两款资源，再完成1加1闭环，最终验证5加5，不把阶段性缩小样本写成最终单位范围变化。

1. **参考行为要保留证据层级。** 官方资料描述、本项目决策和实现结果分别记录。尤其不能把本项目超射程自动接近规则，反写为已核实的《断箭》坦克或直升机右键行为；手册默认键位也不能代替当前版本实操。
2. **命令需要有条件、过程和结束方式。** 普通移动、指定攻击与攻击移动表达不同意图。预览取消、已提交命令取消和武器停火分别定义；持续攻击与一次齐射明确结束条件，避免排队后永远无法执行下一项。
3. **不能开火也必须有反馈。** 把接近、停稳、转向、瞄准、装填和受阻分别显示；地面绕障碍与自动寻找射位分开处理。混合命令由单位逐个判断，受阻数量和原因可见，不静默忽略不兼容对象。
4. **动作与武器状态应独立可追踪。** 装填从发射后计时，弹丸独立飞行；改令须使旧待发任务失效。声音读取实际移动、发射和命中事件，不能每帧触发，也不能把按钮点击等同开火成功。
5. **先确认可动结构，再优化资源。** 空节点或部件名称不证明网格能动；炮塔、炮管、旋翼及挂点需实际核验。使用派生副本制作程序动作后再减面或合并；按车型和战术镜头检查外观，低分辨率不能代替几何、材质和模拟开销测量。

**验证方法：** 先简模指挥，再真实载具动作，最后打靶与声音联动。至少检查单选和混选、排队和取消、超射程、遮挡、武器切换、目标销毁、UI透传、失焦恢复及重置。当前10单位原型已完成规则与双浏览器检查，性能结果只适用于报告记录的短时无窗口条件，不能扩大为长时间设备通过。

## 大型资源提取与静态交付

**适用场景：** UnityFS 大包、Granite 虚拟纹理及运行时分件装配的离线研究。

- 对包逐块解压，UnityPy 从节点文件流读取；按需解析主数据包节点，避免将所有展开数据同时放进内存。缓存带完整标记与摘要，未完成缓存不当成功复用。
- Granite 可能独占打开 GTP，多个模型并行时应对纹理提取加跨进程锁。保留失败目录，再用新目录重试；把失败缓存当成功缓存会制造无贴图模型。
- 先从材质字段与实际编译 Shader 确认图层、色彩空间和通道公式。UnitV3、迷彩与乘员材质分别处理，不能因属性名相似就共用遮罩规则。第二 UV 迷彩需依照其采样关系烘焙，不能逐像素叠加两张贴图。
- 装配矩阵只对独立部件整体应用一次。共同骨架尺度可与已应用 bindpose 的静态几何尺度不同；用数据库关系和作者矩阵定位后，仍需实际审图。发射模板不一定是静态安装件，弹药悬浮或重合时保留异常证据。
- 结构检查不能发现白乘员、黑白块材质、悬浮弹药等视觉错误。每项实际查看四视角及独立 GLB 回读，审核图像带 SHA-256；修复重建后必须重新审核，旧图不能证明新产物。
- 通过项和待修参考分目录，说明基础机体与装配版的差别。生成交付库前核对载荷回执，复制后再次校验，避免选错旧结果或漏文件。

本轮具体范围与尚未恢复的旧资源见 [批量导出报告](../../reports/断箭/批量导出报告.md)。这些方法没有替代引擎集成、动画或设备性能验收。

| 现象 | 本轮确认的原因或边界 | 可复用处理与验收 |

### 静态层级与动画能力分别验收

本轮导出器把蒙皮按序列化初始骨架姿态计算为静态顶点，构建器将源层级保存为空对象与网格；没有重建可驱动网格的 Armature、蒙皮绑定和动画曲线。GLB 导出明确设置 `export_animations=False`。因此，“保留骨架节点名称和层级”只能证明结构被记录，不能证明模型已有可播放动画；单独启用 GLB 动画导出也无法恢复上游未保留的绑定和曲线。

| 能力 | 验收证据 | 本轮状态 |
| --- | --- | --- |
| 静态模型 | 几何、材质、四视角及独立回读 | 逐项记录通过或待修 |
| 变形绑定 | 有效骨架、顶点权重、bindpose，以及改动骨骼后的网格响应 | 当前交付未恢复此能力 |
| 动画片段 | 来源片段、目标路径或绑定、关键帧、时长与实际播放 | 未核查和导出，不据此推断游戏源资源没有动画 |
| 程序驱动动作 | 实际驱动节点、轴向、枢轴及动作规则 | 未验证；旋翼、炮塔、起落架等不能仅凭部件名称判断实现方式 |

后续若开展动画恢复，应从源资源重新保留所需蒙皮数据与曲线，先验证一个型号的一段动作，再检查独立回读中的运动、静止姿态、循环或首尾帧。新增制作或程序模拟的动作应明确标为新建动作，不能称为提取到的游戏原动画。该步骤是后续建议，本次未执行动画提取。

### 批量执行的最小闭环

固定输入与工具 → 单样本验证 → 按清单分批处理 → 逐项结构与视觉审核 → 明确版本选择 → 复制与指纹核验 → 离线目录检查。每件保留观察、限制、源路径和当前审核图指纹；配置变体、独立挂件与去重后的车型分别计数。

修复时保留旧产物，按材质、挂件或骨架依赖定位受影响集合，重建并重新审图后再选入模型库。输入摘要、工具执行、静态视觉、动画和引擎性能各自记录结论，避免将局部通过扩大到未验范围。

## 二、由可见流程确定最小验证目标

原片支持的局部流程为“巡视战线→选择对象→检查当前状态/动作→指定位置、朝向或范围→观察执行与损毁→再部署”。这不是完整经济或战役循环；片尾仍在交战，没有结算。

**研究阶段的最小实验建议：** 用占位几何体和少量对象验证“选择集合→位置/朝向预览→提交命令→执行反馈→取消或改令”，再扩展选择能力与延迟动作。该实验方法继续适用；当前首轮原型范围已确认为俯视RTS指挥、5辆M1A2加5架AH-64D，具体规则以[载具靶场约定](../地图与载具/断箭交互设计经验与原型约定.md)为准。僵尸、联网和建造经济仍未纳入首轮。

**验证方法：** 让第一次使用的体验者说出“当前选中谁、目标在哪、到达朝向如何、命令是预览还是已提交、现在能否撤销”。记录误选、误提交和重复点击位置。不能用报告二维演示通过，代替Three.js游戏已验证。

## 三、输入动作与设备事件分开

设备层将键盘、指针等事件转换为明确动作，规则层再判断动作能否执行。界面按钮和快捷键可调用同一个动作，减少两套规则不同步的问题。

Pointer Events 可提供鼠标、触控和手写笔统一事件入口；统一事件并不意味着各设备可以共用相同操作布局。[MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

若后续选择第一人称视角，再评估指针锁定；通过主动点击进入，监听锁定、解锁和失败事件，并提供恢复入口。[Three.js PointerLockControls](https://threejs.org/docs/pages/PointerLockControls.html)、[MDN requestPointerLock](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestPointerLock)

## 四、指向对象与执行操作分开

Three.js 的 `Raycaster` 可返回命中对象和距离。建议只检测明确候选对象，并结合可达距离、遮挡和当前状态判断是否可操作。地面移动指令和物品交互应使用不同规则，防止点中装饰网格触发错误操作。[Three.js Raycaster](https://threejs.org/docs/pages/Raycaster.html)

**验证方法：** 检查遮挡、过远目标、已移除对象、重复点击及界面覆盖区域。命中检测通过不等于玩法规则通过。

## 五、时间与暂停显式建模

动画与移动按时间戳差值更新，避免每帧固定递增造成刷新率差异。`requestAnimationFrame` 的回调时间戳和 `performance.now()` 可用于计算经过时间。[MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[MDN performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)

现实截止时间和可暂停的游戏时间应分别定义。浏览器隐藏时暂停、清理持续输入；恢复时重置本次时间基准，避免后台累积差值导致角色跳跃。当前 Three.js 的 `Timer.connect(document)` 可利用页面可见性处理后台大时间差。[MDN 页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[Three.js Timer](https://threejs.org/docs/pages/Timer.html)

**验证方法：** 测试切换标签页、最小化、返回、释放指针和暂停后恢复。是否允许某类倒计时在暂停期间继续，必须由玩法明确决定。

## 六、性能结论必须附带测量条件

视频观感无法证明本项目运行性能。首个可玩原型应记录设备、浏览器、分辨率、首屏加载和帧时间分布，并观察绘制调用、三角形数与资源数量。

`renderer.info` 可辅助查看渲染和资源统计；其中资源计数不能当作准确的 GPU 显存字节数。[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)

建议控制绘制分辨率并提供画质降级。高像素密度会增加渲染工作量；阴影、后期和同时活动单位数应在实测后确定预算。[Three.js 响应式与分辨率](https://threejs.org/manual/pages/responsive.html)

**当前状态：** 本项目尚无可玩游戏和设备性能验收。首轮已确定10单位、当前开发电脑目标60 FPS；浏览器、实际渲染GPU、显示及内部渲染分辨率等条件仍需记录，资源预算和达标结论须经实测。

## 七、场景移除与资源释放是两件事

从场景树移除对象不会自动释放全部 GPU 资源。应在生命周期结束时释放所拥有的几何体、材质和纹理，同时解绑输入事件、取消循环。共享资源由明确的共同拥有者释放，避免误销毁。[Three.js 官方资源清理](https://threejs.org/manual/pages/cleanup.html)

**验证方法：** 重复进入和退出同一场景，观察资源数量是否持续增长，并检查退出后的输入事件是否仍生效。一次加载成功不足以证明生命周期正确。


## 八、选择集合驱动场景与面板

**实际依据：** V01约139.2–139.6秒绿色矩形连续扩张，139.7秒显示RIFLE SQUAD ×2、两张队伍卡、10/10和成员选中环；约175.8秒还有22个对象（17小队、5载具）的混合选择汇总。

**反例：** 57秒附近白色矩形跟随墙体与机枪阵地面板切换，不是拖拽多选。仅看到矩形不能证明框选，必须追踪边界扩张和释放后的选择结果。

**迁移建议：** 在规则层保存唯一选择集合，单位使用稳定ID；HTML面板根据集合生成单对象属性或多对象卡片。共有命令按选中对象能力求交集；不兼容动作需要明确说明，不能静默只命令部分对象。UI点击应阻止向地面透传。

**验收实验：** 单选→拖选两组→混选不同能力对象→删除其中一个→再次下令，检查轮廓、数量、面板与实际接收者一致。鼠标键、修饰键和永久编组另行设计，不能当作原片已证。

## 九、移动命令需要表达位置与姿态

**实际依据：** V01 4–13秒、76.8秒及后续机动段同时显示本体选中环、连线和车形目的轮廓，目标朝向发生变化；载具面板可读idle/moving。11.8秒切换到另一辆同型号车，不能将本体位置变化误写成瞬移。

**迁移建议：** 命令数据包含对象ID、目的位置和可选朝向。预览对象独立于实际单位：移动指针只更新预览，确认后提交命令，取消只清除预览。连线表达关联时不要标成真实导航路径；有实际寻路结果后才展示路径。

**验收实验：** 预览时切换对象、拖过UI、取消、重复确认和目标不可达；检查不产生旧目标误提交。用小模型验证位置/朝向可读后，再决定拖动定向还是第二次点击等具体输入。

## 十、动作入口与流程完成分别记录

**实际依据：** GUNSHIP显示LAND与FIGHT HERE提示，兵营显示带数字动作格；原片没有完整落地加油，也没有“支付→排队→训练完成→新单位出现”。护甲绿条和燃料橙条已有清楚标签，不能混用为生命条。

**迁移建议：** 设计文档为每个动作分别记录“入口、合法条件、预览、提交、执行、完成、失败和取消”。只做出按钮不算功能完成，能力提示也不是系统验收。补给与训练应等待完整后勤资料或独立原型实测。

**验收实验：** 对每个计划动作写一条可观察结束条件；资源不足、对象失效、中途取消和完成后再次操作至少各检查一次。后续若确认后勤系统，应把消耗、运送、接收与状态恢复连成可追踪记录。

## 十一、范围能力要闭合延迟反馈

**实际依据：** 246秒“LONG TOM”203毫米火炮显示203 MM FIRE MISSION提示；253.6秒命令高亮，254.5秒双圆预览，之后出现炮位烟团、任务通知与9:55冷却，约265秒起目标区爆炸。这比“画面有爆炸”提供了更完整的命令执行证据。

**迁移建议：** 将“可用→瞄准预览→提交→等待执行→冷却→再次可用”建为明确状态；预览圈、通知、冷却计时和效果读取同一条命令记录。失去选择时仍可追踪已提交任务，不能让玩家以为任务消失。冷却按游戏时间基准计算，别用累计sleep计时。

**数值边界：** 原UI称10发、70米圆、10分钟重装填、惊动300米范围；本轮没有逐发测量、米制标定、AI惊动或完整冷却验证。“70米圆”不擅自解释半径或直径，两个圆也不擅自对应伤害/惊动范围。

**验收实验：** 提交后快速换选、重复点击、取消预览、暂停/切出再恢复。确认只生成一次任务，界面能解释等待时间，恢复后不会补发多次效果。游戏联网若进入范围，另定义权威时间，不在本次提前实现。

## 十二、破坏表现与规则变化分开验收

**实际依据：** 190.5秒有FIRE HERE指定位置射击提示；218至220秒城市建筑分块下落、烟尘扩散。楼体遮挡单位时可见白色车体轮廓。画面没有证明底层采用实时物理，亦未证明碰撞或道路导航更新。

**迁移建议：** 若玩法需要建筑破坏，先用预制碎片或动画验证反馈和遮挡可读性，再分别检查可通行区域、碰撞、拾取、残骸寿命和性能。单位选择标记应在烟尘与建筑遮挡下仍可辨认，避免只追求爆炸规模。

**验收实验：** 同一区域连续触发破坏，观察选中对象可读性、帧时间峰值、碎片回收和命令落点。只有视觉碎裂通过时，不能声称物理与寻路通过。

## 十三、公开资料获取与工具故障可恢复

普通页面请求返回412不代表没有公开播放入口。本轮使用标准User-Agent与来源Referer，公开view/playurl正常返回非预览全长720P，无账号或Cookie；YouTube要求登录时停止媒体获取，只保存其公开元数据。脚本不得将临时签名媒体URL、Cookie、账号或完整素材写入交付报告。

计算机工具初始化的kernel assets路径错误未能修复，因此本轮新增页面没有浏览器增量复测。静态链接、证据台账、图片与语法检查和旧版浏览器验收分别记录，避免把工具执行成功、解码完整和用户体验通过混在一起。

视频时码显示先取整到最小显示单位，再通过整除与取余分解分钟/秒。直接对浮点秒数分别格式化会把59.99999显示成60.00，导致`01:60.00`等错误；显示格式化不能反过来改动真实帧时间或用于累计计时。

## 音效预设与事件渲染分别验证

**适用场景：** Unity游戏的FMOD bank、共享武器音效和离线配套目录。

先区分元数据加载与样本加载。RIFF/FEV没有明文FSB5标记不足以单独证明封装性质；本轮随附运行库能读取事件，但A-10样本在缺少源设置时加载失败。沿实际FMODStudioSettings序列化字段逐项对齐验证，应用源设置后加载与渲染成功；不能猜键值或反复换工具替代证据。

预设名称不是事件身份。通过Addressables正式位置和对象指针追到字段，再用运行库GUID证明事件。缺项先执行原生路径查询：本轮恢复了大小写别名，Kiowa旋翼实际在Dialog.bank。bank文件名不能决定其中声音语义；确认目标后只处理该事件，不把整库语音扩展进范围。

有限事件渲染须保留位置、参数、持续时间与停止规则，不能称为raw_sample或无缝循环。随附WAV writer对中文绝对路径报错，改用经批次边界核验的工作目录和相对文件名；该版本RIFF长度还少4字节，须核对完整data块，保留原件后仅重封装，PCM字节不变。帧数检查能发现播放器可能忽略的容器截断。

页面逻辑、浏览器媒体状态、听感和原游戏一致性是独立阶段。安全策略拒绝file协议时记录限制，不经其他表面绕过；最小DOM替身可执行真实脚本验证筛选与事件处理，但不能证明布局、原生音频解码或实际听审。入口见 [音效提取说明](../../scripts/断箭/音效提取说明.md) 和 [音效提取报告](../../reports/断箭/音效提取报告.md)。

## 音效缺项先核对字段选择分支

**适用场景：** 同时存在武器Impact与弹药Impact，但部分事件路径无法索引。

弹药字段存在不足以证明武器字段已废弃。本轮从IL2CPP类型布局、HitComponent构造器、泛型元数据和ExplosionEventSystem.Update机器码确认：弹药预设对象存在时优先使用弹药字段，缺失时才回退武器Impact；字段空字符串只跳过声音，不触发这个回退。当前配置正常声音可定位和旧回退事件仍缺失可以同时成立，应分开保存，不改写原路径冒充别名。

元数据版本由文件头读取；Unity版本相近不保证旧分析器支持。官方Cpp2IL预发布21实际解析版本39，工具附件校验与当前构建解析分别记录。原生方法可能被拆成多个PE异常目录片段；须按Microsoft的UNW_FLAG_CHAININFO说明回溯来源，才能从函数入口追踪寄存器和对象。只扫描E8/E9字节不能算调用证据，须验证指令边界；共享地址与未知调用者不能强行命名。

分类至少保留原始映射状态、正常分支覆盖、回退状态、运行观测状态及音频来源。所有已有关联WAV均可复用时，新导出数应为0；新增证据不能使旧库的文件身份变化。完整案例见 [命中音效复核报告](../../reports/断箭/命中音效复核报告.md)。

## 旧交付库清理前核查元数据依赖

后续批次可能仍引用前批次交付库中的映射与输出指纹。删除冗余库前先搜索实际读取路径；只迁出被引用的小元数据，以原字节、SHA-256和修改时间核对，并显式记录原路径到保留路径的关系。保留原输入清单，不通过重新计算输入基线掩盖删除。核验程序区分“前库仍存在且不变”与“按冻结清单退役且保留核验依据”。当前库级验收与逐事件听审、循环接缝及运行时集成分别登记。

## 研究音效映射转换为网页索引

事件身份、渲染配置与文件摘要分别保存；模型和选用配置共同确定绑定，不能仅按型号或文件名关联。Unity对象ID超出JavaScript安全整数范围时输出十进制字符串。空字段与对象缺失是不同状态，回退规则按当前静态代码证据保留，索引转换不能把缺项“修成通过”。

按需解码需同时约束在途请求、缓存和声音实例。停止或切换时递增代次，加载完成后核对代次，避免声音迟到播放；旧请求也不能在清空后重新填回缓存。共享解码缓冲区，独立管理每次播放节点，失败可重试。

静态模型没有统一可证炮口节点时使用明确标注的可调示意点。车体与炮口跟随载具，命中声音固定于触发时的世界位置。Web Audio替身加真实Three.js音频类可验证接口、挂载和生命周期，但不能代替WebGL、浏览器解码或听审。


## 并行音频整理先固定共享事件所有权

**适用场景：** 多个工作对话围绕同一模型库复核声音引用和分类素材。

型号集合互斥不能保证声音任务互斥。先以事件GUID加渲染配置形成任务身份，再由全部使用引用确定空中、地面或共享所有者；同一声音的多种用途保留在清单中，物理WAV按完整SHA-256只保存一次。每个分片只写自己的证据和回执，总清单由协调者合并，避免公共JSON及分类文件互相覆盖。

当前渲染函数会改变进程工作目录。同进程多线程调用会争抢相对输出路径；如需要并发渲染，采用独立子进程、独立尝试目录和有限并发。独占执行锁防止同一分片重复运行，所有工作对话结束写入后再冻结输出。

复用、重新渲染验证、新增确证事件分别计数。首测通过只证明当前提取工具能处理该事件，不能把复制已有WAV算成新增提取，也不能把正常弹药命中声音冒充未解析武器回退路径的恢复。输入、原模型、正式音效库和输出分别保存摘要，技术解码与听审继续分别登记。具体边界见 [分类实施计划](../音效与渲染/载具音频提取与分类-实施计划.md) 和 [音效模块说明](../../scripts/断箭/音效提取说明.md)。


## 全bank枚举应保存完整事件身份

只保存各bank数量和某路径的失败查询，后续无法独立检查完整枚举结果。本轮006在读取所有bank元数据时保存完整路径、GUID、参数与逐bank状态，事件记录数量和唯一GUID数量分别统计；strings定义也要与实际已加载事件交叉核对，不能因每个bank成功加载就假设所有strings事件均可用。

失败路径必须区分“有真实事件但样本渲染失败”与“尚无真实GUID”。当前7条路径属于后者；更换渲染器或重复复制已有WAV不会修复事件身份。完整表中没有精确或大小写匹配时，相似名称只可作为研究线索，不能直接用于映射验收。复核任务通过与缺项恢复分别报告，案例见 [剩余音效恢复报告](../../reports/断箭/剩余音效恢复报告.md)。

## 静音事件先核对真实可写参数

事件GUID、样本加载和WAV容器均正常，仍可能因控制参数默认值为0而静音。先保存首次回执，再核对参数类型、可写标志和真实范围；只做有依据的有限激活尝试，保持源默认值不变，将试用值单独记入渲染配置。007批次通过Hydraulic参数一次中点激活恢复9个机械事件，另有3项仍静音，不能把重试完成写成全部声音成功。

同一GUID不同参数可能产生不同声音，任务身份、渲染配置和物理WAV摘要应分别保留。有效样本不等于原游戏状态或所有参数层已覆盖；特殊用途的名称线索单列候选，不直接生成型号匹配。案例见[音效浏览库扩充报告](../../reports/断箭/音效浏览库扩充报告.md)。

## 分类视图分别记录声音范围与模型范围

从声音目录派生模型视图时，事件GUID、文件摘要、原渲染参数及技术状态保持来源原值，关联证据另行增加。逐引用数量与去重后的模型事件对数量不同：本轮884条有效引用形成741个模型事件对，仍只关联101个声音事件。空字段、未索引路径和无单位关联入口继续保留。

直接复制目录对象容易继承旧的范围说明。派生目录应分别保存当前scope、source_scope和model_scope，明确“全部阵营声音素材”与“当前美军模型关联”的不同覆盖范围。修正影响冻结工具时建立新批次，保存首版工具和修订原因，不改旧输入基线。相对引用节省声音副本，也必须在README说明相邻批次依赖。案例见[模型音效分类视图报告](../../reports/断箭/模型音效分类视图报告.md)。

## 本机模型音频整合

- 正式索引依赖结构化来源和已登记媒体，不从旧HTML反向解析；清理旧页面前先保证新入口不依赖它，并保留历史冻结清单及独立退役回执。

- 音频技术检查应核对头部帧数与实际样本数，区分静音、削波、播放解码、人工听审和无缝循环。正式登记不能抹掉已有待复核状态。

## 正式媒体分类与并行任务保护

- 物理目录规范化采用复制、逐文件SHA256核对、发布新路径版本的顺序；URL由内容摘要标识，改存放位置不改变网页地址或稳定ID。旧快照不回写，原文件在依赖清退前保留。
- 其他任务可能在派生清单中保存媒体绝对路径，仅更新正式库索引不足以证明可以删除原件。只读检查当前依赖并保持原位置，其他对话的写入单独报告，不能恢复或覆盖成自己的基线。

## 战术镜头的平滑与输入验证

- 镜头使用真实帧时间，速度采用一阶响应的解析积分；只对速度做逐帧插值再积分位置，仍可能让不同刷新率的启动距离不同。平移输入先归一化，避免斜向快于单轴；松键使用更短时间常数，避免拖沓。当前控制器在30／60／144时间步长下的位移差小于0.0001米，数值检查不等于对应刷新率硬件验收。
- 鼠标缩放保存未截断的地面射线交点，更新投影后补偿镜头中心。若误用游戏命令的边界截断坐标，鼠标在场外时会出现锚点跳变；镜头边界仍需优先限制，并明确边界处无法无限补偿。连续滚轮累积到目标跨度，避免每次从过渡中的当前值重新计算。
- 指北针按世界北向在相机坐标中的投影计算，直接套用正负偏航角会遗漏俯角导致的投影变化。聚焦以选中位置的一次快照为目标，并按高度处理空中单位；选择、命令、聚焦与持续跟随分别定义，避免无意抢镜头。
- 失焦同时清按键、拖动、速度、锚点及未完成镜头目标，暂停时则让镜头独立运行。真实键鼠验证覆盖UI动作，注入失焦事件验证清理回调，控制器时间步长单列；短时无窗口帧时间、长期可见窗口表现和主观手感分别记录。案例见[镜头交互优化验证](../../reports/载具靶场/镜头交互优化验证.md)。

## 城市与固定翼原型的实现经验

1. **地图扩展先统一边界。** 地面范围、导航网格、镜头、小地图和命令落点共同读取地图配置。地面障碍用空间网格，单位避让查邻域，A星用二叉堆与可走区域缓存，限制每步寻路请求。空中机动缓冲与地面可达范围分开，不能只放大地面平面。
2. **固定翼需要自己的任务生命周期。** 持续前进、有限转向、进场、扫射或投弹、脱离、盘旋与取消明确分开。初版把引导目标固定在航线起点前方，导致横向误差迟迟未收敛、投弹过晚；改为沿当前位置的航线进度加前瞻，并增加对准距离。普通炸弹用真实释放点、高度、速度和朝向预测落点，离机后继承速度受重力，不以制导掩盖偏差。对多个航向检查，不能只测顺风直线。
3. **实例化要保留部件和镜像语义。** 先按炮塔、炮管、旋翼等分组，再按材质合并。原挂载有镜像节点时，烘焙后同步反转三角形绕序，保持实例矩阵正尺度。实例化降低绘制调用，不等于降低三角形；未做逐实例剔除时，必须说明场外实例仍提交顶点。卡片和标签分页不应删除模拟对象。
4. **音量、距离和并发一起校准。** 35%到70%只是增益约6.02dB；监听点挂高空相机会令声音随观察高度错误变小。战术中心监听、近处引擎优先、事件距离与总声部上限独立控制。密集齐射发现压缩器的启动阶段仍放过峰值，补末端逐声道软限幅；分析窗抽样不冒充完整逐样本或人工听审。短音效锚点用独立键，引擎使用稳定键，避免同单位多次射击移除仍在播放的锚点。
5. **性能样本先证明负载持续。** 静态、移动、恢复靶交战分开；摧毁后恢复，记录时间线首尾发射与命中增量。区分场内、入画中心、模拟、移动和发声数，标记CPU统计只含规则推进。浏览器控制台作为关口：路径第二段缺少高度曾产生NaN几何，规则测试没有发现，真实输入回归才捕获。预热和采样用单调时间戳，后台或配置变化中止；源码冻结、完整段分位、滚动时间线、无窗口与可见窗口分别说明。

可复用入口见[城市固定翼靶场模块](../../src/载具靶场/README.md)，阶段数据和测试边界见[可视化报告](../../reports/载具靶场/城市固定翼与性能验证.html)。

音频排障补充：Three.js 0.187.0的`AudioListener.getInput()`返回主增益节点，`setFilter()`把滤镜接在增益之后。误按相反方向回接会形成反馈且没有正常设备输出，声音实例的`isPlaying`仍可能为真。最终使用明确的增益→压缩→软限幅→设备链路，并用同一个`createMix`函数在双声道OfflineAudioContext中检查输出非零、低电平约6.02dB增益和强输入峰值上限。接线修订前性能记录单列排障证据，不进入最终报告。拖线取消还应覆盖“鼠标未松开时按Esc”，以及从压力模式切地图后恢复默认靶场，不能只测静止状态按键。

实例拾取补充：更新`instanceMatrix`后，射线检测的实例包围球也可能过期；关闭显示剔除不会自动解决拾取范围。点击时让代理重算包围球，并真实移动到旧范围外再点选验证。声音锚点同样需要生命周期检查：短事件使用独立键，引擎使用稳定键，但替换稳定键前应移除旧节点；以登记数量对照场景实际节点数量，避免Map被覆盖后失去清理引用。

## 载具持续机械声补全

1. **移动事件不等于移动时才发声。** 三型源数据均把机械运行声放在MoveEvent，但坦克待机、直升机悬停、飞机盘旋仍需持续音源。将“是否有机械底声”和“当前运动状态”分开；状态只平滑改变增益与播放速率，避免停车直接静音。查不到专用发电机或履带事件时明确用现有引擎表现，不造确证关联。
2. **有限渲染先检查静音尾部，再循环。** 这三份10.24秒素材末尾约两秒静音，按完整时长重播必然断声。以1至7.5秒稳定段派生单声道，120毫秒平滑交叉淡化，得到6.38秒周期；原素材和原摘要只读。RMS归一、峰值上限、跨多周期窗口和接缝差分共同检查，不能把数值接缝通过称为主观无缝听审。
3. **持续声与事件声分配独立预算。** 八路机械声单独保留，四十路发射／命中共享旧运行时，避免齐射挤掉全部引擎。先保留各型号代表，再按选中、距离与已有声源排序；退场淡出仍占八路预算，释放后才补位。重复型号分散相位并按数量平方根衰减，避免同一波形完全同相叠加。
4. **空间感依赖监听位置、范围与声源尺度。** 战术中心监听保留，坦克、旋翼和固定翼设置不同参考距离；远处额外淡出。不能给选中单位全图恒定响度，否则选择会改变虚拟距离。镜头聚焦帮助定位声音，普通选择不移动镜头；该约定保持已有镜头验收结果。
5. **证明实际声音与证明播放状态分开。** 双浏览器真实键鼠改变状态，再从实际素材空间声源增益节点抽样14秒，覆盖两个循环；另在混音末端测零音量。暂停、关闭、切地图、重置检查声部与锚点释放。总声部必须汇总适配层与共享运行时，单看共享运行时的voices会漏算八路持续声。性能测量使用本轮独立回执与源码身份，不覆盖旧版通过记录。

实现入口见[声音模块](../../src/载具靶场/声音.mjs)，资源准备和测试见[模块说明](../../src/载具靶场/README.md)，核验与缺项见[音效补全报告](../../reports/载具靶场/载具音效补全验证.html)。

## 网页音频响度标定

1. **“有声音”与“够响”分别验收。** 真实素材循环连续、声音状态正确、峰值接近0.95都不能证明平均响度适合试玩。用户确认100%和近处仍偏小后，应使用相同音量、相同素材与位置，测改前和改后的RMS及峰值；不能只提高滑杆默认值并宣称解决。
2. **原生压缩器含自动补偿。** 先前“没有补偿增益”的判断不准确：旧链没有额外可调补偿节点，`DynamicsCompressorNode`内部仍有由阈值、比例与拐点决定的自动补偿。直接改阈值再叠加输出增益，会使档位实际值偏离预期。依据见[Web Audio处理规范](https://www.w3.org/TR/webaudio-1.0/#computing-the-makeup-gain)，浏览器实现差异仍应以实测为准。
3. **把增强分配在压缩前后。** 初次直接后置方案的12dB密集混音约28.8%样本接近限幅上沿，不作为交付。修订为固定原阈值−8dB，6dB档前3后3、12dB档前9后3，保持低电平6／12dB提升；强音平均提升会较小。保留原始0dB，验证它与改前混音等价，给用户可直接比较的基线。
4. **限幅比例不是失真率。** 用实际八路机械声加四十路事件的集中重叠，统计绝对值不小于0.94的样本占比、峰值与非有限值，识别是否过多贴近上沿；不能用“峰值没过1”证明音色无失真。自动技术输出、独立无窗口性能与实际设备听感保持不同验收边界。
5. **增益自动化也要验证生命周期。** 两处增益35毫秒时间常数平滑切换，保持已有声源身份；12dB档仍必须零音量真正静音，暂停、关闭和重置正确释放。新档位记入性能元数据，变化时中止采样，避免把一段混合响度数据当作单一档位结论。

复用入口：[响度模块约定](../../src/载具靶场/README.md)、[验证脚本](../../scripts/验证靶场响度.py)和[可视化报告](../../reports/载具靶场/靶场响度增强验证.html)。

## 整库网页资源流水线

1. 全量先按路径冻结，再按内容摘要去重，保留正式ID与全部来源别名。历史候选、工程源件、网页派生和质量状态分开，编码成功不升级原有缺陷。
2. 机械节点与骨骼模型不能统一合并减面。基础层保留浮点几何；静态细节层带误差及边界约束，骨骼角色保留拓扑。Meshopt三角形编码可能循环排列每个三角形的三个索引，比较应保留绕序并按语义归一；节点默认值写回有微小浮点差，必须设明确容差而非静默忽略。
3. 文件压缩、显存和帧率分开。KTX2提供GPU压缩与Mip链，Meshopt主要减少传输；几何面数与动画CPU仍需单独预算。低分辨率画面不会自动减少高模的顶点处理。
4. 音频编码可能新增峰值。全库解码比较发现部分Opus瞬态越过0dBFS；回退无损FLAC比随意降低全库响度更可控。压缩传输不降低AudioBuffer浮点缓存，原始静音和循环语义仍需单独保留。
5. 冷归档按摘要存对象、映射保留旧路径，逐条解压核对；恢复器拒绝覆盖不同内容。原件未获删除批准前磁盘占用必然增加，不把预计释放写成实际释放。共享加载工厂及只读运行清单避免改动固定源库版本，WASM和Worker必须同步补齐白名单与CSP。

## 像素战术视角的低成本阴影

该节记录第一轮简化底影。实体轮廓、建筑遮光和自阴影的当前方案见后续“局部实时阴影的预算与验收”，两阶段分别保留。

1. **先查材质，再决定补什么。** 三型载具主要材质已有AO和法线贴图。车底实心椭圆的问题应先调整覆盖范围、透明度分布与朝向，重复烘焙AO容易让模型更黑。低分辨率不免除实时阴影的额外渲染成本。
2. **以替换维持预算。** 现有假阴影可用双圈顶点透明度替换硬边，三角形不增加；俯视镜头可用单面透明材质，减少双面透明的额外绘制。逐实例浓淡独立于共享材质；高度不变时无需重复上传，重置时释放自有几何。资源对象略增与运行时绘制减少分别记录。
3. **统一世界日照与局部朝向。** 平面旋转到地面后，局部二维转角的符号需要通过车身世界轴核对。不能只测0和90度的绝对值，还应测斜向、轴的正负和真实移动。太阳方向不随镜头旋转；飞行载具按高度偏移并淡化，不能用贴地圆影代替全部高度信息。道路上方也需要验证深度顺序。
4. **相同FPS不能证明相同GPU成本。** 相机、单位、交战持续性、声音、画质与运行资源身份共同冻结。刷新率限制下应查看异步GPU计时及渲染提交CPU；遇到分位异常，保留原样本并反序复测，不挑选较好数据替换首测，也不把一次异常直接归因于改动。
5. **清单与路由按服务实例冻结。** 多端口验证写同一个导出JSON会让旧服务的媒体路由失配，文件被清理还会令清单404。服务响应应读取内存快照，磁盘JSON仅作导出；测试可将本实例文件映射指向不存在的路径，验证GET、HEAD和媒体仍可用，无需删除真实共享文件。隔离服务用系统分配端口，避免与其他验证端口冲突。

实现与实测入口：[靶场模块](../../src/载具靶场/README.md)、[阴影对照](../../reports/载具靶场/阴影优化验证.md)和[验证脚本](../../scripts/验证靶场阴影.py)。

## 局部实时阴影的预算与验收

1. **明确底影的能力边界。** 渐变底影能表现接地感，无法提供炮管、机翼、建筑挡光及自阴影。需要这些效果时采用受控的真实投影，先承认额外几何通道成本，再测整帧和GPU；低分辨率仅减少部分像素成本。
2. **按固定引擎版本核对阴影层。** 本地Three.js 0.187.0支持独立阴影相机层。显示批只在主相机层，投影批共享真实部件几何，只在阴影层；不必向主通道额外画透明模型。升级引擎必须回归此行为，不能仅靠对象标记推断生效。
3. **拟合影区与筛选实例同时做。** 缩小阴影相机不会自动减少禁用批次视锥剔除的全部实例提交。地面接收区域、建筑余量和可见空中接收者共同拟合；灯光视锥筛选包含画外可能投影的单位，将入选实例压紧到独立批。显示实例仍全量提交，统计需分别说明。
4. **用同一矩阵维护部件投影。** 炮塔、炮管、旋翼和飞机侧倾复用显示矩阵；太阳方向固定，影区对齐纹素。重置仅释放自有实例数据，不销毁共享模型几何。真实阴影与简化底影权重互补，远景停止更新地图并保留纹理，避免缩放时重新编译和分配。
5. **验收必须看到影子。** 近景真实轮廓、建筑有无遮挡对照、自阴影、画外投影者、部件矩阵、真实键鼠和连续重置分别取证。性能相机放在实际交战前线，确认实时权重为1、投影实例大于0；全场总览已降级，不能用它验证近景实时预算。源文件、HTTP提供内容、清单和加载器按摘要核对，防并行任务混合版本。

当前实现见[靶场模块](../../src/载具靶场/README.md)，可重复验证见[实时阴影脚本](../../scripts/验证靶场实时阴影.py)。

并行会话核验补充：仅在采样开始时记录源码摘要仍不够，文件可能在第一个和第二个浏览器之间改变。应冻结HTTP实际提供的源码与清单，并保存路由到快照摘要的映射；已有混合版本数据降为排障记录。资源清理保护范围不能只检查当前靶场，还需读取独立音效实验、正式版本和并行原型任务的路由清单。


## 战术视角游戏资源预算

1. 先测字节组成。三款现用载具的上一轮压缩GLB有87%至92%来自贴图，继续只减面不能充分改善下载。按640／480宽、最近允许镜头分配贴图，主体256、512回退；小遮蔽贴图保留层次。

4. 网络冷缓存、进程冷启动与公网分开。新浏览器上下文禁用HTTP缓存，明确CDP模拟限速、延迟和首次可操作定义；引擎与解码器计入，用户点击后才解锁的音效另标排除。系统文件缓存、浏览器编译缓存及CDN部署不应由本地结果推断。

## 自动退役与存量边界

- 根指令更新不能保证正在运行的会话立即重读。新轮次和续接时重读规则，另建独立任务，交付核对产物及登记；`status`成功或条目数为零不能证明没有漏登记。具体新版确认后由负责会话完成验收登记，不能把候选清单或口头确认当成已接入自动退役。
- 全局启用自动维护不能等同于批准全部旧存量。冻结启用边界；新增缓存绑定新任务和准确文件快照，历史退役绑定工程师具体新版验收及对应旧文件集合，旧登记和旧回收回执不接管。
- 缓存修改时间不能代表最后使用时间。任务登记是首要保护，任务明确结束后，取修改、登记、结束时间的最晚值计算闲置期；不依赖可能未更新的文件系统访问时间。
- 连续新版验收须维护后继关系。清除旧版时验证当前已确认后继与原验收凭证，避免为核验中间版而永久保留全部大文件。
- 回收只改变位置，不释放磁盘；满七天复核后逐文件删除才释放空间。容量警戒线不能覆盖期限，恢复后的条目应暂停自动退役，避免刚恢复又被回收。
- 任务和服务负责实际引用迁移与依赖记录。Windows占用查询只能作为附加检查，不能替代任务登记和模块验收；异常或中断保留回执，不自行扩大范围重试。
- 清理后的报告仍需保留原批准范围。报告生成器读取清单摘要及独立执行回执，核对逐文件清除集合后展示实际结果；不能扫描已清空目录重新生成零候选，覆盖原批准清单或误写为尚未执行。历史回执里的旧路径保留追溯，活动入口单独核对当前优化资源。

## Airbase地图来源与运行派生

后续全图与双层入库的目标和关口见[实施计划](../Airbase全图与场景资产双层入库-实施计划.md)。本轮只读盘点确认：地图设置标称9×9公里；010批次来源表有119组建筑／装饰Bank及112437个放置条目，仍需按范围、启用与实际渲染来源筛选，也不代表植被等来源已经齐备。2公里的34原型和162实例只描述局部。先冻结统计口径与范围，再判断“完整提取”；本文不把新计划的性能预算记作实测成绩。

1. **设置包不能代替真实场景。** 当前构建的BuildSettings序号7关联Airbase，实际外部对象是sharedassets7；建筑由ResourceManager正式路径、SceneCompressorBank十浮点TRS及Addressables精确键恢复。任务节点不代表建筑摆放，禁用TerrainData不能代替实际显示的高细节地表网格。
2. **地表插值必须保留作者UV。** 半精度UV存在量化偏差，世界位置仿射拟合会抹掉真实纹理频率。使用实际三角形重心插值，再按三张RGBA权重和12层源底色派生；材质近似与原游戏画面等价分开声明。
3. **高度、相机与多网格都有失败边界。** 非零BVH容差可让近共面细三角形出现超出源包围盒的假命中；用有限射线、零容差、源范围检查和GLB独立抽样。2公里相机需同步远裁剪面。一个作者实例可含多个网格，不能按实例数要求网格数相等。
4. **文件共享不等于浏览器共享。** KTX2外置后若关闭下载缓存，多个GLB仍会反复下载和转码。同内容图像需同时复用文件请求、转码任务与GPU纹理对象；几何块回收时不能销毁其他块共用的纹理。258像素分块贴图在本机BC3路径出现黑块，向上采样到二次幂后实际看图确认修复，原像素内容和UV保留。
5. **通行、测试夹具与性能分别排错。** 角落高台在既定坡度和余量下不通主区域，应保留不可达输入、细化网格并另加可达长路线，不能随意降低坡度标准。测试直接改变模拟单位而不更新界面会中断帧循环；应走现有重置入口。首个动画时间戳可能略早于启动时间，绝对时间差需截断到零。Meshopt循环变换三角形起点应按绕序等价核对，不能把合法编码误判为拓扑变化。
6. **作者实例与原型内部变换分别核对。** 全部作者放置矩阵为正不代表原型子节点没有镜像。当前谷仓包含负尺度节点，运行实例批需将该节点变换烘焙到克隆几何并校正绕序；同时检查最终实例矩阵和实际画面，不能只查来源矩阵或渲染错误日志。
7. **远景冠层不是行走地面。** 本轮ForestConstrainV2的森林壳高于实际地面约25米。将它纳入地面选择曾造成10298个抽样点虚假抬高；单列森林视觉角色后，全5184块46656个点对独立源BVH的P95误差约0.00011444米、最大约0.00022563米。仍须追加道路特征、多层与运行核验，不能用常规抽样替代全部关口。
8. **草丛序列化方向用不对称数据证明。** 只守恒总数不能确认补丁次序、图层次序或格内转置。本轮用隔离Unity6000.4.9不对称6层夹具独立保存，再经UnityPy回读；补丁和格内均为z行x列，完整输入高度和密度回写逐值相同。来源头为6000.3.24，工具派生版本不同，不能宣布原游戏逐株一致；工程师后来允许省略运行草丛，保留已完成来源证据即可。
9. **完整矩阵实例需要保留无摆放的原型引用。** Blender5.2.3的FLOAT4X4点属性与SetInstanceTransform可保留镜像、非均匀缩放及剪切；本轮436242个点独立回读矩阵误差0。没有当前摆放的草丛原型节点组首次保存被清理，设置节点组fake user后133种链接全部保留。此结论限于本轮实际节点与新进程求值，不能据此跳过渲染和网页验证。
10. **预算统计要区分视图和底层缓冲。** 多个primitive可持有同一ArrayBuffer的不同视图。CPU对底层ArrayBuffer去重；GPU对实际BufferAttribute或InterleavedBuffer对象及其上传视图长度计数。逐geometry累加完整buffer会误报远景超预算。本轮3组共享、子视图和交错属性夹具验证后，在Chrome、Edge静态显示中复核；不等于驱动显存实测。
11. **浏览器验证必须等待目标视区。** 镜头设置后只检查旧的pending=0，可能采到上一视区。设置镜头应同步触发区域请求并返回本次完成Promise，取渲染统计前再等渲染帧。本轮旧快速切换记录保留为验证器缺陷证据，修复后的具体修订重新跑双浏览器，不继承旧视点统计。

12. **原生LOD名称不等于网页性能。** 本轮最密植被区的LOD1仍提交约4184万面，正式样本P95约69毫秒。再查原LODGroup发现第三档使用BaseAlpha／NormalDepth和专用替身Shader；不能把5至8个三角形的源网格当普通白片。原图集可作为网页实例化替身来源，但帧方向、图集纵轴、颜色和近景切换必须实际对照，短样本不能升级180秒或完整验收。
13. **异步重置必须同步更新可被帧循环读取的界面。** 等待区域就绪期间模拟对象已更换，而旧单位卡片仍被updateUI读取，会让帧循环抛错停止。配置负载时在第一个异步等待前同步重建卡片。外部采样器对完成／运行状态一次读取，避免两个读取之间恰好完成而误报中止。

14. **原Shader参数与GLB局部坐标不能混用。** 原生植被替身偏移和图集方向来自Unity，本轮原型GLB已转为(x,y,-z)。真实GLB的POSITION范围与源LOD1范围逐轴核对可直接证明Z翻转；原偏移及取帧视向都需转换，作者实例矩阵与源参数继续保留。只看森林整片截图会漏掉一两米的树冠偏移，须用源LOD1及单体五方向对照。

15. **材料为空不等于源背景为白色。** EZTerrainSimple的三张RGBA权重由renderer577的控制器容器注入，原材质Splat指针为0。复用该容器、BigFactor及12层图像，以实际三角形UV派生背景底色；母版独立回读确认打包图像摘要及世界UV，网页避免重复绘制同源背景。
16. **引用释放也要回收元数据。** 1200次临时引用已无owner，却残留1200项操作和代次表；要等全部异步准备结束后一起回收，再验证旧取消信号不会影响复用名称。目标命令必须持有自己的精细数据，不能只让单位附近网格完成就认为远处目标已验证；准备失败应显式等待，并为单位与寻路保留预算余量。

17. **流式提交不能先清当前视口。** 每16米重取前先移除细节会反复闪到总览；旧地表仍覆盖视口时保留，新几何、材质及植被准备齐全后同步提交，再释放旧引用。过渡资源必须计入原49块及内存预算，连续键鼠逐帧与跨层回访分别核验。
18. **无贴图材质也可能引起旧纹理上传。** 本轮回访纹理每圈增长2项，真实WebGL追踪到阴影材质uniform残留；按源材质持有并释放customDepthMaterial后，重新执行双浏览器五圈180秒，而非仅看JS堆或短探测。结束位置需强制同一精确视区，等待请求与转码为0并采用相同GC条件。
19. **替换背景必须对账组合内的水面。** r13换底色背景时漏掉两处原水面，物理阻挡仍过，不能据此宣布完整显示。将水面独立为强制清单项，对全部属性、绕序、世界矩阵和材质严格回读，再在池塘近景比较可见射线与物理水位；prune须显式保留未使用UV。水层按视区加载，验收不要求机场预载远处水面。
20. **总音量要在响度处理后衰减。** 压缩或补偿会抵消前置25%增益；将主音量放在压缩和限幅之后，同时覆盖机械与瞬态声，分析器读最终输出。本轮保留+6dB与相同声部负载，再重跑完整负载矩阵，不能把声音关闭后的成绩继承为有声通过。
21. **温缓存只允许不可变资源URL。** 固定Three.js及解码器采用完整元数据SHA命名空间并逐文件核对，模块相对导入与Basis路径保持同版本；业务代码仍no-store。不把可变vendor别名设为immutable来达到温启动预算。
22. **库增量必须迁移严格绑定指针的消费者。** 原模型字节未变，十三款交付仍会因库指针变化拒绝重启。共享锁内先发布场景、再重绑双档交付身份，保留原指针及原交付；验证失败或进程中断可按确切摘要恢复，后续指针必须阻止过期回滚。既有服务不因发布被停止。
23. **中断事实与原因分开。** 页面全局消失不等于用户刷新；分别留导航reason、文档timeOrigin／wasDiscarded、关闭、崩溃及失败截图。原因未定即如实保留，后续完整重跑通过也不抹去原失败。JSON在浏览器往返把1.0转成1，登记一致性应在原始HTTP JSON侧比较，避免制造假媒体差异。

## 原作人形动画与Blender骨架回读

1. **人形肌肉曲线不能当作普通骨旋转。** 源动画的Animator绑定承载Humanoid参数，必须结合实际Avatar求解。本轮用隔离Unity项目读取原始包与原Avatar，以Playables采样局部TRS，并用原生BakeMesh输出参考顶点；Blender全帧骨矩阵与关键姿态顶点分别比较。原包和本机引擎版本不同仍须保留实机对照未验证的边界。
2. **先设EditBone长度，再设矩阵。** 新骨长度为零时先赋矩阵会丢失有效骨轴方向，即使通过补偿让动作矩阵看似正确，蒙皮仍可能明显错误。本轮先检查绑定矩阵，再核对原生变形后顶点，修订后最大误差约0.000001013米。
3. **源属性保留与着色表示分开验收。** Blender自定义着色法线存在存储量化，不能把生成成功说成源数据逐值无损。本轮把原始浮点法线和四分量切线保存在可编辑网格属性中，逐值回读，同时单列实际着色法线最大角度差。
4. **精确预制体定位不需要展开全库预载表。** UnityPy的Environment.container会展开依赖；已知SerializedFile时直接访问其container，保留对象身份验证，避免跨包扫描。原Animator可能位于包装根节点的子级，不能只查最外层。
5. **横躺姿态按相机投影取景。** 世界轴包围盒不足以保证人物完全入画；使用投影后的XY范围并居中，保存早期裁切图与修正凭证。
6. **预制体外层的统一倍率放到 Blender 展示根。** 先从骨骼静止和采样矩阵移除该倍率，再让骨架与网格共享带倍率的父级，保持原尺寸与蒙皮绑定。构建 26627577 的 Unity 6000.6.8f1 采样中，外层倍率仍体现在 `BakeMesh(mesh, false)` 顶点上。比较 Blender 网格局部坐标前应对齐该坐标基准，并用装甲丧尸等非单位倍率样本验证。

## 原作群尸LOD运行与压力对比

1. **先查看源LOD再重做低模。** 原作Walker和Runner已有330／447面LOD2，保留46节点骨架及9原生片段即可建立独立运行版；LOD0面数不能代表源包没有群体版本。原始工程、运行工程和各自验收身份分别保留。
2. **导出时间起点与辅助属性需要核对。** Blender帧1可能被编码成1／24秒起点，运行派生整体归零但不改变相对关键帧间隔；共享时间访问器只处理一次。留档浮点切线不等于材质顶点色，运行GLB只去除不需的辅助COLOR属性，源工程仍保留原数据。
3. **少量顶点不能代表完整误差。** 初轮48Hz在少量点中合格，扩展到每片段五时刻全部顶点后峰值约5.3毫米；96Hz修订降到约1.74毫米。提高姿态纹理密度不改原动画，修改参数后重新完成同源码六组180秒，不混用旧成绩。

## 战场通用物理声学传播与航空声学设计经验（V1–V3）

1. **单共享卷积 + 静态分桶与静态声像池是 WebAudio 大战场最优解。** 全场锁定唯一 `AudioContext` 与唯一 3.6s 时变低通 `ConvolverNode`，按 Near (`<260m`) / Mid (`260–680m`) / Far (`>680m`) 静态分桶并预建每桶 5 档静态 `StereoPannerNode`，普通瞬态事件严格 `1 BufferSource + 1 GainNode`（0 Filter / 0 Convolver / 0 Panner），使卷积与滤波开销恒定不随战斗规模膨胀，主线程 `< 0.3ms/帧`、音频线程 `< 8%` 单核。
2. **立体声像必须绑定相机右向量，并采用 RTS 虚拟监听点。** 直接用世界 X 轴做 Panning 在旋转视角后会左右反转；改用 `(worldPos - listenerPos) · camRight` 并随距离收窄声宽。俯视 RTS 镜头监听点沿视线向地面注视中心下沉 `35%`，兼顾拉高视角宏大感与常规战术视距清晰度。
3. **声速延迟与声压等级决定真实纵深。** 严禁为空战事件硬编码固定 `delayMs`（需要二级错峰时用 `delayOffsetMs` 叠加物理延迟）；`0–560m` 严格按 `340 m/s` 线性延迟，`heavy/massive` 超过 `560m` 对数缓增延展至 `2600ms`。按 `small / medium / heavy / massive` 四档声压平滑滚降归零，彻底消除 `2000m` 硬切断崖。
4. **重爆冲击靠干声次声锤 + 背景音闪避，不靠堆音量。** Sub-Punch（`62→38Hz`）直入干声母线避免被混响糊化；在引擎循环音上游插入单个 `engineDuckBus`，于重爆声波抵达监听点瞬间压低背景引擎 `-4 ~ -6dB` 后回弹，零削波显著放大空气超压重量感。
5. **高速飞行器与弹体需要连续动态调制。** 复用引擎既有 `playbackRate` 与 `filter` 实现固定翼多普勒与机头高频哨音/尾喷低频轰鸣前后指向性（0 新增节点）；坠机与重磅航弹呼啸（同屏 `≤ 4`）逐帧追踪位置、速度与多普勒并在触地声波抵达瞬间截断衔接重爆。

完整拓扑与性能约束见[战场物理声学传播设计经验与性能规范](../音效与渲染/战场物理声学传播设计经验与性能规范.md)，自动化门禁见[验证空战声学与火箭音效.py](../../scripts/程序化地图/验证空战声学与火箭音效.py)。
