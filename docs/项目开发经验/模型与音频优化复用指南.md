# 模型与音频优化复用指南

适用范围：本项目的Three.js桌面网页、俯视战术镜头、低分辨率三维画面及清晰UI。先按本页选择处理路线，再查[统一库说明](../资源与资料库/统一模型音频库使用说明.md)与[维护模块](../../scripts/资源库/README.md)。

本页沉淀已经验证的方法和失败原因；案例数字是首轮统一库索引3的验收快照，不随以后增量入库自动更新。13款丧尸独立角色及混合群体仍由[专项计划](../丧尸十三款拆分入库与混合群体-实施计划.md)执行，不能引用为已完成成绩。

## 一 先选处理路线

1. 明确最靠近的允许镜头、内部渲染尺寸、同屏数量、目标电脑及帧时间预算。普通电脑目标必须有真实目标设备结果；当前开发电脑成绩单独记录。
2. 读取当前索引和来源记录，按SHA256盘点唯一内容，分清原件、最新可编辑工程、运行规格、历史派生与临时恢复副本。
3. 在下表选路线，先跑通实际加载和动作闭环，再按同一规则处理整库；已经批准整库执行的范围不反复停在样板确认。

| 资源类型 | 优先处理 | 必须保留或单独验证 |
| --- | --- | --- |
| 静态载具与场景 | 按实际镜头缩贴图、简化材质，再做有误差约束的几何细节层 | 外轮廓、透明部件、UV与表面方向；场景建筑另查碰撞和通行 |
| 炮塔、炮管、旋翼等机械模型 | 按运动部件分别优化，按部件和材质组织批次 | 节点轴心、局部坐标、父子关系、挂点及程序动作 |
| 骨骼或形变角色 | 先拆出独立角色，保留实际加权骨及必要祖先，处理贴图与动画数据 | 绑定矩阵、权重、拓扑、动作目标、轮廓与循环；不套静态减面规则 |
| 开火、命中等事件声音 | 从保留原声编码，完整解码并比较时长、声道、RMS与峰值 | 瞬态、原混音关系和源质量标记；峰值异常素材单独回退 |
| 引擎、旋翼等持续声音 | 检查稳定段、静音尾部、循环接缝，再建立状态与声部预算 | 原事件与项目派生循环的身份分开，停下或悬停时仍可持续发声 |

## 二 模型优化的经验

### 先看体积组成和屏幕占用

上一轮三款靶场载具的保真压缩GLB中，贴图占约87%至92%。这类资源先缩贴图、简化材质，比继续只减面更能降低下载量；几何、绘制和动画成本仍需分别测量。

本项目已采用主体底色256默认、512回退，小遮蔽贴图按需保留；这由640／480宽像素战场及最近允许镜头验证得出，不是“网页模型必须256”的通用标准。新增模型有大字标识、复杂透明或更近镜头时重新做对照，不机械套参数。

### 材质、纹理和几何分别记录

- 纹理压缩与几何压缩分别使用现有KTX2、Meshopt加载链；检查颜色空间、透明、Mip链及实际浏览器转码。文件变小、GPU纹理内存降低、三角形减少是三种结果，不能合并成一个压缩率。
- 简化材质移除法线图，并用原金属度／粗糙度纹理相应通道均值与材质系数保留整体倾向；检查自阴影、细小轮廓及玻璃是否受影响。
- 512回退提高底色分辨率，不能恢复已经移除的法线或完整材质。完整材质需求应从保留原件重建到待入库并重新验证，不能假设退役保真派生仍在原路径可用。
- 静态细节层按误差、边界和轮廓控制，无法满足阈值时保留更多几何或复用基础层；目标比例不能替代外观合格。现有256远景层供显式选择，不能写成已经接入自动距离切层。
- 不同GLB规格仍可能各自嵌入相同贴图，不能据此声称完成外部共享纹理。运行实例是否共享几何和材质，另查实际对象引用与释放行为。

### 结构与动画需要独立验收

机械部件不能为了合批失去独立转动能力；镜像节点烘焙后还要核对三角形绕序和实例矩阵。Meshopt可能循环重排三角形索引，结构比较应保留绕序并按语义归一，浮点变换使用显式容差。

骨骼角色本来只有约800三角形时，独立骨架、动画更新和绘制调用常比进一步减面更值得先测。287骨骼的13款整包不能直接当成单只复制；按角色保留加权骨和必要祖先，不硬凑统一骨数。动作保真检查与新增自制循环分开，整体模型平移不能充当蒙皮顶点变化证据。

最新Blender主工程保留可编辑骨架、部件及动作，贴图应内嵌或有受保护的显式依赖。必须在全新进程独立重开工程并回读GLB；保存成功或导出成功不等于迁移后可编辑。

## 三 音频优化的经验

### 编码先保留原始混音关系

本项目事件声音采用Ogg容器中的Opus、约96kbps可变码率，保留源声道、时长与增益。部分有损编码会新增超过满刻度的解码峰值，这类素材使用无损FLAC保留源峰值与响度，不为维持统一扩展名而强行使用同一编码。

旧流水线的数值比较将源与派生统一解码为48kHz双声道浮点，检查有限值、时长差不超过25毫秒，非静音素材RMS差不超过1.5dB；这是当时的技术门槛，不是无损、音质或主观响度保证。声道是否保持还需核对真实编码与浏览器回读，不能从统一比较格式反推源声道。新素材应记录适用阈值，原有静音、削波或待听审状态不能因编码成功而升级。

### 循环和音量分别处理

三款机械事件原声末尾含静音，整段直接循环会断声。当前循环由稳定段派生，采用单声道、交叉淡化和RMS处理，并保留来源ID、源摘要及制作参数；这些步骤仅适用于确认的持续声，不统一剪掉所有音频尾部，也不把单声道规则套到音乐或环境立体声。

音量偏小时按“实际输出链→监听位置与距离→单类增益→并发混音”排查。战术监听点位于观察中心附近，挂在高空相机会导致近处也被额外衰减。`isPlaying`为真只证明播放状态，还要从真实素材混音末端确认非静音。

当前靶场默认100%主音量、6dB增强，低电平增益分为压缩前3dB和压缩后3dB；强音提升受压缩和软限幅影响。原生压缩器存在自动补偿，改阈值后再简单叠加增益会使档位偏离预期。用相同素材、位置和音量做0／6／12dB对照，保留零音量静音、切档平滑和重置检查。RMS不是LUFS，峰值不过1也不能证明无失真或听感合格。

### 压缩文件和解码内存分别预算

AudioBuffer中的浮点样本估算为：`时长秒 × 实际解码采样率 × 声道数 × 4字节`。例如10秒、48kHz、双声道约3.84MB，不能按Opus下载大小估计常驻内存。

按需加载、共享解码缓存、闲置释放与声部预算一起做。靶场目前是80MiB缓存、八路机械声与四十路事件声的项目配置，不是浏览器固定上限。退场淡出期间仍占预算；机械声和事件声的锚点生命周期分别检查，统计总声部时不能漏掉适配层独立持续声。密集齐射需检查输出和声音舍弃计数。

## 四 每轮按五步闭环

| 步骤 | 必须产出 | 进入下一步的依据 |
| --- | --- | --- |
| 1 盘点保护 | 稳定ID、来源、完整路径、SHA256、字节、质量状态、消费者与任务读写登记 | 当前依赖与其他任务保护明确，原件和最新工程可识别 |
| 2 按预算派生 | 原件只读；输出到独立批次或待入库；每项参数、源与输出身份齐全 | 文件存在且结构检查通过；不自动发布，不无意义重编码有损音频 |
| 3 同条件验证 | 模型结构、实际视角画面、机械／骨骼动作；音频完整解码、循环、混音与生命周期；浏览器证据 | 实际加载及功能通过，失败项保留或回退，人工待验状态明确 |
| 4 统一发布 | 保留原件与最新工程，当前资源按摘要去重；新索引、锁、预期版本与原子指针 | 当前模块支持的发布契约已经验证，固定入口实际HTTP资源摘要一致 |
| 5 复核退役 | 本轮独立任务、活动引用复查、冻结清单、工程师具体验收登记、缓存条目及交付核对 | 后续获批清单无依赖后自动七天回收并到期复核清除；未审核存量不接管，暂缓须说明原因 |

补充三个容易漏掉的检查：

1. **页面打开后还要加载真实内容。** 白名单、WASM、Worker、加载器依赖和服务内存清单一并核对。旧进程可能仍缓存旧路由；服务迁移需核对应用身份和创建时间，不能结束其他任务服务。
2. **报告冻结同一套源码和资源。** 相机、光照、阴影、分辨率、单位数量、声音和源摘要一致；性能窗口串行执行，避免Blender渲染与浏览器测试相互干扰。
3. **归档可恢复后才进入清理审批。** 归档需实际解包并逐条核对，来源映射和必要证据保留。新旧同摘要不等于可直接删除；并行已处理文件按原路径及摘要去重。回收不释放空间，永久删除后的历史不能再声称可从回收区恢复，单批例外授权不改变全局规则。

### 最小验收清单

- [ ] 模型：轮廓、材质、透明与UV正常；机械轴心或蒙皮、动作、重开工程有效；256／512及实际最近镜头已比较。
- [ ] 声音：完整解码、时长、声道、有限值、RMS、峰值、循环与混音有效；零音量、暂停、关闭及重置无残留；人工听审独立标记。
- [ ] 性能：下载字节、首次就绪、解码内存及帧时间分开记录；固定画质、负载与版本，保留P95／P99、真实长帧和无效样本。
- [ ] 运行：查询与原件恢复均走当前统一库；8767资料库、8768靶场、8769群体消费者按实际改动回归，HTTP摘要对应交付规格。
- [ ] 维护：原件与最新工程受保护；文档和来源同步，历史候选有精确清单和新批准，未把技术通过写成人工或设备验收通过。

## 五 本轮案例的正确比较口径

GB／MB／KB在下表使用十进制字节；内存配置MiB另按二进制单位。

| 案例 | 已验证数据 | 能复用的结论 |
| --- | --- | --- |
| 8768三款载具 | 上一轮1024保真规格32512508字节，当前256几何层1共3585884字节，减少约89.0% | 同三款装配范围比较；不称为对最初原件的压缩率，不包含引擎与音频 |
| 整库声音 | 251份唯一内容，原件与三份循环源合计534557860字节，运行版21614982字节，减少约95.96%；234份Opus、17份FLAC | 保留异常回退，按同范围唯一文件比较；253入口不等于253份不同文件 |
| 靶场声音子集 | 13项声音共837588字节，约0.84MB | 按场景加载所需子集，不把21.61MB整库当首屏必需下载 |
| 丧尸完整包 | 13款整包原件36182136字节，256档15559928字节，保留287骨骼 | 贴图与文件已优化，整包尚不能当成已完成13款独立群体运行优化 |
| 当前单只丧尸 | 256档105940字节，800三角形、23骨骼、两个测试循环 | 骨架独立与资源精简有效；不能拿单只体积对比完整13款包计算压缩率 |

完整模型库含400份保留规格、503466252字节，属于库内集合；同一场景按所需规格加载。库内总大小、页面首屏大小与峰值运行内存分别预算。

现有Chrome／Edge模型解析、音频解码和原型回归是技术证据。逐模型外观、逐条听审、真实服务器网络与普通电脑性能没有因此自动完成。当前仍有既有模型待修、角色待人工验收、静音待复核和未关联声音；增量入库不能抹掉这些状态。

## 六 后续任务直接使用的入口

从项目根目录运行以下当前维护命令；整库核验会启动独立浏览器负载，应避开其他性能采样时段。

```powershell
python -X utf8 -B scripts/断箭/查询资料库.py --query M1A2 --json
python -X utf8 -B scripts/资源库/查询资源.py --query 丧尸
python -X utf8 -B scripts/资源库/维护资源库.py audit
python -X utf8 -B scripts/资源库/维护资源库.py verify
```

旧整库报告和编码脚本保留历史方法，执行入口以[统一维护模块](../../scripts/资源库/README.md)为准。不要照历史命令重建退役目录；需要重建时写待入库，旧V2发布器不再使用。新增音频或模型的实际发布能力应读取当前模块后确认，不能把曾经迁移成功当成已有通用自动入库。

新任务先填写这五项：

1. **范围与保护**：资源ID、来源摘要、类型、当前消费者；原件、最新工程、其他任务使用文件。
2. **视觉与负载**：实际镜头、内部尺寸、同屏数量、目标设备、帧时间与可见性条件。
3. **处理规则**：贴图、材质、几何、骨架／动作、音频编码与循环的处理和回退选择。
4. **证据与状态**：源／输出摘要、技术阈值、Blender和双浏览器结果、人工待验与设备待验项。
5. **入库与退役**：当前索引版本、写入方、消费者回归、文档落点、本轮任务名、`stage`清单及摘要、工程师具体验收后的`accept`结果、缓存条目及`status --task`交付核对；无旧版或无缓存时明确说明，无需自动发现或推断。未审核存量仍单独审核。

制作与性能会话分开时，服务、交付和样本的读取依赖由消费者单独登记。生产任务完成不能替消费者解除保护；旧会话续做新一轮使用新的轮次任务名，不能沿用旧登记来接管历史存量。完整命令见[维护清理说明](../../scripts/维护清理/README.md)。

深入排障见[项目开发经验](项目开发经验.md)中“整库网页资源流水线”“战术视角游戏资源预算”“载具持续机械声补全”“网页音频响度标定”等章节。案例证据见[统一库报告](../../reports/资源优化/统一模型音频库与清理清单.html)、[游戏版对照](../../reports/资源优化/游戏版整库优化验证.html)、[持续声核验](../../reports/载具靶场/载具音效补全验证.html)与[响度核验](../../reports/载具靶场/靶场响度增强验证.html)。历史报告只证明对应批次，不覆盖后续实现。
