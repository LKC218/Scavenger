## 实施顺序

1. 固定未占用的新批次、输入与250个唯一事件清单；核对源文件和工具摘要，101份旧WAV逐文件复用。
2. 单任务串行提取149个新事件，每项独立尝试、输出和日志，失败保持失败并继续其他项，不写旧库。现有工具使用默认参数与有限时长FMOD事件渲染，仍标记event_render，不冒充原始raw_sample或穷举所有参数层。
3. 完成WAV解码、帧数、非零样本、削波及摘要检查；静音项核对参数和依赖后登记，不自动当作通过，不猜配或改写声音。
4. 生成独立音效浏览库：以声音为主入口，支持用途分类、事件名/路径搜索、来源bank与提取状态查看、原生音频试听；默认不自动播放，同一时刻仅一条。页面不要求先选择型号，不显示新造的型号对应。
5. 交付声音CSV、成功与失败记录、输入/输出核验及README。先做技术检查，再由工程师实际预览试听；库级功能验收不自动覆盖逐事件听审或循环状态。
