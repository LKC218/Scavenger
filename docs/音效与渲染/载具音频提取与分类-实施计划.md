```text
├─ 音频分类清单.csv
├─ 型号音频清单.csv
├─ 缺项说明.md
├─ 输出核验.json
└─ README.md
```

每份分类WAV使用“中文用途-源事件短名-文件摘要前12位.wav”作为可读文件名；仅清理Windows不允许的字符、保留完整原名及GUID于清单，截断过长名称并检查大小写冲突和保留名。短摘要仅用于可读名称，完整SHA-256负责身份核验；发生碰撞时增加摘要长度，禁止覆盖。

以事件GUID及渲染配置区分事件身份，以完整文件摘要去重。同一物理文件对应多个事件时保留全部事件身份和用途，按明确的共享类别存放。不同参数渲染不能只按事件路径复用。型号目录保存人可读的对应清单和相对音频路径，不再为每个型号复制同一音频；无声音的3个入口也必须有缺项说明。

清单至少包含：型号、配置/单位/选项、武器及弹药编号与名称、中文用途、源事件路径/GUID、来源批次、复用或新增、渲染参数、相对WAV路径、时长/格式/完整摘要、映射/技术检查/循环/听审状态。字段链与大整数对象ID在本地证据中保留，避免浏览器安全整数精度损失。本清单用于素材整理，不生成新的引擎运行资源包或接口。

3. 选择实际未占用的新批次编号，统一建立输入清单与事件任务清单。编号不在讨论阶段创建或由各工作对话自行抢占。

52与77按型号集合互斥；101个事件按唯一所有者分配，不按型号重复渲染。工作对话发现清单之外的事件或新的共用关系时，提交候选与来源，由主对话更新任务清单版本并分配后再提取，不自行扩张范围。

缺项任务不按相似名称或声音猜配。恢复事件须有当前构建可追溯的单位/配置/预设字段链及正式位置、真实事件或原生GUID依据。已有机器码证明“弹药预设对象存在时读取弹药；对象缺失才走武器Impact”；空字段不触发该回退。52个部分映射入口的正常弹药命中声音已经存在，不因7条旧武器路径重复提取正常声音。

缺项研究达到约定的1至3小时检查窗口仍未出现新证据时，提交已检查范围、阻断原因与未恢复状态。该情况不阻塞已有101声音分类交付，不能据此标记路径已恢复或全局废弃。

### 并发与写入约束

- 多个对话可以同时做只读核对；FMOD渲染最多两个独立子进程，初始并发1，确认内存和I/O余量后再提升到2。原生大型索引解析最多一个实例。
- 每个FMOD实例拥有独立工作目录、尝试名、输出和日志。现有提取函数会切换进程工作目录，禁止在同一Python进程的多个线程中并行调用。
- 现有 `提取音效.py --category` 会写批次总渲染记录，不能让多个对话直接对同一批次运行。新增任务封装只接受已分配事件，写分片结果；主对话最终合并。
- 工作对话不修改正式库、共享总JSON/CSV、导航和公共脚本，不重用其他对话的缓存/临时文件，不写入对方分片。
- 任务领取和完成状态由主对话单一写入，工作对话只提交自身回执；重复事件/配置身份、输入变化、摘要冲突或输出越界立即停止该项并报告。

### 阶段三：合并、分类与检查

1. 主对话收齐三个分片，核对覆盖集合为129且无重漏，按事件及渲染配置合并，检测重复渲染、冲突证据和缺失载荷。
2. 使用全部引用重算使用范围与用途。逐文件复制到分类目录后核对完整SHA-256；只保留一份相同物理WAV，型号清单使用相对路径引用。
3. 检查WAV解码、格式、帧数、非空数据、异常样本及削波；失败项保留记录，不混入技术通过文件。保持当前已验证48kHz双声道PCM16输出，原FMOD容器及重封装记录另存证据。
4. 生成音频分类清单、129份型号对应说明、缺项清单、输入/输出核验及README，更新相关正式研究说明和文件导航。
5. 交付新增与复用的精确统计、分类路径、全部未完成项及验证范围。保留当前正式版，分类候选是否提升正式版由工程师之后验收。
