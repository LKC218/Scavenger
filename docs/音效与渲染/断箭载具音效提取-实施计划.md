### 设计原则与范围

1. **先证明对应关系。** 目标链路是模型及选用配置 → 音效预设 → FMOD 事件路径或 GUID → 样本或事件渲染。文件名相似与听起来相近只能标为候选。
2. **保留音效共享关系。** 同一发动机、武器或弹药可被多型号引用。样本按指纹去重，型号和事件引用分别保留；不强行为每型号制造独占声音。
3. **分开交付两种声音。** 原始样本解码结果标为 `raw_sample`；经 FMOD 参数、混音或效果处理得到的录制结果标为 `event_render`，保存渲染参数，不称为原始录音。
4. **保护现有模型库。** 新音频批次独立保存，引用原模型 ID 和载荷摘要。现有 GLB、Blender 工程、模型清单与核验记录保持原样，不把音效作为修改静态模型的理由。
5. **状态与证据一致。** 映射、解码、循环技术检查、实际听审和页面交互分别记录，不能由其中一项通过推导其余通过。

本轮核心包括载具引擎或运动声、其选用武器的射击声，以及明确引用的发射、命中或爆炸声。相关素材不存在或不能确证时写明缺项。语音、音乐、环境与剧情声音不做整库扩展；发现相关引用时登记后续入口。完整游戏混音复现、动画、游戏启动与写回、正式引擎集成及公开发布不在本轮范围。

## 二、实施计划

### 阶段一：建立独立音频批次与输入基线

1. 读取本机配置、Steam manifest、已有模型清单和交付选择；确认游戏构建、模型版本、剩余磁盘及依赖可用。构建改变时建立对应新基线并标记跨构建兼容性，不沿用旧结论。
2. 在现有批次目录下选择未占用的 `BA-<构建号>-<序号>`，当前建议 `BA-26273833-002`，标记用途为音频；记录关联静态批次及模型清单摘要。已有目录拒绝覆盖。
3. 固定实际使用的 bank、strings bank、元数据与必要运行库的相对路径、大小、修改时间和 SHA-256；执行结束复核相同集合。按实际引用追加 DLC 依赖，不复制整个游戏。
4. 将工具按版本放在 `local-data/tools/`，保留官方仓库、版本、发布元数据、摘要和命令帮助。先检查本地已有工具，再补足需要的解码工具或隔离运行时；不改变系统默认环境。
5. 建立最小测试日志与进度记录，按系统时间戳计算耗时；外部命令用 `subprocess.run([...])` 参数列表，后台辅助进程隐藏窗口，退出时释放并清理本次进程。

**关口：** 可追溯输入、独立输出边界和工具运行条件已固定，任何路径解析后都不能指向游戏输入或原模型库作为输出。

### 阶段二：验证 bank 兼容性并建立事件索引

1. 核对 RIFF/FEV 的实际块结构、格式版本、插件和 FMOD 运行库版本；扫描标记只能辅助识别，不以缺少 `FSB5` 标记判定加密。
2. 优先测试与实际版本兼容的 FMOD 事件元数据读取，读取 strings bank 的路径/GUID、事件所在 bank、参数和循环或持续事件信息。使用独立系统实例，释放句柄；不启动游戏。
3. 对样本提取路径测试已验证可读的容器及编码。候选工具为 vgmstream，确认样本为兼容 FSB5 后才考虑 python-fsb5；命令行参数和实际支持范围以本机工具帮助、源码与试解结果为准。
4. 不能直接解码时，调查样本封装、编码及 bank 依赖；必要时用兼容 FMOD 运行时离线渲染一个事件到本地音频，明确其 `event_render` 身份。记录实际尝试与错误，不反复盲换工具，不猜密钥。
5. 输出事件与样本索引、工具兼容性结论、未解决项；本阶段按需探测，不进行无差别全音频导出。某格式受阻时继续可独立完成的数据库映射及证据整理。

**关口：** 至少一条目标事件具有可验证的索引与可播放的提取或渲染路径。若存在无法跨越的封装或依赖问题，形成有证据的受限报告，受影响项不得标为已提取。

### 阶段三：完成 A-10 小样与对应关系验证

1. 以 `Units.Id=282` 和预设 `UNIT_SOUND_PRESET_A10` 为入口，沿 catalog、脚本对象和序列化字段查到音效预设。保留对象路径、标识与字段依据，不依靠搜索命中名称直接认定归属。
2. 对照静态批次中 A-10 的选用装配，解析单位、武器、弹药及选项覆盖关系；分别寻找发动机、机炮及实际装配关联事件。发射、命中和爆炸按各自角色登记，不能互相替代。
3. 输出已确证的声音。优先保存原始采样率、声道与帧数的 WAV 解码结果，保留原始抽取数据；如新增压缩试听副本，单独标记派生编码。连续事件渲染需设有限时长、停止规则和参数清单，避免无限循环。
4. 检查解码、帧数、持续时间、非有限 PCM 值、空数据、峰值和循环起止；静音或削波先核查其设计及渲染参数，不能自动归为错误。循环点未知时明确标记，不编造循环范围。
5. 有实际听音能力时，播放目标事件或导出文件并记录听到的内容、截断、杂音及循环接缝；没有听音能力时，将听审标为“待试听”，可继续已通过映射和解码的技术流程，不把波形检查写为听感通过，也不自动通过用户扬声器持续播放。

**关口：** A-10 至少一个引擎或运动事件与一个实际武器事件完成确证映射及可播放技术验证，才进入自动批量。明确不存在的角色记为缺项；无法证明映射的候选不触发关口通过。关口不能满足时输出首测报告与可继续方向。

### 阶段四：空中优先、地面随后批量配套

1. 读取原模型交付清单，固定 52 个空中、77 个地面资源入口；先处理空中。每项沿当前选用配置与覆盖字段匹配，不将所有可能改装音效混入当前版本。
2. 对已确证事件提取或离线渲染，复用相同 bank/事件索引和样本缓存。默认最多两个解码工作进程；同一 FMOD 系统实例串行操作，工具临时路径互不覆盖。
3. 样本按 SHA-256 存放于共享音频目录，各型号保存独立配套清单。保存原事件 ID、源 bank、样本索引、音效角色、参数及共享关系，不能仅按输出文件名去重或覆盖。
4. 每个预期角色写状态：确证、候选、缺失或不适用；解码状态与听审状态独立记录。4 个模型待修项保留原模型状态，音频可单独确证，不改变静态验收结论。
5. 某型号失败时保存日志、错误与已完成结果，继续其他可处理型号；重试使用新尝试目录。为所有 129 个入口生成覆盖记录，未解析不等于没有音效，不用相似声音填补缺项。

**关口：** 每项都有明确的模型配套状态及问题清单，所有已输出声音通过其声明的技术检查；不以 129 个入口记录齐全宣称 129 项音效全部通过。

### 阶段五：交付试听目录与最终核验

1. 在新批次生成 `音效配套库/`：共享音频、型号映射、必要预览、离线 `配套音效目录.html`、JSON/CSV 清单、README 与核验记录。文件复制后重新计算摘要。
2. 页面支持型号搜索、空中/地面筛选、映射状态与听审状态展示，显示对应事件、共享标记及限制；使用原生音频控件，默认不自动播放，同一时刻只播放一条，循环播放由用户主动开启。
3. 从原模型库复制并校验必要缩略图，模型文件使用明确的相对引用与载荷摘要。README 说明与原模型库的相对目录关系；音频自身可携带，模型文件链接依赖原模型库，不能宣称整个页面的模型链接独立可迁移。
4. 用真实离线页面验证型号搜索、状态筛选、音频加载/播放状态、无结果、长名称与窄屏；页面播放状态不等于实际听审。无 GUI 条件时保留自动化检查结果并明确未完成的界面项，不沿用其他页面的历史截图。
5. 复核本轮输入摘要、原模型库清单与载荷未变、输出指纹与覆盖统计；生成批量音效报告，同步来源、观察、脚本说明、导航和经验。运行项目结构检查及与新增功能直接相关的验证，释放本次后台进程。

**交付标准：** 数据能追溯、音频能按声明方式解码或渲染、模型对应关系有依据、试听入口可用、已知缺项和实际听审状态可见。与原游戏混音一致需要另外的运行对照，当前不承诺。
