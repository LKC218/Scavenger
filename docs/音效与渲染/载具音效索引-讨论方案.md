# 载具音效索引-讨论方案

## 当前结论

工程师选择Three.js网页端为后续目标。本方案已获工程师确认，索引生成、双向查询及独立播放样例已实现，见 [模块说明](../../src/音效索引/README.md) 和 [实施计划](载具音效索引-实施计划.md)。正式游戏接入及压缩音频派生不在本轮实现范围。正式音效库V1沿用003目录，保留101个事件和129个入口的现有真实字段映射；其中126项有声音。后续应从现有映射生成精简运行索引，继续保留来源证据。

## 推荐的数据结构

首版使用三份静态JSON，不新增数据库或服务端。

| 索引 | 主要内容 | 解决的问题 |
| --- | --- | --- |
| 音频资源表 | audio_id、事件GUID及路径、文件SHA-256、文件地址、时长、渲染类型、循环状态、来源版本 | 一个音频可被多个载具共享，物理文件按摘要去重 |
| 载具绑定表 | model_id、unit_id、配置标识、选项；单位动作、weapon_id射击、ammunition_id命中和拦截到audio_id的关系 | 同一模型不同配置、同一载具不同武器和弹药分别匹配 |
| 播放规则表 | 动作触发、开始与停止、淡入淡出、音量、空间位置、并发上限、冷却、缺项处理 | 将已经确证的资源关联转为可控的游戏声音 |

模型标识与配置标识共同定位，不根据文件名或听感猜配。audio_id建议采用事件GUID对应的稳定标识；同一事件不同参数的渲染须另带render_profile标识，文件SHA负责内容版本与缓存，不能单独代表事件语义。中文名称供界面展示，原始标识供数据关联。

当前总映射已有大部分字段关系，不需人工重配129个入口。正式版本、物理文件摘要和研究字段链继续保留，网页运行索引只携带所需字段。引擎接入不直接依赖研究脚本，也不把整个研究目录搬入运行资源目录。

## 绑定与播放原则

1. 发动机和运动音关联单位动作，声音位置跟随车体；后续确认是否需要起动、怠速、运动、停止等独立素材。现有有限渲染不能直接视为无缝循环。
2. 射击音关联实际weapon_id及射击动作，声音挂载炮口锚点。先确认素材是单发还是连射片段，避免每颗子弹重复触发完整连射片段。
3. 命中音关联当前武器限定的弹药及命中类型，声音放在世界命中点。当前证据表明弹药预设对象存在时优先走弹药分支；对象缺失才走武器Impact回退，空字段不能等同对象缺失。
4. 7条未解析武器回退、3个无当前单位引用入口保持明确缺项。查询返回状态与原因，不自动借用相似型号的声音。原4项模型待修状态独立。
5. 增加双向查询：载具查看其动作、武器、弹药及声音；音效查看全部使用型号和角色。界面显示中文作用与缺项原因，保留事件路径和字段链查看入口。

## Three.js接入建议

全局AudioListener跟随主相机；空间音源使用PositionalAudio，并分别挂载车体、炮口或命中点。距离衰减参数按网页实际比例和场景试听调节，不照搬任意数值。[Three.js空间音频文档](https://threejs.org/docs/pages/PositionalAudio.html)

使用AudioLoader按需读取并缓存已解码AudioBuffer，同一资源多处播放共享缓冲区，播放实例独立管理。101份当前WAV约200MB，不在首屏全量下载；先加载当前载具及其可用武器，切换时释放不再使用的缓存，设置容量上限。[Three.js音频加载文档](https://threejs.org/docs/pages/AudioLoader.html)

由“开启声音”按钮的用户操作启动或恢复AudioContext，提供静音与总音量控制。[MDN音频实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)

当前WAV作为正式来源保留，面向网页的压缩音频后续生成派生版本，再单独验收浏览器解码、音量、循环接缝与素材对应关系。

## 推荐实施顺序

1. 先确认字段格式及动作命名，挑选A-10、AH-64和一项地面载具验证单位、武器与弹药层级；预计半天。
2. 从正式库生成全量静态索引和双向查询页面，检查129入口、101事件、共享引用及缺项是否守恒；预计半天到一天。
3. 在独立Three.js样例中接入选定载具的运动、射击与命中，再验收停止、并发、空间位置和首次点击解锁；预计一到两天，具体取决于现有动作接口。
