## 项目定位

- 目标平台：网页端。
- 三维渲染技术：Three.js。
- 历史防线阶段：8794提供已获工程师确认通过的V003交互与空中音效版；8793和8792的V002／V001服务已停止，144份有用资料归档到V003历史资料，三张阶段截图按已批准七天流程处理，见[整合退役验证](../reports/载具靶场/旧版整合与退役验证-V003.md)。8768靶场与8769群体实验独立保留。此前三路守基地及8至10分钟属于旧阶段方案，当前主线以上方无倒计时肃清占区规则为准。
- 资源研究：开展《断箭》目录核验、静态模型提取与美军空地载具批量验证，结论按验证阶段记录。
- 首轮原型：单机、RTS点选和框选指挥、俯视缩放镜头，5辆M1A2加5架AH-64D，低分辨率三维画面与清晰UI；当前开发电脑以60 FPS为目标。
- 当前扩展：保留首轮对照，新增1200米静态简模城市、A-10C单次扫射／普通轰炸与盘旋、连续机械声及10至500分档；当前默认100%音量与6dB增强，另有原始和12dB对比档。100单位为60 FPS主验目标，200／500只探索，实测与可见窗口试玩分别验收。镜头局部手感已通过。
- 阴影范围：固定白天、局部实时实体投影、建筑遮光和自阴影；近景2048阴影图，远景平滑降级。允许受控开销，100单位以整帧P95不超过16.67毫秒为主验，GPU成本另测；实现与边界见[靶场模块](../src/载具靶场/README.md)。
- 首轮验收：电脑键鼠与Chrome／Edge，按游戏手感调整射程及等待时间，友军不拦弹且不受伤。
- 新主线待锁定：初始编成、车型与弹药数值、接触伤害数值、区域点位和占领计时、胜负判定细则，以及测量负载与时长。玩法方向及开发电脑键鼠、Chrome／Edge、60帧目标已确认，以现行策划为准；旧防线耐久与波次不自动移植，联机另行讨论。

《RESTAND》是一项参考研究。丧尸方向现已由工程师确认，其他观察到的系统仍不自动转化为本项目需求。三车固定配装、普通丧尸100生命基准与原始值／当前值／建议值的边界见[对丧尸战斗建议](地图与载具/三车对丧尸战斗设计建议.md)和[第一版研究目录](../research/断箭/三车对丧尸研究/第一版-01a1a2af/README.md)。

首轮原型的已确认交战规则、断箭官方资料与配套建议见[断箭交互设计经验与原型约定](地图与载具/断箭交互设计经验与原型约定.md)。实际源码位于`src/载具靶场/`，操作与职责见[模块说明](../src/载具靶场/README.md)；规则确认、源码实现、浏览器操作与设备性能分别记录。

具体准备、实现顺序与验收任务见[载具打靶原型实施计划](地图与载具/载具打靶原型-实施计划.md)。先完成两款资源核验和1加1闭环，再验证最终5加5；源码和派生资源目录随实际实现建立。

批次编号采用 `BA-<Steam构建号>-<三位序号>`，例如 `BA-26273833-001`。编号一经写入批次输入清单便固定；重试若需改变输入或工具版本，建立新批次并记录与前一批次的关系。同输入下修复转换脚本时，将旧工程、日志和图像保留到 `历史输出/`，再生成新产物并重新审核。目录按实际职责建立，不提前创建空目录。

本地核验记录保留时间、构建号、资源文件头版本、相对路径与文件大小。正式结论引用输入快照名称并明确读取范围；文件头可识别、工具启动成功、资产解析成功、几何体提取、材质还原及 Blender 可视检查分开验收。以往版本和社区经验用于选择方法，不能替代当前安装的实测。

## 后续游戏源码的建立原则

以下是开始实现原型时的建议边界，当前不创建对应空目录：

| 建议位置 | 责任 | 边界 |
| --- | --- | --- |
| `src/main.js` | 启动与组装 | 不承载全部玩法逻辑 |
| `src/core/` | 渲染、帧循环和生命周期 | 不判断胜负或奖励 |
| `src/input/` | 设备输入到游戏动作的转换 | 不直接修改奖励、伤害等规则 |
| `src/game/` | 当前原型的规则与状态 | 不绑定 HTML 按钮或具体按键 |
| `src/ui/` | 菜单、提示与状态展示 | 通过明确动作调用规则 |
| `public/assets/` | 模型、纹理、音频等静态资产 | 记录来源和使用许可 |

小型原型只拆实际需要的模块；出现稳定职责后再建立目录与就近说明。当前不引入 ECS、网络同步层、多包架构或复杂插件系统。Three.js 官方安装示例可作为启动参考，具体分层属于本项目设计选择：[官方安装与项目结构](https://threejs.org/manual/pages/installation.html)。

当前靶场实际源码位于`src/载具靶场/`；入口、场景、输入和模拟之外，城市阶段按实际职责拆出地图、寻路、飞行、声音和统计模块，未建立建议中的空目录。规则侧不依赖DOM或Three.js；声音适配器通过固定资产复用现有音频运行时，不依赖资料库页面状态。只向127.0.0.1:8768提供白名单源码与媒体，与资料库8767分离。派生模型、输入摘要和浏览器回执位于`local-data/原型/载具靶场/`；首轮见[原型验证](../reports/载具靶场/原型实现与验证.md)，当前城市、A-10C、分档与音量范围见[模块说明](../src/载具靶场/README.md)及[阶段计划](城市固定翼原型-实施计划.md)。

合并战斗模式沿用该模块，实际规则、配置、角色适配和GPU合批分别建档；当前8794服务按V003摘要冻结运行源码，不覆盖旧靶场共享清单，历史8793和8792服务已停止。模型与声音读取统一库，角色读取已核验交付，游戏不读取研究JSON。历史制作输出、输入快照与回执统一保存在`local-data/原型/丧尸防线/V003-01a1a2af/历史资料/`，由归档映射追溯原路径；当前制作与长驻服务分别保护。GPU姿态纹理及机炮对齐段只在运行内存派生，不修改GLB或原音频。各版技术和人工验收独立记录。

## 实现流程

独立丧尸群体实验采用`src/丧尸群体测试/`，入口、群体规则、角色动画、场景和统计按实际职责拆分；只复用固定本地Three.js及官方addons，不接入载具靶场或正式资料库状态。源码与启动脚本为正式文件；模型派生、Blender工程、逐帧数据及浏览器证据位于`local-data/丧尸模型/性能测试/`；无私人绝对路径的研究摘要在`research/丧尸模型/`，离线报告在`reports/丧尸模型/`。操作、依赖与性能口径见[模块说明](../src/丧尸群体测试/README.md)。

1. 检查项目和适用技能，读取相关规范。
2. 明确需求、证据范围与待确认项。
3. 提交方案，获得工程师确认后编码。
4. 拆解任务，包含必要的 `scripts/` 工具。
5. 实现并做与改动风险匹配的验证。
6. 同步文件导航、最近模块说明与必要的经验文档。
7. 交付时说明使用的技能、验证范围和未完成项。

## 文档与命名

- 文档默认使用有意义的中文文件名，词组分隔使用连字符，不含空格。
- `README.md`、`AGENTS.md`、`apps-code-map.md` 等明确约定的入口保留原名。
- `docs/apps-code-map.md` 只维护文件入口、职责和关联文档，不写阶段记录或完成说明。
- 新增、修改或重构功能后，同步最近的模块说明；不得只更新总入口。
- 研究结论有适用条件时，连同来源、限制与验证方法一起保存。
- 全局运行界面（除维持历史 SHA-256 冻结的旧入口外）须统一接入 [全局UI-UX规范](全局UI-UX规范.md)，直接引用 `src/界面规范/` 共享令牌、组件与剪影标绘源，并由 `scripts/界面规范/` 提供 `127.0.0.1:8766` 活体规范路由；任何已接入模块的令牌、剪影与文档登记由 [检查项目结构.py](../scripts/检查项目结构.py) 自动校验。
- 实装前的界面与交互设计 HTML 预览统一放入 `docs/界面预览/<分类目录>/`，与存放已实施阶段验证及性能报告的 `reports/` 区分；目录与 HTML 文件名不含空格，须声明 `zh-CN` 且离线自包含，并在 [界面设计预览总索引](界面预览/README.md) 与分类目录 `README.md` 记录功能与状态，由 [检查项目结构.py](../scripts/检查项目结构.py) 自动校验。

## 本地数据与发布

多人开发的仓库文件范围、资源分包、接收端路径配置、已有能力和待实现任务见[多人协作方案](多人协作方案.md)。该方案为文档规划，资源导入工具和跨机接入仍待实现与验证；建库、资源打包、代码实现及发布按后续明确确认的范围执行。

不提交账号凭据、环境变量值、私人配置和健康数据。`.gitignore` 排除本地数据目录及常见凭据文件，示例配置只保留无敏感值的字段。

`local-data/` 整体忽略，覆盖工具、运行时、绝对路径配置、原始核验和提取产物；`tmp/`、`temp/` 保存可再生成文件。避免按 `.glb`、`.png` 等扩展名全局忽略，以便未来单独确认的正式运行资产正常归档。当前尚无 Git 仓库，忽略规则需要在未来建库后结合实际跟踪状态再次核验。

从项目根目录运行 `python scripts/检查项目结构.py` 检查入口、导航、本地链接与目录边界；报告内容继续使用 `python scripts/检查报告.py` 检查。两种检查均不访问游戏资源内容，也不执行提取。

报告以静态文件交付，本地预览仅绑定 `127.0.0.1`。安装依赖、初始化仓库、公开部署和未来游戏开发应按对应任务范围执行；本报告交付本身不证明这些阶段已完成。

## 正式资料库边界

实际网页源码在`src/资料库/`，标准库服务与检索维护在`scripts/断箭/`，固定启动入口在项目根目录。正式版本、媒体私有路由、验收回执与资源保存在被忽略的`local-data/断箭/正式资料库/`。V1直接复用原批次，V2按冻结清单将635份媒体独立复制到模型空地及ID目录、音频用途目录，必要来源JSON复制到入库记录。正式运行不依赖旧HTML，ID与内容摘要URL保持稳定。

日常使用只进入正式库；历史提取批次保留内部结构和冻结证据，通过本地`README.md`及逐文件分类清单导航。其他对话正在开发的原型、丧尸模型及其资料不参与归档或清理。媒体原件还承担旧版本和原型依赖，不能仅凭摘要重复删除；后续清理先解决依赖，再提交精确清单。

开发者与Agent优先按[使用说明](正式资料库使用说明.md)查询稳定ID，新增资产遵循[增量入库说明](资源与资料库/资料库增量入库说明.md)。该资料库是本机研究资料入口，未自动纳入未来游戏public/assets。

## 网页资源优化与冷归档

`local-data/网页资源库/`保存运行派生、冻结盘点、逐资产验证回执和删除候选；`local-data/资源归档/`保存原件压缩包、旧路径映射及完整恢复核验。全部留在项目内并由现有local-data忽略规则覆盖。`scripts/资源优化/`维护实际流水线，`src/资源加载/`只提供共享加载工厂，`src/网页资源验证/`提供独立验证台。

正式源版本与稳定ID保持不变，运行接入使用独立开关和内存清单；未通过验证的资源回退原件。默认基础层保留几何；静态细节层独立验证，骨骼不套用静态减面。删除必须审批精确冻结清单，不能把归档成功等同旧脚本已经全部迁移；恢复脚本按映射恢复原路径。

## 战术视角游戏资源派生

游戏版处理及验证输出位于`local-data/网页资源库/游戏版第一版/`，与原始资料、全库第一版和冷归档隔离。正式报告位于`reports/资源优化/`，脚本复用`scripts/资源优化/`，不另建空模块。新旧媒体不自动删除，跨会话预览服务不抢占；游戏清单覆盖只引用逐项验证通过并核对摘要的派生。
