# 前线资产库网页 UI/UX 重构实施计划

> **【历史归档说明】**：本文档所描述的前线资产库早期独立界面设计已被唯一全局权威规范 [全局UI-UX规范.md](../全局UI-UX规范.md)（Code SSOT V2.2）与统一主端口 `http://127.0.0.1:8800/dev/library/` 取代，仅保留作历史记录。

状态：已实施，等待工程师进行视觉与交互验收。正式页面、样式与交互已替换；资源索引、媒体文件与 8768／8769 服务未改变。为支持“打开文件位置”，8767 本机服务增加了受资产ID、登记URL和路径边界约束的只读定位端点。

## 一、定位结论

引用的“1103｜优化｜模型音频统一归档”会话完成了以下工作：

- 将 8767 统一命名为“前线资产库”，副标题为“模型 · 动画 · 音效”。
- 将 143 个模型入口、253 项声音统一到 revision 4 索引。
- 将静态模型规格收敛为 256 默认、256 远景、512 回退，骨骼角色保留完整拓扑与动作。
- 完成 8767／8768／8769 的资源接入、清理与浏览器回归。

该会话没有单独设计页面级视觉系统。当前页面仍是功能型三栏工具：顶部栏、模型列表、预览区、声音列表和固定播放器。它可以使用，但存在以下会直接影响浏览效率的问题。

## 二、现状问题

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| 固定播放器遮挡内容 | 桌面播放器约 95px 高，移动端约 145px 高；`body` 预留空间小于实际高度 | 桌面模型操作行和音效列表被遮住，移动端“当前规格”区域被压住 |
| 双滚动轴 | 左侧模型列表使用 `max-height` 内部滚动，右侧声音列表使用页面滚动 | 两栏长度不一致，页面底部出现大块空白，浏览位置容易丢失 |
| 分类控制不一致 | “全部／空中／地面”是分段按钮，“角色与其他模型”是独立按钮 | 同一层级出现两套控件，分类计数不可见 |
| 选中态造成位移 | 卡片选中时边框从 1px 变 2px，内边距同步缩小 | 选择模型时列表轻微跳动 |
| 声音名称偏技术化 | `US_A10_Turbine_New`、`SFX_Expl_MISSILE...` 直接作为主标题 | 工程师需要先解析原始 ID，扫描效率低 |
| 缺少统一交互层 | 没有全局搜索、键盘选择、规格快捷键、移动端资产切换 | 143 个模型和 253 项声音的检索成本偏高 |
| 移动端信息顺序不佳 | 模型列表占据首屏，预览和规格被推后，播放器覆盖内容 | 首屏看不到当前资产的核心信息 |

## 三、设计方向

正式方向：**战术资产检验台（Frontline Asset Command）**。

页面不是通用后台，也不是游戏商店，而是“在暗色战术终端中，用一块明亮检验台查看真实模型和声音”的工作界面。它与 8768 载具靶场保持同一产品气质，但信息密度更高、阅读更克制。

### 设计原则

1. **资产优先**：模型预览和当前规格占据视觉中心，导航与元数据退后。
2. **一个视口完成主任务**：桌面端不依赖页面滚动；左索引、中检验台、右上下文各自独立滚动。
3. **播放器是布局的一部分**：底部传输条作为网格行存在，不再覆盖内容；只有播放时才扩展信息。
4. **技术身份与可读名称分层**：中文用途／可读名称在前，原始事件 ID 在后。
5. **移动端先看资产**：首屏先给当前模型、规格和声音，资产切换通过底部抽屉完成。
6. **状态不只靠颜色**：通过图标、文字和边框共同表达“通过／待修／待复核”。

## 四、信息架构

### 桌面端（≥1280px）

```text
┌ 顶栏：品牌 / 全局搜索 / 模型库·音效库 / 索引状态 ┐
├ 资产索引 312px ┬ 检验台 自适应 ┬ 上下文 356px ┤
│ 分类计数       │ 标题与状态     │ 音频 / 参数 / 来源 / 关系 │
│ 当前编目       │ 明亮检验台     │ 按用途分组的声音           │
│ 模型列表       │ 规格三段       │ 当前选中声音               │
│ 显示更多       │ 操作与下载     │ 查看全部                   │
├────────────────┴────────────────┴──────────────────────────┤
│ 传输条：当前声音 / 进度 / 播放 / 循环 / 音量 / 快捷键      │
└────────────────────────────────────────────────────────────┘
```

- 顶栏：品牌、全局搜索（`/`）、资料类型切换、索引 revision 与同步状态。
- 左栏：分类计数、当前编目、排序、模型列表、显示更多。列表使用单一内部滚动，滚动位置在切换视图后保留。
- 中栏：资产眉题、名称、来源 ID、质量状态、预览／三维检验台、三段规格、预览图／重置／全屏／下载。
- 右栏：音频、参数、来源、关系四个页签；音频按“发动机与运动／射击与发射／命中与爆炸／载具毁伤”分组。
- 底部：传输条作为网格第三行，不覆盖任何面板。

### 中屏（960–1279px）

- 保留左索引与检验台两栏。
- 右栏改为检验台下方可展开的“上下文抽屉”，默认显示音频，参数与来源按需展开。
- 传输条保持底部一行。

### 移动端（<960px）

- 顶栏 + 粘性工具条：模型／音效切换、搜索、刷新。
- 资产条：`001 / 143`、当前模型名、“切换资产”和筛选。
- 单列内容：标题与状态 → 检验台 → 三段规格 → 操作 → 音频／参数／来源 → 声音列表。
- “切换资产”打开底部抽屉，内含搜索、分类计数和模型列表；选择后关闭抽屉并回到检验台。
- 传输条固定在底部，正文预留与传输条完全一致的高度，不允许覆盖内容。

## 五、视觉系统

### 色彩

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| 背景 | `#0b100d` | 页面底色 |
| 面板 | `#111814` | 左索引、右上下文 |
| 面板次层 | `#151e18` | 卡片、输入框 |
| 分隔线 | `#27342a` | 面板边界与列表分隔 |
| 主文字 | `#e8efdd` | 标题与正文 |
| 次文字 | `#96a397` | 说明与元数据 |
| 弱文字 | `#6a776d` | 眉题、快捷键、单位 |
| 信号色 | `#d6ff72` | 主操作、选中、通过状态 |
| 警告色 | `#ffb35c` | 待修参考、需注意状态 |
| 风险色 | `#ff826b` | 失败、待复核 |
| 信息色 | `#8bc8ff` | 待验收、角色与其他模型 |

主操作只使用信号色；警告色和风险色只用于状态，不用于大面积装饰。

### 字体

- 中文与正文：`Microsoft YaHei UI` / `Microsoft YaHei`。
- 英文标题与数字：`Bahnschrift`，使用较窄字宽和轻微字距。
- 事件 ID、规格、字节、三角形：`Cascadia Mono` / `Consolas`。
- 不引入远程字体，保持本机离线可用。

### 形状与质感

- 主要面板使用 1px 边界，少量关键块使用切角，不把所有卡片做成圆角。
- 检验台是明亮中性色面板，外围是暗色终端；这是页面唯一的大面积亮区。
- 网格、扫描线只用于检验台，透明度控制在 3%–6%，不干扰模型辨识。
- 阴影只用于检验台与主按钮，不堆叠多层玻璃效果。

### 动效

- 微交互 150–200ms，面板切换 220–280ms。
- 只对背景色、边框色、透明度和位移做过渡，不对宽度和高度做动画。
- 支持 `prefers-reduced-motion`；减少动效时保留状态变化，不保留装饰动画。

## 六、关键交互

### 模型浏览

- 点击模型行更新检验台与上下文，不自动加载 GLB。
- 选中态使用左侧信号色竖条与背景层级，不改变边框宽度，避免列表跳动。
- `↑`／`↓` 或 `J`／`K` 移动当前模型；`Enter` 加载当前三维模型。
- 搜索支持型号、角色、原始 ID、别名与标签；搜索框聚焦时按 `Esc` 清空并退出。

### 三维检验

- 初始展示预览图；点击“加载三维模型”后才下载 GLB。
- 加载中按钮显示实际进度，检验台保留骨架和当前画面，不产生布局位移。
- 加载成功后显示“实时三维 · 已就绪”，保留“预览图／重置视角／全屏”操作。
- 规格切换使用三个平铺按钮，显示分辨率、层级、字节和三角形；`1`／`2`／`3` 直接切换。
- 规格切换后不自动下载，提示“规格已切换，点击加载”。

### 声音试听

- 声音按用途分组；主标题优先使用可读名称，原始 ID 作为次级等宽信息。
- 当前索引多数声音以原始事件名为主，设计稿中的中文名称是展示层示例；实现优先使用现有 `name` 与 `category`，必要时只在前端增加只读展示映射，不写回索引。
- 点击播放按钮在全局面板内播放，同一时间只保留一个活动声音。
- 底部传输条显示当前声音、用途、格式、进度和时长；切换模型时停止并清空声音。
- `Space` 播放／暂停，`L` 切换循环，`Esc` 停止并清除当前声音。
- 循环是片段循环，不把它描述为游戏原生无缝循环。

### 文件定位

- 模型检验台提供当前 GLB 与可编辑 Blender 工程的“打开文件位置”；声音列表、声音检验台和声音详情提供当前音频的同一操作。
- 页面只提交当前稳定ID与该资产已登记的URL。服务端核对资产归属、HTTP路由、`local-data`边界和文件大小后才调用Windows资源管理器定位，不接收任意路径。
- 定位是只读操作，不打开、移动、改写或删除资源；接口响应只返回文件名，不回传本机完整路径。

### 状态与空态

- 模型状态：模型通过、待修参考、待验收。
- 声音状态：技术通过、待复核。
- 无关联声音时展示原因和“浏览全部音效”入口，不只显示空白。
- 读取失败时在顶栏与当前面板同时提示，保留刷新入口。

## 九、验收标准

1. 1440×900、1024×768、390×844 均无内容被底部传输条遮挡。
2. 桌面端不出现页面级纵向滚动；左、中、右三栏各自滚动且互不干扰。
3. 143 个模型入口和 253 项声音仍能读取、搜索、筛选、加载和试听。
4. 三维加载有可见进度，加载失败有可恢复提示，切换模型会中止旧请求。
5. 音频同一时间只有一个活动声源，切换模型停止播放，循环状态清晰。
6. Chrome／Edge 控制台无未处理异常；键盘焦点顺序与视觉顺序一致。
7. 页面名称、副标题、导航与现有“前线资产库”约定一致，资源身份和 API 契约不变。
8. “打开文件位置”只接受当前资产与其登记文件；拒绝其他资产URL、资产预览、未知ID和越界路径，定位失败有可见提示。
