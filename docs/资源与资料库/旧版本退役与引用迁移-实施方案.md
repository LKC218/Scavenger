# 旧版本退役与引用迁移-实施方案

## 状态与目标

状态：工程师批准的阶段一至五已完成；956份冻结重复副本已按批准摘要删除，失败0份。原始提取证据和其他对话使用资源保留；冻结候选及删除执行回执分别保存在本地阶段002目录。

目标：正式库继续作为开发者和Agent的统一入口，保留原始提取证据，逐项解除旧交付副本的读取依赖，最终生成可独立审核、按精确清单执行的删除候选。

基线为本地`维护/重复文件依赖排查/审计002/`：当前正式V2，1605份重复媒体共14,394,879,266字节。当前安全删除候选为0。实施前重新核对版本和其他对话使用情况，不能把此次快照视为持续有效的保护清单。

4. 正式资源：当前版本、635份正式媒体、来源元数据及已有验收保持可用；尚无确证替代、摘要不符、依赖不明或文件正在变化的项目一律保留。

已知靶场保护项为007的8份声音，以及001的M1A2、AH64D两份原始GLB。实施时保护精确路径及必要的外部依赖，不仅按文件名或这10项数量判断。不得修改其他对话的路由来解除依赖。

## 二、退役与引用迁移设计

### 1. 冻结记录保持原样，新增迁移对照清单

旧V1快照、历史JSON、CSV和日志中的原路径仍是当时的事实，不全局替换、不补写摘要、不删除引用字段。新增独立迁移对照清单，按以下关系解析历史资源：

```text
历史记录与字段 → 原资源路径及摘要 → 已登记的正式保留副本
```

每项至少保存：引用文件及其SHA256、JSON字段或CSV行列、原始引用值、解析后的旧路径、媒体字节和SHA256、正式保留路径与内容URL、对应版本、处理状态及迁移回执。相同媒体可以对应多份历史记录。

对照清单必须逐项匹配记录指纹和资源身份，不能只按名称、路径前缀或相似型号重定向。来源文件变化、映射缺失、目标摘要不符时停止该项迁移；不得把所有历史引用统一当成可忽略项。

### 2. 区分运行引用与历史追溯

| 引用类别 | 处理方式 | 完成条件 |
| --- | --- | --- |
| 当前正式库、开发者和Agent查询 | 使用现有当前索引和稳定ID；确认实际读取正式目录 | 不依赖待删路径，模型、声音和双向关系可用 |
| 本任务维护的核验工具 | 为必要工具增加显式归档解析模式，按迁移对照清单读取同摘要副本 | 真正读取并验证目标文件；缺失或错误映射必须失败 |
| 旧快照、历史清单、历史日志 | 保持字节不变，标为历史追溯引用，附解析依据和退役状态 | 原记录指纹与引用字段逐项匹配，归档回读通过 |
| 其他对话或未知动态消费者 | 不迁移、不改文件，列入保护或待核实项 | 未解除前不得成为删除候选 |

原始路径和mtime保留为历史事实；替代副本用字节和SHA256证明内容身份，不伪造原文件时间，也不声称原路径仍存在。归档回读通过只证明已迁移的读取链路有效，不能替代当年的视觉、听审或提取验收。

### 3. 旧版本退役方式

在独立退役登记中，将V1标记为归档版并关联原快照指纹、替代V2及迁移回执；不修改V1快照正文，不切换当前正式指针。V1后续通过显式归档解析回读，不再作为日常开发入口。

003等旧交付目录按文件登记退役，仍保留其中的来源、映射和核验记录。004等历史样例若存在读取依赖，必须迁移其受维护入口或明确归档并验证解析；未处理的消费者继续阻止对应文件进入候选。

旧脚本的逐个处理方式必须登记为“已支持归档解析”或“保留源码并退役，由归档核验入口接替”。不承诺所有历史脚本在原路径删除后仍可原样运行，不将其失效静默计为通过。

不创建符号链接、硬链接或旧路径占位文件来掩盖依赖；退役登记也不等于已删除。计划、映射就绪、验证通过、候选已冻结、删除完成分别记录。

## 三、五阶段实施计划

### 阶段一：更新基线与保护清单

只读刷新聊天状态、原型路由、输入记录、当前索引和媒体指纹。把956份首轮范围展开为精确清单，建立引用消费者台账，冻结保护项及其必要依赖。读取中的变更、无法确认的动态路径和14份未解析临时文件单列，不据此放行。

产物：本地基线、保护清单、引用消费者台账、首轮待迁移清单。任何新发现的其他对话依赖从待迁移范围移入保护范围。

### 阶段二：建立显式归档解析

以635份正式媒体为保留来源，为已确认同摘要的首轮副本建立逐项迁移对照。原始提取记录、冻结清单、脚本快照及退役凭证不修改。迁移映射只写新增维护记录，不批量重写历史批次。

产物：迁移对照清单、引用覆盖清单、归档版登记。该阶段不建立空壳“退役完成”回执。

### 阶段三：迁移受维护消费者并演练

依据阶段一台账，按需调整本任务维护的核验入口。现有`核验音效交付.py`仍会直接读取旧模型和旧音效目录，是重点核查对象；历史脚本快照及其他对话源码不修改。

在隔离环境中模拟待删旧路径不可用，强制归档解析从正式保留副本读取。演练不得改名、移动、屏蔽或临时删除工作区真实文件。模型需确认GLB或Blender工程的外部贴图等依赖已自包含或明确保留；未确认的模型不得放行。

产物：逐消费者迁移或退役记录、真实读取轨迹、隔离回读结果。全部原始证据指纹保持不变。

### 阶段四：生成精确删除候选

重新审计并逐项满足以下条件后，才列入候选：

1. 原文件与正式保留副本的字节及SHA256一致，保留副本不在任何删除范围，后续维护也明确保护它。
2. 不在其他对话保护范围，没有未迁移的运行消费者、外部资源依赖或未解释的路径线索。
3. 所有历史引用均有对应来源指纹、字段及有效迁移映射，归档回读真实通过；没有通过直接忽略旧引用制造无依赖结果。
4. 原始证据和快照指纹未变，当前正式库查询、预览、媒体读取及原型受保护资源的只读复核通过；相关扫描异常已解释或相关文件继续保留。
5. 输出绝对路径、字节、SHA256、正式保留副本、依赖处理依据、预计释放量和清单总摘要；候选本身不代表删除批准。

产物：可审核候选清单及暂缓清单。保护项、原始导出和提取证据不加入首轮候选。

### 阶段五：独立批准后按冻结清单删除

只有工程师另行批准精确清单，才进入删除阶段。执行前重新核对来源、保护范围、正式指针及全部候选摘要；发现变化则停止该批次，不自动扩大或改写已批准清单。

只删除批准的逐个媒体文件，保留目录内证据和元数据。记录成功、跳过、失败和实际释放量；删除后再次验证正式库、归档回读、证据指纹和其他任务保护项。删除后不承诺还原旧路径副本，需恢复时另行从保留的同摘要资源复制。

## 四、拟实施任务清单

以下为已批准阶段的任务清单，运行记录保存在本地维护阶段目录。

- [x] 扩展`审计重复文件依赖.py`：刷新保护清单，区分未迁移运行依赖、已验证归档引用和保留项，逐项检查映射覆盖，保留未知依赖。
- [x] 新增小型`历史资源解析.py`：显式加载受控清单、核对来源和目标摘要，仅供归档核验使用，不改变当前查询和HTTP服务的默认解析规则。
- [x] 新增`退役旧版资料.py`：仅实现基线冻结、映射准备、隔离核验和候选生成；删除入口在精确清单获批后的阶段实现。
- [x] 按台账调整必要的受维护核验入口，验证错误映射、缺失目标、保护项变动时确实失败；复核正式使用入口与证据完整性。
- [x] 同步文件导航、脚本维护说明、资料库模块及使用说明，生成本地迁移回执、候选和暂缓原因。

所有精确本机路径、指纹、保护清单和运行回执写入被忽略的`local-data/断箭/维护/旧版退役与引用迁移/<阶段编号>/`；已有证据不搬动。该目录只在阶段实际产生资料时创建。

## 五、审核范围与完成标准

推荐首先批准阶段一至四：迁移和验证，不执行删除。其他对话保护项和639份原始导出、提取证据重复媒体继续保留。首轮956份中无法满足条件的文件明确暂缓，不为达到释放量目标放宽要求。

阶段一至四初估60至120分钟，取决于受维护消费者数量及模型外部依赖；无法在首轮确认的项目列为暂缓，不用估时替代验收。

准备完成的标准是：每个候选都有可验证的同内容保留副本、完整来源链和已处理的消费者；隔离回读不依赖待删路径；证据保持原样；保护项不变。最终删除需要再次批准精确清单。
