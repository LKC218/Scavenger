# 资料库增量入库说明

## 全图场景技术发布

Airbase全图采用独立[场景发布器](../../scripts/资源库/发布场景.py)，由[交付封存与发布](../../scripts/断箭/地图提取说明.md)绑定全量文件和真实验收凭证。场景增量在共享维护锁内同步重绑未变的十三款交付，失败或进程中断可恢复原指针及原交付，后续版本阻止过期回滚。发布后检查[正式入口](../../scripts/断箭/验证正式场景.py)、[旧消费者](../../scripts/断箭/验证场景消费者.py)及正式登记的依赖收集。技术与AI通过不升级工程师人工状态，也不代替旧载荷的具体清单accept；操作见[维护模块](../../scripts/资源库/README.md)。以下早期V1／V2命令保留历史用途，当前统一库新增场景不使用旧WAV发布入口。

## 场景与原型的后续方案

[Airbase全图与场景资产双层入库实施计划V002](../Airbase全图与场景资产双层入库-实施计划.md)已获执行授权，定义整图引用独立资产、不可变版本ID、共享媒体、完整依赖及受控发布验收。全图处于A1原型制作，尚未实际入库。

场景使用[专项发布适配器](../../scripts/资源库/发布场景.py)，不放宽12款角色旧发布器。场景包清单固定`schema=1`，包含`package_root`、`files`、`assets`、`scene`和`acceptance`；文件及其相对依赖完整冻结，独立原型和整图身份分开。候选可先只读验证，正式发布要求四项技术及AI视觉通过，人工状态保留待审。维护锁、期望指针、不可覆盖ID、原子提交及精确回滚的命令见[维护模块](../../scripts/资源库/README.md)。已完成的11项隔离事务验证不代替真实场景验收；当前仍无全图发布回执。

## 当前状态

统一库建立后，旧V2直接发布GLB／WAV的命令已禁止写入正式旧目录；下文旧流程只保留为历史说明。当前查询、原件恢复、资源重建使用[统一维护模块](../../scripts/资源库/README.md)。重建只写`local-data/资源库/待入库/`，不自动发布。十三款专项新增的[统一库增量发布器](../../scripts/资源库/发布增量.py)只接受冻结并通过技术核验的12款角色清单：原件保留在已有归档，新增可编辑工程和256／512规格经双浏览器检查后，以维护共享锁、预期指针摘要与版本和原子指针切换发布到独立索引版本目录。既有ID、音频、靶场与原件索引保留；角色状态保持待人工验收，不因技术入库升级。

## 版本退役衔接

发布新快照不自动代表完成验收。新版验收后按[统一清理规则](../版本退役与缓存清理规则.md)核对旧载荷的替代关系和消费者，再用专项退役流程处理。旧快照及必要来源证据按身份保留；通用清理工具拒绝直接处理正式库媒体和快照。任务及服务启动前登记读写占用，首次存量先审核。

后续新轮次按[维护清理说明](../../scripts/维护清理/README.md)建立独立任务，开始及交付核对`status --task`。当前制作历史的精确清单由`stage`冻结，工程师确认具体新版后由负责会话登记`accept`；交付须列出退役、缓存和依赖交接状态，或无需处理／暂缓原因。原有专项候选、库索引和原件不因启用自动策略而扩大范围；已有服务未迁移引用时不能解除保护。不得把发布成功写成已经完成旧版自动退役。

## 流程

1. 从[清单示例](../../scripts/断箭/资料库入库示例.json)复制JSON到本机待入库目录，按实际文件填写。路径相对清单所在目录，也接受本机绝对路径；本机路径只留在local-data。
2. 通过CLI查询当前版本号，或读取本地`当前版本.json`的`revision`。
3. 先验证，再显式发布，两个命令使用同一当前版本号。例如分类整理后V2为2，实际操作前仍需读取当前版本：

```powershell
python -B scripts/断箭/维护正式资料库.py validate --manifest local-data/断箭/待入库/入库清单.json --expected-revision 2
python -B scripts/断箭/维护正式资料库.py publish --manifest local-data/断箭/待入库/入库清单.json --expected-revision 2
```

示例不是真实待入库资产，必须替换占位路径和ID后使用。验证不复制媒体、不切换版本。发布先锁定写入并重查版本号，再按内容摘要复制新文件、校验复制结果、生成新快照并原子切换指针。相同内容直接复用，旧快照保留。失败不切换正式指针，可能留下未被指针引用的候选文件，需人工核对后清理。不得盲删写入锁，应先核对记录PID是否仍工作。

新增模型自动归入`资源/模型/空中或地面或其他/稳定ID/`，GLB、工程及预览相邻保存；新声音归入`资源/音效/用途/摘要.wav`。同内容已登记时复用其现有位置，不因多个模型使用而复制声音。分类目录由核心函数统一生成，路径非法字符做受控替换并区分身份。V2迁移生成的CSV是带版本的人工查阅快照，新增资产发布后的实时结果以CLI及网页索引为准。

## 清单字段

`schema_version`固定1，`source`必须明确来源及使用范围，可用对象保存批次和证据相对路径。`models`、`audio`、`bindings`至少有一项实际内容。

| 类型 | 必填字段 | 可选字段 |
| --- | --- | --- |
| 模型 | `id`、`name`、`category`、`model_path`、`preview_path` | `blend_path`、`source_id`、`variant`、`aliases`、`tags`、`extensions` |
| 声音 | `id`、`name`、`category`、`audio_path` | `event_guid`、`event_path`、`kind`、`render_profile`、`aliases`、`tags`、`extensions` |
| 关联 | `model_id`、`audio_id`、`field`、`evidence` | 无 |

资源ID以`model:`或`audio:`开头，后续仅字母、数字、点、下划线、冒号、短横线；全库唯一、不得覆盖既有ID。修订资产使用新ID，旧资源保留。分类：模型`air/ground/other`；声音使用有意义的用途名称。`extensions`留作后续补充属性，不改变当前查询契约。

模型当前接受自包含GLB 2，PNG/JPEG/WebP预览，可选Blender工程。声音当前接受非空PCM16单/双声道WAV；检查实际样本数、静音和削波，逐条听审和循环状态仍待人工确认。新模型状态为待验收，不能继承旧模型通过状态。

只补关系时可省略模型、声音数组，引用已有稳定ID。关系必须有确证`evidence`，不得按名称猜配。`field`建议沿用MoveEvent、Shot、Impact、DeathEvent、MissileInterception；其他字段页面显示为其他用途。当前没有删除、覆盖资产或自动型号匹配接口。

## 验收

`核验正式资料库.py`在隔离目录测试验证无副作用、实际新文件复制、摘要复用、过期版本拒绝、重复ID拒绝、缺证据关系拒绝，且断言正式指针未变。真实新增资产发布后应刷新网页，补模型外观或听审记录，再决定是否用于后续开发。
