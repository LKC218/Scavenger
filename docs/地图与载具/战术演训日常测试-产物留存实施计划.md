# 战术演训日常测试产物留存实施计划

版本：V001。前两阶段已交付。第三阶段进入试运行：自动登记已接入，连续三个工作日的验收仍待自然时间观察。标签专项历史 Chrome 过渡等待超时按原失败留存。本文件维护实施范围和验收条件；第二阶段实测留在本机二期目录的 `第二阶段验证记录.json`，第三阶段进度使用入口的 `--observation` 核对。

## 1. 现状与目标

已有六条战术演训浏览器测试可显式使用 `--routine`：8811 移动、8812 镜头版移动、8812 高度镜头、8813 标签版移动、8813 标签与过渡，以及 8784 命名。原有正式命令继续输出完整证据。详见[候选工具说明](../../scripts/战术演训/README.md)。

推广轮次测得：新接入的五条测试输出由 37 个文件减到 7 个，少写 234624982 字节（223.76 MiB）。其中四条通过用例少 19 个文件、少写 14.26 MiB；其余收益来自标签专项复现同一已知失败，单独统计。258 份既有证据的摘要已复核。数据为本机推广轮次 `留存推广实测对比.json` 中的一次对比，非通用节省承诺。

第一、二阶段已统一六条用例的调用、输出目录和摘要文件名，补齐故障、中断及并发隔离；8784 日常检查改为独立只读核对。第三阶段试运行默认自动交接，并保留手工回退。Chrome 标签专项历史过渡等待超时尚未查明原因，不作为六条场景全部通过。

交付目标是：日常跑一条明确的命令就能验证，结果好找，关闭浏览器后可按现有制度回收临时产物。正式验收、单项补证、资产归档与旧存量沿用各自流程。

## 2. 从使用者看最终行为

入口为 `scripts/战术演训/运行日常测试.py`。下列六条用例均已接入，`--list` 可核对。默认生成新运行 ID 并自动登记；明确用于人工复核或持续消费者的运行加 `--retain` 保持保护，原手工模式可通过 `--manual-registration` 回退。

```powershell
python -X utf8 -B scripts/战术演训/运行日常测试.py --list
python -X utf8 -B scripts/战术演训/运行日常测试.py --case move-v3 --channel msedge
```

| 标识 | 既有测试 | 服务 |
| --- | --- | --- |
| `move-v3` | 标签版移动交互 | 8813 |
| `labels-v3` | 标签与景别过渡专项（完整判定、精简产物） | 8813 |
| `move-v2`、`altitude-v2` | 镜头版移动；高度与镜头 | 8812 |
| `move-v1` | 移动交互 | 8811 |
| `name-8784` | 统一命名、桌面布局及入口复用 | 8784 |

入口只分发给明确登记的脚本。单浏览器用例默认 Edge；专项可显式选 Chrome、Edge 或串行双浏览器；命名用例保留原来的双浏览器检查。默认只跑所选用例，不用全量套件充当每次开发检查。子进程用参数列表执行，从项目根定位资源；新日常命令默认无窗口。

每次生成唯一运行 ID 和未占用的输出目录，稳定版统一为 `tmp/运行/战术演训日常测试/<用例>/<运行ID>/`。已记录的路径和旧试点目录保持原位；已有直接 `--routine` 调用保留兼容。服务不可达、身份不符或在运行中变化时，直接报告，无替代端口、自动重启或自动重试。

| 结果 | 持久输出 | 命令表现 |
| --- | --- | --- |
| 通过 | 每次运行一份 JSON 摘要；无截图、逐帧文件、单浏览器副摘要或录屏 | 打印状态、检查数、文件数、字节数和摘要路径，退出码为零 |
| 验证失败 | 同一份摘要；每个失败浏览器最多一张关键截图、一份日志 | 保留失败检查和可取得的上下文，退出码非零 |
| 页面前失败或无法取图 | 摘要和必要日志；原因写明，无占位图片 | 能区分服务身份、浏览器启动、取图失败、执行中断或登记失败 |
| 正式验收与补证 | 沿用既有文件、截图和原始采样 | 原参数、端口和使用方式不变；日常入口不分发正式单项补证 |

摘要只写一份。保留运行 ID、用例、模式、时间、候选身份、版本摘要、浏览器版本、判定列表、退出原因及产物相对路径与大小。在所有输出写完后锁定文件集合。输出根不可用、越界或保护登记失败时，停止并在终端明确报错，不往未知路径落盘。验收报告继续按自己的证据格式生成，日常结果不作为实景人工验收。

## 3. 分阶段实施

### 第一阶段：统一日常入口（约 45–90 分钟）

- 新增日常入口及用例表，先接 `move-v3` 和一个真正产生日常大数据的专项 `labels-v3`。只读核对固定端口的应用、地图、冻结源码摘要与服务身份；非受支持的参数组合在启动浏览器前报错。
- 同步 `日常留存.py` 的目录和摘要约定。旧试点支持旧目录；通过新入口只写新目录。已有测试不另抄一份，所有原判定保留。
- 第一、二阶段沿用现有手工保护登记；只有第三阶段的交接测试通过，才由入口自动登记和关闭本轮任务。
- 用同一冻结候选跑一次通过、一次页面内故意失败、一次端口或身份失败。通过须恰好 1 文件；页面可取图的失败须是摘要、1 图、1 日志；无页面的失败须有摘要与原因。验证重复目录、越界目录和 `--map-command-only` 混用都被拒绝。

阶段交付：两个可用的日常命令、一份对照数据、原验收命令及既有证据复核记录。其余测试继续用现有命令。

### 第二阶段：补齐六条测试，处理故障和并行（约 1–2 小时）

- 把 V001 移动、V002 移动和高度、8784 命名接入同一入口。8784 的日常复用采用独立 `只读核对演训入口.py --check-only`：核对两个根快捷文件的字节身份和现有服务，但不执行快捷文件。原启动器本身被旧候选凭证按摘要保护，故不能在其上直接添加新开关；原快捷用法和正式 `--start` 保持原字节。日常模式服务丢失时必须失败，不能创建新进程或快照。退出前复核 PID 与冻结身份。
- 统一失败取证：失败当场且存在有效页面时优先取一张，超时保留原异常；包含失败检查、关键日志和追踪栈，限制大列表和日志长度。不改变正式逐帧采样或截取键鼠事件的机制。
- 回归六条用例的实际成功或可解释已知失败，覆盖双浏览器、启动失败、截图失败、中断、同时分发同一用例和目录冲突。故意失败只注入测试进程。异常时只处理本轮自有资源；无法确认浏览器进程已退出就保留保护。8813 标签专项历史同项失败须保持原非零结果，单项补证仍是完整专用命令。

阶段交付：六条日常用例可运行；排查失败能从摘要定位到具体日志；端口和原验收证据不变。

### 第三阶段：接入已有清理流程并试运行（约 1–2 小时，另观察 3 个工作日）

- 由统一入口按运行 ID 负责自己的 `protect → enroll → close`：开跑前登记准确读写范围；测试和浏览器确实退出、产物冻结后，仅把可重跑的本轮输出登记为缓存；已批准用于人工复核或其他消费者的资料单独保留和交接。登记失败或运行状态不明时暂停，不替其他会话关任务或推断文件空闲。
- 继续调用项目的 `tick`。已登记的缓存按现有闲置七天规则进入回收，再按逐文件七天复核清除。统一入口不执行删除，不接管未审旧存量，不调整定时任务的触发时间、阈值或权限。真实项目只核对资格和冻结条目；七天生命周期用隔离测试的受控时间验证。
- 记录每次文件数和字节数。最先观察成功摘要是否始终只有 1 份，失败图是否真的能定位问题，以及登记目录是否有残留。增长超预算时先提示并盘点，容量上限不改变保留期限。连续 3 个工作日收集至少 5 次日常运行，确认没有未归类产物和自动关闭其他任务后，再将新入口作为推荐用法。

阶段交付：可复核的运行与登记记录、使用和排障说明、试运行报告。之后新增战术演训浏览器测试时，先选择日常/完整模式，再把符合相同输出边界的用例登记到入口。

### 后续扩围（独立审核）

稳定后可把同样的约定推广到其他网页模块。Airbase 大依赖包按内容摘要复用是独立工作：需要先验证启动、独立打包和回退，不纳入本计划的测试工具改动。资产原件、CAB、TGA、既有回收批次及未审核旧存量不纳入本次实施。

## 4. 验收与回退

- 以同一冻结修订、相同浏览器通道与采样参数做前后对照。日报分别汇总通过、失败两类的文件数和字节数，不把历史故障或无样例当成通过。六条用例的正常判定、正式 CLI 参数和补证路径全部复核。
- 对既有正式证据和验收入口做前后摘要核对。任何脚本将日常输出写入验收目录、意外替换服务、丢掉原先判定或误报成功，立即停在该阶段，下一阶段暂不启用。
- 回退时停止使用新统一入口，切回原有直接 `--routine` 命令；正式验收照原命令执行。各阶段保留独立改前源、测试输出和版本标识。已登记的临时产物按现有流程处置，不通过删除目录实现回退。
- 完成实现时，把使用方式同步到 [文件导航](../apps-code-map.md)、[战术演训工具说明](../../scripts/战术演训/README.md)和[脚本维护说明](../../scripts/脚本维护说明.md)。按轮核对 `status --task`，报告真实验收状态、缓存登记和保留依赖。项目当前无 Git 仓库，本计划不初始化或发布 Git。
