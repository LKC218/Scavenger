### 首要技术问题

1. **恢复真实来源链。** 地形高度、地表纹理、道路形状和建筑摆放要对应到同一张Airbase地图。小地图图片、名称相似和单个Prefab不够证明原布局。
2. **建立统一坐标。** 源坐标、裁切区域、Blender、glTF和Three.js必须共用明确转换；原点平移与轴向转换分别记录，不能重复应用缩放或镜像。
3. **补齐非平地适配。** 现有靶场地面显示、鼠标落点、寻路和部分弹道以平面为基础，坦克初始高度为0。加载地图GLB不能自动获得贴地行驶、正确碰撞或高程命中。
4. **将资料还原与运行派生分开。** 保留有来源的几何、纹理与放置记录，再生成分块、简化材质、碰撞和导航数据；运行优化不能改写来源身份。
5. **限定首测目标。** 验证可提取、可还原、可移动和可在目标负载下运行；不在本阶段恢复整套Unity场景逻辑或原游戏玩法。

### 纳入与排除

| 纳入本计划 | 本阶段不纳入 |
| --- | --- |
| 首测及扩展区域内真实地形、道路、建筑与必要附属静态物体 | 全部地图与全游戏环境模型批量提取 |
| 地表材质、道路标线、建筑底色及必要透明材质 | 原游戏光照、天气、风、粒子和Shader逐效果复刻 |
| M1A2地面通行、建筑避障、地形高度与射线落点验证 | 飞机起降、机场调度、可进入建筑、可毁建筑、完整车辆物理 |
| 现有三型载具的地图兼容回归及100单位性能目标 | 联机、正式玩法、手机和其他电脑性能承诺 |
| 独立地图验证入口及对现有Demo的最小地图适配 | 替换现有默认地图、正式资料库发布、外网部署、写回或启动原游戏 |

树木、草、围栏等只在它们影响首测视觉、道路边界或通行时按实际来源纳入。没有必要时不扩展植被整库，也不恢复地下、多层路面或桥下通行。

## 二、实施计划

### 阶段一：固定输入与定位地图数据

**任务顺序：登记依赖 → 固定输入 → 定位几何与放置 → 验证尺度 → 冻结区域。**

1. 使用现有清理工具的`protect`登记本任务全部项目内读写依赖，包括只读工具、配置、原型源码和当前资源。游戏安装目录作为外部只读输入。核对其他任务改动；不解除状态不明保护或删除执行锁。结束使用后再`close`，持续运行的服务另行保护。
2. 读取本机配置、Steam构建、工具来源和磁盘可用量，在`local-data/断箭/批次/`选择尚未占用的`BA-构建号-序号`。记录用途为Airbase地图、阶段和关联批次；不提前固定可能被其他任务占用的编号。冻结实际读取文件的相对路径、大小、修改时间与SHA-256。
3. 从Airbase设置、正式Addressables目录和真实对象引用出发，查找地图地形、放置表、道路及共享资源依赖。按需读取UnityFS节点、主数据包和自定义地图序列化结构；只登记实际依赖，不将500 MB资源包的全部内容都导出。保存引用、对象ID、文件ID和原始字段依据。
4. 判明地形表示：标准TerrainData、现成Mesh、纹理编码高度或其他自定义结构；判明道路表示：网格、贴花、样条、地表绘制或混合方式；判明建筑是否依赖GPU实例数据、预合并网格或外部放置表。`.ng`仅在真实格式和来源得到证明时读取，默认重建Demo导航，不以改后缀方式转换。
5. 用源数据尺度字段及至少两个分离地标交叉核对方向、距离、高程和摆放关系。建立从源世界坐标到米制地图坐标的单一转换。优先选择跑道或滑行道连接附近、包含至少3栋建筑且至少2种建筑类型的500米方区；应有不少于150米连续可测路段，并覆盖道路与非道路交界。位置以实际数据为准，不虚构中心坐标。

**关口G0：** 地形来源、道路来源、建筑来源及原布局关联均有可追溯证据；米制比例和区域边界可证明。区域中心、朝向、源坐标范围与转换矩阵写入冻结配置后才提取。若Airbase真实布局中找不到同时满足条件的500米区域，提交候选俯视图和缺失条件，不能移动建筑凑成“原图”。

### 阶段二：提取500米区域并制作可编辑工程

1. 在500×500米核心范围外读取约25米上下文，用于法线、纹理、道路和跨边界物体处理。上下文不扩大地面命令范围。与边界相交的建筑保留完整物体并标记跨界，不截断建筑后冒充完整；地形与道路按裁切规则处理。
2. **地形：** 保存源高度数据或原网格及比例、偏移、采样间距、方向和空洞信息。生成米制地形网格及独立高度查询数据，处理地块拼接与法线。机场地形实际平缓时保留真实高度，不能人为加起伏证明提取成功，也不能用平面代替尚未解析的地形。
3. **道路：** 保存真实网格、样条控制或地表道路掩码和对应变换；恢复宽度、连续性、标线与贴地关系。如果道路仅存在于纹理中，明确交付为地表道路表现，另生成有依据的通行派生；不得声称恢复了原本不存在的独立道路网格。
4. **建筑：** 只提取区域及上下文实际引用的Prefab或合并网格。保留源对象身份、完整世界矩阵、材料、LOD及碰撞引用；重复模型保存一份，摆放另存实例表。当前载具材质转换器只作为读取与通道研究参考，地图Shader须重新核验，不直接套用载具遮罩公式。
5. **材质与工程：** 优先现有UnityPy、Blender和纹理工具；有虚拟纹理时复用已核验工具并串行访问共享数据。先保存来源贴图，再生成运行派生。Blender后台建立500米主工程，检查贴图打包、尺度、轴向、镜像绕序和层级，保存后独立重开；导出GLB后由独立进程回读。

**关口G1：** 500米地形、道路和建筑三类全部取得可追溯产物；范围内应有物体与实际导出集合一致，缺失项逐个列出。关键地表、道路或建筑缺失时不通过。占位色、白模或自画道路只能留作排障，不能触发扩展。

### 阶段三：独立Three.js验证与最小Demo适配

1. 建立实际可运行后再登记的地图验证模块，使用固定版本Three.js及现有共享模型加载器。新入口仅绑定127.0.0.1，选择未占用的安全端口并校验服务身份；不占用、重启或替换8767、8768、8769服务。源码、清单和HTTP实际响应固定摘要，避免并行任务混入版本。
2. 定义轻量地图数据契约：`bounds`、原点与尺度、地形分块、静态原型和实例、道路、建筑占地、可走区域及`heightAt(x,z)`。Three.js加载文件，纯数据与数学层处理高度和通行；不让模拟规则直接读取研究目录、Blender文件或原游戏包。
3. 当前靶场通过显式地图配置接入候选地图，避免继续只用`city`布尔值选择场地。扩展点限于地图配置、地形显示与拾取、导航和高度相关的模拟逻辑；平地地图仍返回高度0。当前城市、小靶场、资源规格、镜头手感和声音规则作为回归基线。
4. M1A2在地形上采样高度与适度朝向，校正出生点、道路移动、停止、倒车和建筑避障；动态避让沿用现有能力，不承诺完整车辆扫掠碰撞。对坡度、水面、洞和地图边界建立明确通行规则，默认阻止未知或无支撑区域。建筑占地从旋转后的实际轮廓生成并按车体半径膨胀，避免把所有建筑当作轴对齐立方体堵死道路。
5. 鼠标落点使用实际地面或可行走表面，不再对所有位置使用高度0平面。地面攻击、炮口、目标、弹丸地形相交、阴影与小地图统一引用地图高程。直升机及固定翼仅检查安全高度、命令边界与外侧机动缓冲；首测不在500米内强行容纳固定翼完整攻击航线。

验证器提供地形高度、道路、建筑碰撞、分块及实例计数叠加层。关闭叠加后的外观另行审图，不把调试视图当作最终地图。现有资源通过CLI查询稳定ID与当前规格，不遍历旧提取目录或自动写入正式资源库。

### 阶段四：500米首测验收

**所有必需项通过，才记为“500米首测通过”。文件生成、网页加载与验收通过分开记录。**

| 验收项 | 方法与通过条件 |
| --- | --- |
| 来源与完整性 | 输入、实际依赖、源对象、实例矩阵和输出摘要可追溯；地形、道路、建筑来源确证；范围内必需资源缺失0；既有资源与非本任务文件未被改写 |
| 尺度与布局 | 核心区域500×500米，边长误差不超过0.05米；至少两个分离地标复核方向和距离；建筑摆放转换与原矩阵一致，未人工平移拼凑 |
| 高度与拼接 | 固定规则抽样至少100个有效地面点，对照源高度或源网格；允许误差为0.1米与源高度最小量化步长中的较大者，统计最大值和分位值；同源相邻块边界应一致，数值误差不超过0.01米，无可见裂缝 |
| 道路与建筑 | 检查全部道路端点及交界、每种材质和建筑类型；无道路悬空、明显穿地、反面丢失和关键标线错位；贴花叠加只使用记录过的偏移，不用大幅抬高遮掩地形错误 |
| 工程与媒体 | Blender保存重开、贴图依赖、GLB独立解析及HTTP加载通过；无404、解码失败、NaN几何和地图相关控制台错误 |
| 实际视觉 | 实际查看俯视、四方向斜视、道路近景、建筑地面接触及GLB回读；记录每图文件摘要、审核对象和问题。没有原游戏对照图时，只能声明源数据重建检查，不能声称原游戏画面完全一致 |
| 通行与交互 | 至少10组固定路线，包含连续道路、转弯、建筑绕行、边界、不可达目标、坡面或已证实的平缓地面；车辆不穿建筑、不明显浮沉、不走出边界；实际鼠标点选、右键、缩放、聚焦、暂停恢复及重置通过 |
| 回归 | 旧城市与小靶场可在隔离验证入口正常运行；三型载具显示、声音、阴影和现有命令不因地图适配退化；不以地图尚未纳入的机场起降作为通过项 |
| 性能 | 按下方固定条件分别测Chrome和Edge，100单位主验的整帧P95不超过16.67毫秒；如不达标，保留问题和优化记录，首测不升级为通过 |

#### 性能条件与建议预算

预算是待验证的工程目标，不是现有实测结果。正式测量前冻结硬件、GPU驱动、浏览器版本、窗口尺寸、实际绘制分辨率、资源规格、声音与阴影设置。默认沿用现有电脑、1280×720验证视口、内部宽度640且高度按比例、设备像素比1、当前256载具规格、既有声音与阴影策略。

- 每个浏览器串行进行：空场60秒；10辆M1A2固定路线60秒；100单位代表负载预热10秒后采样180秒。100单位按现有80%地面、16%旋翼、4%固定翼组成；固定翼使用独立外侧机动范围，记录场内、可见、移动、模拟及发声数量。
- 代表负载须有持续移动及可重复交战，不用空场或已清空目标的结果冒充交战性能。记录FPS、整帧P50/P95/P99、超过33.34毫秒和50毫秒的帧数、绘制调用、三角形、纹理估算、JS堆和寻路排队；无窗口结果与可见窗口结果分别登记。
- 500米地图运行派生初始目标：地图首次必要传输不超过50 MiB，回环冷HTTP缓存首次可操作不超过10秒；典型局部视角总绘制调用不超过200、提交三角形不超过100万、纹理估算不超过256 MiB。引擎、载具与地图传输分别统计，估算显存不冒称真实GPU显存测量。
- 100单位整帧P95为主要性能关口。其他预算超标时先优化并说明；确需调整数值须提交实际测量依据供工程师审核，不能静默放宽阈值。只做为解决具体剩余风险所必需的复测。
- 连续切换、重置及退出至少5次，确认事件、材质和几何资源不持续积累；共享资源按拥有关系释放，不销毁其他模块或实例仍使用的资源。

**关口G2：** 首测全部必需项与实际视觉审核通过，生成绑定输入、工程、GLB、源码和运行媒体摘要的通过记录。工程师若在批准实施时指定人工样本确认，则在该确认后扩展；否则按批准范围由执行任务自行审图判断，不重复申请同一阶段授权。

### 阶段五：通过后扩展至2公里并复验

1. 围绕同一真实区域选择2000×2000米范围，优先让500米首测区位于扩展区内部，保留相同世界原点与资产稳定标识。若原地图边界限制，整体平移扩展方区并记录映射，不能复制500米图块铺满或放大建筑凑面积。建立新的扩展批次并引用首测通过记录，不覆盖首测工程。
2. 延续同一解析链，增量提取新增依赖与摆放记录。地形建议以125米块组织：500米为4×4块，2公里为16×16块；这是运行组织建议，不修改源数据。边界共享同一高度采样；全局实例ID去重，跨块建筑只归属一个主块并保存覆盖范围，防重叠显示和碰撞遗漏。
3. 相同几何、材质及规格的建筑使用实例化；批次按空间块划分并维护包围盒，不能将全图所有建筑合为一个永不剔除的大批。共享纹理、网格压缩和远景细节层复用现有加载器能力，实际兼容后才启用；地表优先分块纹理，不能把整张2公里图缩成一张256贴图。
4. 优先分块按需加载，局部显示用高细节、全场总览用低细节；渲染卸载不删除全局静态通行数据。2公里导航先采用米制简化占地与约4米基础网格，必要道路局部细化，以真实道路宽度和现有车体半径检查可达性；没有具体瓶颈前不引入复杂分层寻路框架。
5. 重做全部块接缝与关键交界检查、全图完整性和布局审图，扩展路线覆盖图块边缘与长距离移动。Chrome和Edge分别完成100单位180秒主验及不少于90秒跨区镜头移动，检查加载空洞、迟到资源、瞬时长帧和回收。2公里建议预算为首次必要地图传输不超过80 MiB、回环冷缓存首次可操作不超过15秒、典型视角绘制调用不超过350、提交三角形不超过200万、纹理估算不超过512 MiB；总览和局部视角分别记录。

**关口G3：** 2公里范围数据完整、分块与跨块通行正确、视觉与100单位性能达标，生成独立验收结果。若扩展失败，保留已通过的500米版本作为当前候选，2公里标为未通过；不得用降低单位数或遗漏建筑来替代原目标而不说明。

## 五、风险、回退与停止条件

| 风险 | 处理与停止条件 |
| --- | --- |
| 只有小地图和设置，找不到实际地形或布局 | 保存证据并继续定位；G0不通过，不用自建平面/摆放冒充提取；需要原游戏运行观测时另行提出范围 |
| 数据包大、内存或磁盘不足 | 按节点读取、单工作进程、复用摘要一致的完整缓存；预估展开空间并保留余量，达到事先记录的内存/磁盘上限时安全停在检查点，不对未知缓存执行删除 |
| Shader或虚拟纹理不兼容 | 查实际字段、图层与编译关系，串行访问共享纹理源；未知材质列为待修，不以缺图0代替实际视觉通过 |
| 地形不适合单值高度场或存在多层道路 | 首测优先选单地面区域，保留洞与阻挡；不能还原的多层结构停止相关通行验收，不能压平后声称一致 |
| 接入改动影响其他任务与既有Demo | 实施前核对最新源码和活动登记，使用明确地图开关与隔离服务；保留旧地图路径，进行有限回归，不切换正式服务或改全局资源版本 |
| 2公里性能不达标 | 先处理材质批次、局部可见块、纹理和细节层，再定位导航或阴影开销；保留实测，500米通过版本继续可用，2公里保持未通过 |
| 中断或额度不足 | 检查点记录阶段、任务配置与摘要，恢复先保护和复核输入，再续未完成项；不创建并行任务掩盖额度限制，不重新渲染已核验资源 |

执行采用单任务、单提取/构建/浏览器工作进程；外部命令用参数列表，不拼接Shell。计时以系统时间戳差值为准。后台辅助服务隐藏启动，按PID、命令及身份只管理本任务进程；不控制或关闭其他Blender工程、浏览器服务和游戏。

版本与缓存按[七天回收规则](../版本退役与缓存清理规则.md)管理。此计划不授予删除旧音效任务文件、存量模型、归档或其他聊天资料的权限。失败输出可记录为退役候选，但实际清理仍按当前登记、来源和精确清单审批，不无期限累积也不自动清除证据。
