| **GLB 文件字节** | 92 KB | **1.18 MB** | 1.82 MB | 2.83 MB | **150.22 MiB** | 256 远景档另占 **120.41 MiB**；未启用网格量化，**几何占比高达 ~88.5%** |
| **内嵌贴图字节** | 38 KB | 139 KB | 232 KB | 319 KB | **18.06 MiB**（11.5%） | 909 条贴图中唯一仅 356 条（7.60 MiB），**跨车重复嵌入率高达 60.8%** |

**现行运行时结构缺陷**（详见 [场景.mjs](../../src/战术演训/场景.mjs#L81-L103)）：
1. 浏览器启动时才遍历场景树，调用 `toNonIndexed()` 展开顶点索引并 `mergeGeometries()`，导致运行时显存与顶点数无谓膨胀并拉长冷启动耗时；
2. 炮塔、炮管、旋翼轴心仅针对 3 款靶场装配模型手工硬编码，无法扩展到全部 129 款载具；
3. 前线资产库静态模型（129 款）与靶场机械装配（3 款）事实分裂，存在双套维护隐患。

## 二、 单源流式载具核心技术架构

总体设计原则：**“单一可编辑源 + 声明式规则表 → 离线全自动编译与视觉自修闭环 → 同源三档渐进 LOD + 去重图集 + 二进制 Range 归档 → 统一实例化渲染与 680p 展示/战局双模共用”**。

| 考核维度 | 现行基线（`revision 7`） | 本方案目标门限 | 优化幅度与口径说明 |

### 2.2 模块一：离线声明式节点清洗与可动部件语义合批

将现行 [场景.mjs](../../src/战术演训/场景.mjs#L81-L103) 中在浏览器端做的节点解析、矩阵烘焙与镜像绕序修复**100% 前移至离线编译期**（复用 `local-data/tools/网页资源优化/1/` 固定版本的 `@gltf-transform`、`meshoptimizer`、`sharp`、`ktx2-encoder`）：

1. **祖先链语义传播（解决父空节点 + 子 `*-渲染网格` 结构）**：
   - 扫描表明 `gun / rotor / blade / tail / radar` 多位于父级空节点，实际网格挂在子节点下。编译器自顶向下遍历原始层级，按 `vehicle-rig-rules.json` 规则将所有后代网格继承归属到标准槽位：
     - 地面载具：`hull`（默认兜底）、`turret`、`barrel`、`radar`；
     - 旋翼航空器：`hull`、`main_rotor`、`tail_rotor`、`gun`；
     - 固定翼与无人机：`hull`（默认装配外挂合并入机身）。
   - 取每个语义槽位根节点的精确世界坐标作为局部旋转轴心（`pivot = [px, py, pz]`），将槽内全部子网格顶点烘焙到“以轴心为原点”的局部空间，同时一次性修正负行列式镜像矩阵的三角形绕序与法线方向。
2. **黄金基准与规则覆写**：
   - 将现有已验证的 `M1A2`（炮塔/炮管）、`AH-64D`（主旋翼/尾旋翼/机炮）、`A-10C`（整机）轴心与部件归属作为自动回归测试用例；
   - V0 自动扫描全部 129 款载具生成初始 `vehicle-rig-rules.json` 分类清单，对少数命名非标车型（如自定义前缀或复合炮塔）通过该声明式 JSON 覆写，绝不手工修改导出后的 GLB。
3. **废节点清零与同槽材质合批**：
   - 在提取完有效语义挂点（炮口估算点、尾焰、引擎声源、着地极值点）写入元数据后，彻底删除 17,534 个无用空节点及无用 `TEXCOORD_1`、`TANGENT` 冗余属性；
   - 同一可动槽位内的不透明子网格按图集重映射 UV 后离线合并为 **1 个单一索引缓冲 Primitive**（保留完整顶点索引，彻底废除浏览器端 `toNonIndexed()` 展开）；半透明玻璃/座舱盖独立归为 `glass` 材质组以保证透明排序与环境反射正确。

### 2.3 模块二：同源三级 LOD + 强量化 + 自动误差收敛闭环

1. **统一顶点强量化与压缩**：
   - 全部三级 LOD 统一启用 **`KHR_mesh_quantization` + `EXT_meshopt_compression`**（`QUANTIZE` 模式）：
     - `LOD0`：**位置 14-bit（10m 载具精度 ~0.6 mm）、法线 12-bit（消除战机光滑座舱与流线机身的高光条带）、UV 10-bit**；
     - `LOD1 / LOD2`：**位置 12-bit、法线 10-bit、UV 10-bit**。
2. **同源三级渐进 LOD 生成策略**：
   - **LOD0（单一高清基线：单车 360° 展示 + 战局极近景 `span < 160m`）**：
     - 从 `模型.7z` 无损恢复的原始高模出发，先执行重复顶点焊接、退化面清除与不可见内表面（包围盒深度遮挡极小闭合内腔）剔除，再按包围盒尺寸分三档目标面数（小型 5k–10k、主力 12k–18k、重型 18k–24k）执行 `MeshoptSimplifier`（`lockBorder: true`，严控几何误差阈值 `error <= 0.0025`）。
   - **LOD1（战局常态 `160m – 480m` + 近景实时阴影专用代理）**：
     - 直接以同源 `LOD0` 为输入减面至 **2,000 – 3,800 面**，保持所有可动槽位结构一致且**100% 复用 LOD0 贴图坐标与低级 Mipmap（0 额外贴图字节）**；
     - 战局实时 2048 ShadowMap 统一绑定 **LOD1 投射阴影**，阴影通道顶点开销立降 5–10 倍。
   - **LOD2（远景总览 `>= 480m` + 全库 129 车常驻零等待底座）**：
     - 由同源 `LOD0` 合并整车外轮廓并重网格化/激进减面至 **150 – 380 面**实心轮廓壳（单网格、无细碎天线/外挂、**0 贴图**），离线按五方向 WebGL 渲染均值烘焙逐顶点色或主色调（与大地图路线 B 的色阶校准同源），单车仅 **10–18 KB**。
3. **视觉反馈驱动的自动降级收敛机制（防止“盲目减面崩模”）**：
   - 每款载具编译完成后立刻进入自动视觉闸门；若 `LOD0` 剪影 IoU `< 0.965` 或前景 SSIM `< 0.92` 或黑面异常 `>= 0.5%`，编译器自动执行**最多 2 轮收紧重编**：
     - 第 1 轮重试：减面误差阈值减半（`error × 0.5`），目标面数预算上调 `1.35×`；
     - 第 2 轮重试：针对问题槽位关闭简化（保留原清晰拓扑 + 仅执行去废节点/合批/14-bit 量化）；
   - 若仍未通过阈值，自动将该车型写入 `需人工复核清单.json` 并附差异热力图，绝不伪造通过。

### 2.4 模块三：去重共享贴图池 + 单车 1024 KTX2 图集 + 双模渲染环境

1. **防发糊的贴图密度守恒规则**：
   - 先对全库 129 款原件（从 `模型.7z` 按 SHA256 只读恢复）全部贴图做内容哈希统计：
     - **跨车出现 ≥ 2 次的通用贴图**（导弹、挂架、履带、轮胎、通用金属件等，覆盖现状 60.8% 重复项）提取至全局共享贴图池 `vehicles-shared-tex.scvveh`，按原分辨率上限（底色 512/1024 ETC1S、法线 512 UASTC）唯一编码一次；
     - **单车独有贴图**按像素面积加权自动排布烘焙为 **1 张 `1024×1024`（小型载具/无人机 `512×512`）ETC1S KTX2 图集**（含完整 GPU Mip 链：`1024 → 512 → 256 → 128`），保证单车特写像素密度**高于**现状分散的 256 贴图，同时不额外存多套分辨率文件；
     - **轻量 512 法线细节**：若源模型包含有效法线贴图，同步排布并编码为 **`512×512` UASTC 线性空间 KTX2**（单车约 70–110 KB）；无有效法线图则自动省略并在元数据中标记 `hasNormalMap: false`。
2. **同一份 `LOD0` 的双模渲染环境**：
   - **战局模式**：轻量化方向光 + 半球光 + `LOD1` 实时阴影 + `stylized-680p-v1` 复古微缩呈现，极致稳定帧率；
   - **单车 360° 展示模式**：读取**同一份 `LOD0` 资产**，在展示台额外开启 Three.js 内置程序化 Studio 环境贴图（`PMREMGenerator + RoomEnvironment`，0 外部文件开销）+ 柔和地面接触阴影 + 可交互旋转/部件动作测试，全面释放 1024 底色 + 512 法线 + 12-bit 曲面法线的军械质感。

### 2.5 模块四：自动化物理、包围盒与挂点元数据派生

参考路线 B 的 [自动物理派生.mjs](../../src/程序化地图/自动物理派生.mjs)，离线编译 129 款载具时同步自动生成并验证以下游戏数据（直接编入二进制索引与结构化 JSON 供 G05/G06 及路线 B 大地图复用）：
- **精确碰撞 OBB / 局部包围盒**：车体长宽高、中心偏移与碰撞半径；
- **贴地采样点**：地面载具自动按底面极值派生 4 角轮距/履带接地采样坐标（供大地图坡面俯仰与侧倾贴地使用）；
- **名牌与安全包络盒**：自动按 [载具名牌.mjs](../../src/战术演训/载具名牌.mjs) 口径计算包含主/尾旋翼完整旋转扫掠圆的 `labelBounds` 与直升机越障安全半宽/顶高；

- **五方向平均线性基色**：供 `LOD2` 远景壳、小地图图标与战术列表色块使用。

### 2.6 模块五：二进制索引（`.scvi`）、HTTP Range 分层归档（`.scvveh`）与统一运行时

2. **统一运行时渲染模块（`src/程序化载具/`）**：

## 三、 全自动执行、自行检查与多维视觉测试体系

为满足工程师“**全自动执行、自行检查、视觉测试**”要求，本计划内置**一键无人值守总控流水线**与**三级硬性自动化闸门**，绝不依赖人工逐车肉眼排错：

### 3.1 总控调度与断点续跑
- 入口脚本：`scripts/程序化载具/运行全流程.py`（支持 `--from V0 --to V5` 全自动串行直通，也支持按阶段单跑与按输入 SHA256 增量断点续跑）。

### 3.2 第一道闸门：静态二进制、结构与完整性自检（`验证静态结构.mjs` + `验证归档回读.py`）
1. **输入溯源校验**：逐一比对 129 份原件与正式库 `revision 7` 登记的 `source_sha256`，确认原件只读未变；

   - **视角 1（单车特写前左 45°）**：检验单车 360° 展示台正侧前观感、贴图清晰度与 Studio IBL 质感；

## 六、 风险预判、保护边界与维护合规

1. **主要技术风险与自动兜底策略**：
   - **风险 A：部分车型非标节点导致炮塔/旋翼归类不准** → 解决：祖先链匹配 + 动态旋转差图自动验真，一旦出现“车身联动”或“部件脱离”自动拦截告警并写入规则覆写清单，不静默放行；
   - **风险 B：极个别细长部件（雷达天线/防滚架/机枪管）在 LOD0 减面中被过度简化** → 解决：`lockBorder: true` + 剪影 IoU 自动闸门触发两轮误差收紧或自动回退无损量化拓扑；
   - **风险 C：图集重排 UV 后出现接缝渗色（Texture Bleeding）** → 解决：图集打包强制 `≥ 4px` 边距填充（Edge Padding）+ KTX2 Mip 生成前做边缘像素外扩，并在六视角 SSIM 与放大特写中自动检出。
2. **清理工具与跨会话交接合规**：
   - 实施阶段启动前运行 `scripts/维护清理/清理工具.py protect --task 程序化载具优化实施-V001-<会话前缀>` 登记全部读写路径（含 `local-data/资源库/原始归档/模型.7z` 只读依赖与 `local-data/程序化载具/`、`tmp/程序化载具-*` 输出目录）；
   - 解包 `模型.7z` 产生的临时原件副本与中间贴图烘焙缓存统一置于 `tmp/程序化载具-V001/`，构建完成后按准确文件集合执行 `enroll --kind cache --note 可由模型.7z与编译脚本重新生成` 登记，绝不触碰存量边界或篡改既有保护；
   - `V5` 交付后保留 `8822` 读依赖保护直至工程师完成人工验收，不擅自覆盖或关闭其他会话保护。
3. **当前未执行边界声明**：
   - 本文档仅为 V001 实施计划方案，**尚未编写构建脚本、未修改任何模型或运行源码、未宣称上述压缩比、视觉指标与性能门限已实测达成**；一切实测数据均以获批后 `V0–V5` 实际执行与双浏览器采样凭证为准。
