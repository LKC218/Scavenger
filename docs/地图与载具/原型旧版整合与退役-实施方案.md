## 旧服务如何停止

1. 执行前重新读取维护登记与进程情况，逐个核对8792／8793的监听PID、进程创建时间、完整命令行及`/api/status`。必须分别为`scavenger-defense`的V001／V002和本次记录的源码身份；PID仅为快照，不能直接复用旧PID。
2. 与原负责会话完成旧版制作和测试消费者交接，确认没有仍需运行的旧版对局或测试；有持续使用则暂缓该版本。保存服务清单、资源路由、源码身份和日志；不操作工程师的浏览器窗口。
3. 先把验证脚本的默认依赖改为8794并检查，再停止旧服务。现有服务没有HTTP停止接口，使用PowerShell `Stop-Process -Id 已复核PID`逐个停止已确认的独立Python服务；不按进程名称批量结束，不递归结束进程树。
4. 每停一个就确认对应端口不再监听，8794仍返回V003且源码摘要不变；统一库及其他服务继续运行。身份不符或端口被其他程序占用时停止本轮操作，不接管。
5. 停服后才迁移旧目录中的保留文件，随后由原负责会话按下节结束对应保护。本轮不会替其他会话关闭保护，也不通过空闲状态推定任务结束。

注意：旧服务是在脚本的历史版本运行时启动的。当前`预览丧尸防线.py --port 8792`会提供V003，不能当作V001恢复命令。必要回滚须使用已冻结的旧版服务清单、路由和源码身份恢复，不能只照抄旧进程命令行。归档映射、旧服务资源清单和运行源码保持完整，直至迁移及V003检查闭合。
