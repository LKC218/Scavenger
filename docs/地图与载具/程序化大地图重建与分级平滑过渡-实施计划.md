### 1.2 现行渲染表现与切换的两大体验瓶颈

1. **植被外观瓶颈**（详见 [植被替身.mjs](../../src/地图验证/植被替身.mjs) 与 [全图显示.mjs](../../src/地图验证/全图显示.mjs#L224-L263)）：
   * **全细节树名额过小**：受单棵原生高模面数限制，近景真实 3D 树上限仅 **48 棵（`span < 180` 时 96 棵）** 且受 `900,000` 总面数熔断限制，大量中近景树提前降级为 2D 广告牌替身。
   * **替身无动态光影与视差**：替身采用无光照 `MeshBasicMaterial` + 固定 `color_scale` 近似烘焙，关闭投影与接影（`castShadow = receiveShadow = false`），在 `48°` 俯视角下旋转镜头时易显“扁平纸片跟随旋转”，与周边真 3D 载具/建筑脱节。
   * **近景草丛全省略**：当前关闭 6 类草丛后近景地面细节偏裸露。
   * **远景树木清零**：在 `view.span >= 500` 模式下直接置 `stats.visibleTrees = 0`，拉远镜头时大片森林突然消失，地形瞬间变秃。
2. **远中近切换不顺畅根因**（详见 [全图显示.mjs](../../src/地图验证/全图显示.mjs#L155-L186) 与 [景别过渡.mjs](../../src/战术演训/景别过渡.mjs)）：
   * **`span = 500` 排他性清场**：跨越 `500m` 时系统先调用 `showOverview()` 并清空当前所有详情区块与批次（`removeBatches()`），再异步请求并构建目标层；即便有 `120ms` 全局 8×8 Bayer 淡变，仍存在“先撤旧→等待加载→整屏集体抖动弹出”的断档感。
   * **全屏单一 `sceneLevel` 一刀切**：当前全屏所有建筑共享同一个 `near / middle / far` 级别，未按物体到相机距离实现连续交叉溶解。
   * **跨级色差**：近景贴图、远景简模与总览底图在光照响应和色温上缺少统一标定。

## 二、 路线 B 核心技术架构设计

总体设计原则：**“源参数与模块库分离（可随时修改）、地形与草丛程序化生成（极低体积）、建筑与物理自动派生（改模型不穿帮）、远中近连续常驻与距离抖动过渡（零闪屏顺滑缩放）、发布态 HTTP Range 单包归档（浏览器秒开）”**。

### 2.1 目标体积与性能预算（硬指标）

以下预算为路线 B 预研工程与网页交付的**必须达标门限**（沿用 [Airbase全图与场景资产双层入库计划](../Airbase全图与场景资产双层入库-实施计划.md) 的严谨口径，实测分列**传输字节 / 编码响应体 / 唯一内容字节**）：

| 考核维度 | 现行基线（revision 7） | 路线 B 目标预算 | 优化幅度 / 说明 |
| :--- | ---: | ---: | :--- |
| **整图运行包全集** | `1,034.22 MiB`（28,404 文件） | **≤ 90 MiB**（开发散文件 / **1–3 个归档包**） | **缩减 ≥ 91%**（目标区间 `45–85 MiB`），彻底消除 2.8 万小文件同步瓶颈 |
| **首屏冷启动传输** | 地图 `14.45 MiB` / 全依赖 `19.81 MiB` | **地图 ≤ 6 MiB** / **全依赖 ≤ 12 MiB** | 含代码、解码器、默认 30 载具与必需音效 |
| **20 Mbps / 80 ms 冷启动** | `13.37–13.49 秒` | **≤ 6.0 秒可操作**（总览反馈 **≤ 1.5 秒**） | 温启动 **≤ 2.0 秒** |
| **帧时间（640×364 主验）** | P95 `5.1–6.6 ms`（100 混编） | **平均 ≥ 60 FPS，P95 ≤ 16.67 ms，P99 ≤ 25 ms** | 长帧（>33.3 ms）比例 `< 0.1%`，预热外最长帧 `≤ 100 ms` |
| **帧时间（1080p 高分选测）** | 未纳主测 | **空场/100 单位平均 ≥ 60 FPS，P95 ≤ 16.67 ms** | 专门校验树叶 AlphaClip 与 Splatmap 多层采样的像素填充率极限 |
| **显存与解码驻留** | 纹理 ≤ 256 / 几何 ≤ 192 / 模拟 ≤ 64 MiB | **纹理 ≤ 160 MiB / 几何 ≤ 128 MiB / 模拟 ≤ 48 MiB** | JS 堆 `≤ 384 MiB`，5 圈 180 秒回访存活资源增长 `≤ 3%` |
| **高度与通行精度** | 三角形回读 P95 ≤ 0.05m | **主地面 P95 ≤ 0.05m，最大 ≤ 0.12m**；桥梁/多层误差 **≤ 0.02m** | 道路、机场跑道平面误差 **≤ 0.01m** |

### 2.2 模块一：程序化地形、Splatmap 与道路系统（替代 534.64 MiB 地表切片）

1. **共享网格池 + GPU 顶点高程位移（0 地形 `.glb` 下载）**：
   * 在浏览器端建立固定规格的**棋盘格几何体对象池（`PlaneGeometry` Pool）**，围绕相机采用多级同心环（如 `64×64`、`32×32`、`16×16` 顶点分段），外缘统一添加**向下裙边（Skirt）**或边缘顶点对齐，消除不同分辨率区块之间的 T 型接缝裂纹。
   * 顶点着色器直接采样**16-bit 量化分块高度图纹理**，在 GPU 完成 `position.y` 位移与平滑法线重算。
2. **混合高程与物理支撑（替代 206.30 MiB 双份三角形页）**：
   * 9km × 9km 基础地形采用 **2 米步距 `uint16` 分块高度图**（4501×4501 采样，按 250m 分块存储并做 Delta + Zstd/PNG16 压缩，全图约 **10–16 MiB**；高程分辨率 `< 0.01m`）。
   * 对机场跑道、道路坡肩、陡坎和**立交桥/高架桥等立体多层区域**，保留局部 `0.5m` 细化高度掩码或独立 3D 桥面支撑补丁（预计 `< 4 MiB`），同时保留 `querySupport` 的多支撑层提示，确保不把桥面覆盖掉桥下通道。
3. **动态 Splatmap + `WebGL2 DataTextureArray` 着色（替代 402.42 MiB 烘焙贴图）**：
   * 将原 12 类地表基础纹理（草地、泥土、沥青、水泥、砂石、农田等）精简重组为 **8–12 层可无缝平铺的主材质（Albedo + 法线/粗糙度，打包为 `512×512` KTX2 TextureArray，总量仅 3–6 MiB）**。
   * 全图使用紧凑的 **分块或金字塔压缩权重图（Splatmap，每个 250m 或 1km 区一张低分 KTX2/PNG 索引+权重，全图 6–12 MiB）**。
   * 片元着色器采用 **“最多取权重最高的前 3~4 层混合 + 随机哈希旋转防重复平铺（Stochastic Tiling）+ 坡度/高度程序化微调”**，将每次像素采样纹理次数控制在 `≤ 4` 次，兼顾高近景清晰度与 1080p 帧率。
4. **道路中心线样条化（替代 21.35 MiB 道面大网格）**：
   * 将道路、滑行道与标线描述为**中心线控制点样条 + 宽度 + 路面材质编码 + 交叉口标记（`roads.bin/.json`，预计 0.5–1.5 MiB）**。
   * 加载区块或编辑器改路时，由 Web Worker / 运行时自动生成平滑贴地路面带状几何与标线 UV，并同步写入**高度贴合修饰（Road Flattening）**与**地形 Splatmap 路基权重**，彻底告别“改一条路重烘一整片地”的痛点。

### 2.3 模块二：植被外观重塑与全距离生态体系（目标 1 核心）

彻底抛弃现行“48 棵数万面原高模 + 无光平片纸片 + 500m 森林消失”的割裂方案，建立**四层立体生态体系（总运行体积控制在 6–12 MiB 以内）**：

1. **近景档（0 – ~320m）：定制 RTS 球形法线低模蓬松树**
   * 制作 **6–8 种**风格统一的乔木与灌木模型（单棵严格控制在 **250 – 650 三角面**）：低模圆柱树干 + 多向交叉的**蓬松叶片簇卡片**。
   * **核心美术工艺（决定外观是否自然的关键）**：
     * 在建模导出阶段将所有树叶顶点的法线重写为**以树冠中心向外辐射的球形/半球法线（Spherical/Spherized Normals）**，彻底消除交叉面片在光影下的“黑十字接缝”。
     * 采用**高紧致包裹轮廓的多边形卡片 + `alphaTest` 硬裁切**（而非大块透明正方形面片），尽量减少空白透明像素，控制 `1080p` 下的 Overdraw。
     * 开启**真实实时阴影投射（`castShadow = true`）与受光阴影（`receiveShadow = true`）**，并在顶点着色器加入基于世界坐标相位的低成本**微风顶点摆动**。
   * 因为单棵仅 ~450 面，通过 `InstancedMesh`（按种类合批，共 6–8 次 Draw Call）即可在**近景视口同屏真 3D 渲染 1,500–3,000 棵树**，将 90 万面限制变为真正覆盖全视口的森林。
2. **中景过渡档（~250m – ~900m）：受光立体交叉/八面体冠层代理**
   * 不再使用无光照的 `MeshBasicMaterial` 单平面转向广告牌；改为极低面（**20–48 面**）的**十字/三叉立体蓬松块或烘焙带法线贴图（Normal-Mapped）的受光八面体代理**，保留实时方向光漫反射与高度渐变（树冠顶部亮、底部偏暗），消除转向纸片感。
3. **远景与总览档（> 600m 至全图 9km）：常驻集群林冠壳（Forest Canopy Clusters）**
   * 在预处理阶段，根据树木分布图把成片森林聚合为**贴合地形起伏的立体低模集群冠层块（或高度场附加林冠凸起层，全图总计约 2–5 万面，仅 1–2 MiB）**，与近景树共享同一套线性色彩空间校准值。
   * 拉远到 `span >= 500m` 直至 `9000m` 全图总览时，**大片森林依然饱满、有明暗朝向与体量感**，绝不会凭空消失。
4. **近景草丛与地表碎石回归（几乎 0 额外包体）**：
   * 不保存 609 万格密度数据；直接在相机周围 `0 – 150m` 范围内，根据地形 Splatmap 的草地通道权重 + 道路/建筑遮罩，用 GPU `InstancedMesh`（如固定 8,000–16,000 簇环形滑动缓冲池，每帧根据相机移动重定位网格格点位置）现场绘制 3–4 簇交叉草叶与风动效果，并随镜头升高平滑缩小沉降消失。全图仅需 **1 张 `512×512` 草丛图集（< 250 KB）**，同时在设置中保留高/中/关三档以适配不同显卡。

### 2.4 模块三：零真空、距离驱动的平滑切换架构（目标 2 核心）

1. **废除 `span >= 500` 的清场跳变，实现“远景底盘常驻 + 局部细节叠加”**：
   * 得益于路线 B 全图静态体积被压缩到百兆以内，启动时将**全图 16-bit 粗高度（~1 MiB）、远景集群林冠（~1.5 MiB）、道路主干与全图建筑远景简模底座（~4–6 MiB）常驻内存/显存**。
   * 镜头从 `70m` 拉远到 `9000m` 或高速横移时，**永远不撤回总览清空批次**，画面底层始终 100% 连贯；近景只负责在镜头当前周围环带流式激活或休眠高细节区块/模块。
2. **将“全屏统一淡入”升级为“距离驱动 8×8 Bayer 连续溶解（Distance Cross-Fade）”**：
   * 保留 [景别过渡.mjs](../../src/战术演训/景别过渡.mjs) 中已验证无帧间闪烁的固定 **8×8 Bayer 屏幕空间阈值矩阵**，但把触发源从“全屏共用一个 120ms 计时器”改为**在着色器中按“实例/区块到相机焦点的水平距离（或屏幕空间像素高度）”直接计算 `fade` 权重**：
     * 例如定义近→中过渡环 `[R_near_start, R_near_end]`（带 ±15% 滞回保护）：在该环带内，近景树/建筑 `coverage` 从 `1.0 → 0.0` 连续递减抖动消隐，同时同坐标的中景/远景代理 `coverage` 从 `0.0 → 1.0` 同步抖动浮现；
     * 建筑、树木、草丛、地形各自拥有独立的平滑过渡半径，缩放时呈现如波浪般自然的“局部精细化/简化”过程，不再出现整屏同时换模的突兀感。
3. **跨级视觉一致性锁定（防色差跳变）**：
   * 所有远、中、近三层模型与地形共用统一的线性色彩空间（`LinearSRGBColorSpace`）与材质光照响应曲线，预处理阶段自动以**近景模型五方向 WebGL 渲染平均亮度与色度**反向校准中远景代理与林冠颜色（延续并升级项目既有 [植被替身.mjs](../../src/地图验证/植被替身.mjs#L46-L53) 的有界色阶校准经验）。

### 2.5 模块四：模块化建筑库、可调整工作流与自动碰撞/寻路派生（目标 3 核心）

1. **“共享模块库 + 轻量场景清单 + 手工覆盖层”三层数据结构**：
   * **标准原型/构件库（`assets/map-kit/`）**：按**固定战略地标**（机场塔台、主跑道群、大型机库等）与**通用可复用模块**（民用楼栋、厂房仓库、围墙护栏、路灯道具等）组织，共约 **35–60 个核心 GLB**。
     * 所有模型启用 **位置 14-bit / 法线与 UV 10-bit 量化 + Meshopt 压缩 + 共享纹理图集（Atlas KTX2，底色用 ETC1S、法线/遮罩用 UASTC）**，整套原型库控制在 **15 – 30 MiB**（近+中两级合并封装或单源自动减面，远景低像素建筑直接复用统一简模盒与平均色，不再存 `48.63 MiB` 独立远景 `.glb`）。
   * **可编辑地图工程清单（`scene-source.json` / 分块描述，约 2–5 MiB）**：
     * 存储：地形高程/权重图引用、矢量道路样条、程序化林区/街区生成规则（区域多边形 + 密度 + 随机种子）、以及**手工精确实例与修改覆盖表（Manual Instances & Override List）**。
     * **手工覆盖优先机制**：任何被人工拖动、删除、替换的建筑或森林局部区域，都会写入 Override 掩码，程序化生成器自动避让该区，彻底避免“改全局规则破坏手工精修区”的隐患。
2. **两条互不冲突的“调整地图物品”工作流**：
   * **工作流 A（Blender + 增量编译器，B3 阶段初期即交付）**：在精简后的 Blender 模板工程中以集合实例引用模块化 GLB 库调整建筑与道具摆放，或直接替换库内某个 `.glb`；运行一键增量编译脚本，**仅重编码变更原型或受影响区域的 250m 分块（数十秒完成）**。
   * **工作流 B（浏览器内轻量地图编辑器模式，B3 阶段后期交付）**：在独立候选预览页内置 `?mode=editor` 开关，支持：
     * 点选/框选现有建筑、树木与道具，进行移动（自动贴合当地地形高度）、旋转、缩放、替换原型 ID 或删除；
     * 从侧栏资产面板拖拽新建筑/掩体/路灯放入地图；
     * 使用笔刷调整局部地形高度或涂抹 Splatmap（水泥/草地/泥地），以及拖拽道路样条控制点；
     * 一键导出更新后的 `scene-source.json`（及修改的权重/高度增量图）和对应运行分块数据。
3. **自动派生碰撞、寻路与飞行包络（关键防坑闭环）**：
   * 每次修改或新增建筑/植被/道路后，编译管线（以及浏览器编辑器的本地导出/实时更新逻辑）**自动从模型实测几何提取旋转凸包/复合盒碰撞（BACO）、更新受影响 125m 格的 4 米局部寻路阻塞网格与 125m 粗通行成本，并重新计算直升机 30m 越障所用的局部顶高安全包络**，彻底消除“改了楼却隐形撞墙/坦克穿墙/直升机撞树顶”的隐患。

### 2.6 模块五：二进制索引与单文件 HTTP Range 流式打包（快速打开核心）

1. **二进制紧凑网格索引（替代 4.94 MiB `地图运行.json`）**：
   * 72×72（5,184 格）区块是否存在、包围盒高程极值、数据偏移与长度全部编码为定长二进制头部索引（约 **64 – 128 KB**），启动解析耗时由数十毫秒降至 `< 2 ms`。
2. **开发散文件 / 发布单包双模式**：
   * **开发调试模式**：直接按目录读取独立区块文件，改完任意模型或区块立即可刷新验证。
   * **发布归档模式（参考 `PMTiles` 思路）**：将全图按空间 Morton（Z 序）曲线合并打包为 **1–3 个静态归档包**（例如：① `base-startup.scvmap` 约 `6–10 MiB` 供首屏秒开与远景常驻；② `terrain-tiles.scvmap` 约 `18–30 MiB` 存分块高度、Splatmap 与局部物理；③ `kit-assets.scvmap` 约 `15–30 MiB` 存量化模块化模型与图集），支持标准 `HTTP Range: bytes=start-end` 按需请求与静态 CDN 强缓存。

## 三、 运行时契约兼容与接口边界

为保证未来能低成本与现行 [战术演训模块](../../src/战术演训/README.md)（G01 载具移动、直升机离地 30m 越障、固定翼安全空域）及后续 `G02–G08` 尸群战斗衔接，路线 B 的新地图运行时（建议独立建于未来批准后的 `src/程序化地图/` 模块）**必须严格兼容以下已有接口语义**：

| 契约接口 | 路线 B 实现方式 | 兼容要求 |
| :--- | :--- | :--- |
| `bounds` / `center` / `safeAltitude` | 读取场景清单冻结边界与实测全图最高模型/地形顶高 | 与现行米制转换 `(x - 4425, y - 136, 4850 - z)` 及 `9km×9km` 一致 |
| `heightAt(x, z)` / `querySupport(x, z)` | 主地面从内存驻留的 16-bit 量化高度图做双线性插值；道路样条与桥梁补丁做局部优先叠加 | 已知空洞/页外返回 `NaN` / `unsupported`，未加载区域返回 `pending`，不填 0 高度 |
| `collisionsIn(bounds)` / `supportSegment(a, b)` | 读取自动派生的旋转建筑凸包/复合盒、树干胶囊与路面/桥梁 3D 支撑射线求交 | 保证弹丸拦截与尸群绕障与现行规则一致 |
| `prepareRegion(owner, bounds)` / `releaseRegion(owner)` | 沿用显示与模拟分别持有租约、LRU 有界缓存、并发队列限制（下载 4 / 解码 2） | 镜头快速拉走时不解除在途单位与命令所在区域的精细模拟租约 |
| `update(view)` / `visibleGroundMeshes()` / `dispose()` | 驱动 GPU 地形池、距离抖动参数、近景草丛跟随池及严格释放所有几何/纹理/Worker | 支持双浏览器多轮次往返无显存泄漏 |
