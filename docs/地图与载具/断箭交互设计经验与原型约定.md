## V003迁移与证据边界

本轮按工程师最新要求研究公开视频，不再启动原作试玩。两段飞行ACV教学的完整字幕时间线、关键连续画面与未核实项见[审阅记录](../../research/断箭/交互音效研究/V003-01a1a2af/视频审阅记录.json)。不能将完整解码称为逐帧人工观看，也不能把2025年教学等同于本机较新构建的全部行为。

V003接入核心选择、落点朝向预览、队列与攻击反馈，以及三车原表允许的移动射击、M230水平射界和现有建筑视线。已通过镜头保持不变。原图标和音效复用、规则重新实现、网页适配参数分别记录，详见[模块说明](../../src/载具靶场/README.md)。下文早期“停车／悬停、手选武器”约定保留历史语境；防线V003已按工程师新确认采用上述规则，8768仍为旧对照。

官方手册与视频共同支持“取消当前命令”和“关闭自动交火”是不同动作。浏览器快捷键冲突也需独立处理：原作Ctrl数字编组保留兼容，网页推荐Shift数字保存、Alt数字调用。右键拖拽朝向精确语义尚未在本轮视频确认，因此标为本项目适配。固定翼扫射和轰炸保持不同任务，暂不加入飞机侦察、燃料、返航补给及原作完整HUD。

## 四、本轮已确认的五条交战规则

确认依据：工程师对上一版方案末尾五项选择回复“全部A”。

| 编号 | 规则 | 对后续实现的约束 |
| --- | --- | --- |
| 规则一 | 射程外指定攻击时，自动接近有效射程后开火 | 需要接近过程、预计停止位置和明确失败反馈，不能瞬移或忽略武器射程 |
| 规则二 | 指定攻击或Q攻击移动才触发交战 | 闲置和普通移动均不主动搜索靶标开火；Q模式才进行沿途自动交战 |
| 规则三 | 视线被挡时停下并提示，由玩家重新选位 | 首轮不自动寻找其他射击位置，也不把隔墙射击当作正常命中 |
| 规则四 | AH-64D由玩家选择机炮或导弹 | 依据当前选择使用相应武器和射程，不静默改用另一种武器 |
| 规则五 | 移动途中收到攻击命令，停车或悬停后瞄准开火 | 不把移动射击带入首轮；射程外接近时仍需先移动，到达后再稳定和瞄准 |

### 配套边界处理建议

1. 将“绕过阻挡行驶的障碍”和“寻找无遮挡射击位置”分别处理：前者属于已确认的基本导航，后者首轮不自动执行。
2. 建议先检查当前武器和目标是否适配，再计算射程外的接近路径；进入射程后的射界被挡时，进入受阻等待并提示。接近时机与遮挡检查优先级需在操作样例中验证。
3. 没有可达停止点时明确提示不可达；不要无限重算路径、贴住障碍持续抖动，或偷偷切换武器缩短接近距离。
4. 多单位接受同一命令后各自执行：受阻坦克不阻止其他满足条件的直升机开火；面板汇总可执行数量及受阻原因。
5. 取消和换目标应使旧的瞄准、待发射任务失效；已发射弹丸独立完成飞行，不凭空收回。具体取消边界属于实现前待验证项。

## 五、操作入口与命令生命周期建议

以下为本项目配套操作设计。鼠标上下文命令沿用已确认范围；当前已实现并完成下文标注的浏览器检查，主观点击手感仍待试玩。

### 选择与镜头

| 输入 | 建议动作 | 必须能看懂的反馈 |
| --- | --- | --- |
| 左键点选、拖动框选 | 建立单个或多个单位的选择集合 | 单位标记、数量与面板一致 |
| Shift加选择 | 添加或移除选择 | 集合变更后即时更新数量和卡片 |
| 单位卡片或Tab | 在原选择集合内切换当前命令接收对象 | 显示子选择，避免误以为仍对全部单位下令 |
| 预设编组按钮 | 选择坦克组、直升机组或全部 | 显示组名与成员；自定义编组快捷键后续适配 |
| WASD、滚轮、中键拖动 | 平移、缩放、旋转镜头 | 限制缩放距离，提供恢复默认视角入口 |

### 命令入口

| 输入 | 建议行为 | 条件与结束方式 |
| --- | --- | --- |
| 右键地面 | 普通移动 | 地面和空中分别分配落点，显示已求得的路径；不主动开火 |
| 右键靶标 | 指定目标攻击 | 遵守五条已确认规则；建议持续到靶标销毁，然后执行队列下一项 |
| Q加左键地面 | 攻击移动 | 沿途对有效靶标交战；建议交战结束后继续原移动目标，受阻时明确提示 |
| R加左键地面 | 坦克倒车 | 混选时明确标注仅对坦克执行及适用数量，不静默忽略其他单位 |
| 攻击地面按钮或G加左键 | 对选定位置射击 | 建议一轮后结束，仍检查选定武器、射程和射界；G是本项目候选键位 |

Shift追加命令；普通新命令建议替换现有队列。E建议取消当前及排队命令，Esc只退出尚未提交的指令预览。二者不能共用模糊的“取消”提示。浏览器失焦、输入框焦点和UI覆盖下的按键与鼠标行为需单独验证。

H仅还击暂缓：当前靶标不反击，无法有效验证还击条件。道路快速移动、变高度、返航补给、烟幕和反制等也不因参考游戏存在就自动纳入原型。

### 一次指定攻击的推荐流程

```text
选择单位 → 指定靶标 → 校验当前武器与目标
                     ├─ 射程外：沿可达路径接近
                     └─ 进入射程：停车或悬停 → 检查射界与朝向 → 瞄准 → 发射
                                                └─ 受阻：停下并显示原因
发射后：弹丸独立飞行 → 碰撞判定 → 命中反馈
        武器独立装填 → 满足条件时进行下一次射击
```

不能等弹丸命中后才开始装填。瞄准、装填和弹丸飞行分别保存状态；换选不会使已提交命令消失。普通取消命令也不等于长期关闭武器或禁止将来交战。

## 六、两类载具的攻击差异

| 方面 | M1A2 | AH-64D |
| --- | --- | --- |
| 移动过程 | 地面绕行、车体转向和减速停车 | 固定高度移动、减速和悬停 |
| 瞄准表现 | 炮塔转向与允许范围内的炮管俯仰 | 机身朝向与机炮转向分别满足当前武器约束 |
| 首轮攻击 | 主炮单发、装填、可见弹丸及命中 | 机炮短点射与一种导弹分别验证 |
| 程序动作建议 | 炮塔、炮管及后坐 | 旋翼、机身姿态及可动武器 |

武器分别配置射程、瞄准时间、连发节奏和装填。当前主炮射程52、装填3.2秒，机炮射程43、间隔0.3秒，导弹射程74、装填6秒，均为游戏化参数。机炮仅程序俯仰，水平方向由机身对准；导弹采用简化自主追踪，挂点依据源外侧挂架；完整水平射界和真实制导动力学未实现。

## 七、把执行原因呈现给玩家

| 状态类别 | 建议显示 | 验证重点 |
| --- | --- | --- |
| 选择与预览 | 当前接收者、落点、预计朝向、待提交提示 | 预览不会提前改变真实单位状态 |
| 移动与队列 | 已求得路径、终点、队列序号、接近攻击位置 | 无寻路结果时，关联直线不能冒充可达路径 |
| 攻击准备 | 转向中、停车或悬停中、瞄准进度、装填进度 | 玩家能区分等待原因，避免反复点击 |
| 无法执行 | 超出射程、视线遮挡、不可达、武器不可用 | 文字或图标说明，兼容单位分别执行 |
| 战斗结果 | 发射、命中、伤害、靶标销毁 | 效果与声音来自真实战斗事件，不由按钮点击假触发 |

清晰UI与低分辨率三维画面分别处理。选择标记和指令预览在烟尘、障碍遮挡及镜头缩放下仍需可辨；拾取按实际显示区域换算，不因画面像素化而使点击粗糙。UI操作不能向战场透传命令。

## 八、静态资产接入的可复用经验

1. 先在派生副本检查炮塔、炮管、旋翼是否具有独立几何、正确轴向和枢轴。节点名称或空对象层级不能证明能驱动可见网格；程序新建动作要注明来源。
2. 先确定可动部件和声音挂点，再减面或合并。统一优化流程，按车型和战术镜头检查轮廓，不使用全库固定减面百分比，也不把各型号归一为相同尺寸。
3. 同型号共享几何、材质和纹理，单位分别保存位置、命令和武器状态。减少绘制像素不能自动解决三角形、材质切换或模拟开销。
4. 移动、发射、命中声音由对应状态变化触发，遵守声音并发和停止规则；当前有限事件WAV不能直接视为无缝循环或完整转速混音。
5. 模型与音效正式库只读，研究目录不成为游戏运行时依赖。真实尺度、挂点、可动动作、浏览器播放和设备帧率分别验收；资产进入运行目录前另行确认来源与使用范围。

## 十一、已确认的镜头手感约定

工程师试玩反馈为平移、缩放和旋转生硬，随后确认：默认便于阅读3至5辆车的局部战斗，滚轮拉远总览；选择移动中的单位保持当前视角，只有主动聚焦才移动。此处的3至5辆是阅读目标，单位密集时不限制可见数量。

本项目采用正交投影、约49.7°俯角与96默认视野跨度，缩放范围58至180。WASD归一化输入、短加速和快速停稳；滚轮以鼠标指向的地面位置为锚点；中键灵敏度0.004弧度／显示像素并加少量平滑。C和按钮对当前命令接收者做一次位置快照聚焦，Tab子选择只聚焦该单位，不自动跟随，不下达游戏命令。

《断箭》提供指挥操作参考，《RESTAND》的视频提供近景与总览切换的观察方向；本项目尚未测得RESTAND的精确投影、俯角、缩放锚点或平滑曲线。当前数值来自原型调试，不写成任一参考游戏的官方参数。完整响应时间、交互验证和边界见[镜头交互优化验证](../../reports/载具靶场/镜头交互优化验证.md)。

## 十二、已确认的城市与固定翼阶段

工程师已试玩确认镜头通过，追加1200米城市演训、A-10C与100单位主验、200／500探索；之前“固定翼后置”的约定是首轮范围，当前按[新阶段计划](../城市固定翼原型-实施计划.md)执行。

《断箭》[官方手册](https://ftp.matrixgames.com/pub/BrokenArrow/BrokenArrowManualEBOOK.pdf)印刷第20页提供固定翼扫射／轰炸拖线确定航向的参考。[2026年7月2日官方周年更新](https://steamcommunity.com/games/1604270/announcements/detail/671746950739004897)补充机炮、火箭和空地导弹可直接点目标自动执行攻击，扫射命令仍用于未知或疑似位置。两者反映不同版本，不只照搬旧手册。不据此推断RESTAND也采用相同固定翼输入：现有RESTAND视频证据不足以还原其完整固定翼流程。

本原型采用右键目标单次机炮攻击，K拖线扫射、B拖线轰炸，以起点到终点给方向、以中点给轰炸目标区；预览给方向箭头与落区，过短航线拒绝。K／B为本项目快捷键，B不是原作返基地。Shift追加任务，完成脱离后执行；E取消任务与队列后盘旋，不悬停、不回收已发弹药。点选、下令不抢镜头，C仍只聚焦一次。

固定翼不使用直升机的停车／悬停射击逻辑。持续前进、有限转弯、足够长的进场、前向射界、非制导普通炸弹和任务反馈分别实现。安全高度、速度、转率、弹道伤害与缓冲范围均为项目游戏化值；机场、起降、燃料与防空另阶段验证。音量默认70%、战术监听点、8引擎／48总声部与末端限幅用于控制大量实例混音。

测试将静态、持续移动和恢复靶持续交战分开。恢复靶位于开阔区域，记录单位总数、入画中心数、实际模拟、发声和持续发射量；不将这组负载冒称为复杂城市战斗。结果和限制见[可视化报告](../../reports/载具靶场/城市固定翼与性能验证.html)。
