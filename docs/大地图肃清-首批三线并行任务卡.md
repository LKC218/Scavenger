## 二 三张执行卡

### A 交互与指挥

目标：让玩家看得清、选得准、下令明确。

- 范围：按已确认镜头与空地规则制作G01；接入G04武器和命令界面，不重新设计伤害规则。
- 交付：交互模块、短操作表、地面／直升机／固定翼样本；测试替身与真实运行连接分别注明。
- 依赖：主对话提供公共入口与单位约定，C提供可用命令和实时状态；早期可用明确标记的受控样本。
- 开工前补齐：键鼠操作、镜头边界、反馈样式、高度参数、样本型号与可改文件。

人工重点：

- [ ] 缩放、旋转、聚焦／跟随舒适，手动平移退出跟随。
- [ ] 地空重叠、不同高度下点选／框选准确；标签、卡片、筛选与循环可用。
- [ ] 空中目的地对应地面落点；直升机高度切换、固定翼到点盘旋清楚。
- [ ] 武器／弹种确由玩家选择，范围预览与实际规则一致，隐藏敌人不能被锁定。

### B 表现与性能

目标：优先保证大群观感和稳定帧率，再补足战斗视听。

- 范围：只使用G00登记的断箭丧尸候选；近处低模个体、远处廉价替身；四类动作错相位；死亡、群声及G04表现。
- 交付：分档画面对照、表现模块与素材来源表；区分已有素材、缺项、需另批提取或制作的内容。
- 依赖：C提供行为、存活和战斗结果，A提供镜头条件；早期受控动画基准不能代替真实行为验收。
- 开工前补齐：外观组合、数量档、分级距离、尸体／残骸／音源／特效预算及测量条件。

人工重点：

- [ ] 四类动作可辨、群体不整齐同步，近远切换不漏画、不重画。
- [ ] 死亡动作与适量血液清楚，尸体／残骸限时限量，烟尘不长期遮挡指挥。
- [ ] 命中／爆炸按弹药类别可辨；迷雾群声只提示粗方位。
- [ ] 在约定规模和镜头下观感可接受；对照Chrome／Edge持续帧时间及长帧记录，性能结论绑定测试条件。

### C 规则与结算

目标：保证尸群行为、弹药、命中和损失只有一套有效结果。

- 范围：先提供G01样本移动、高度切换和盘旋状态，再完成G03尸群行为，分段接入G04武器、弹丸与结算；不扩展特殊丧尸、全车型或完整任务经济。
- 交付：规则模块、武器／弹药来源对照、可复现交战样本和边界检查；原作值、网页候选值、人工接受值分开。
- 依赖：主对话锁定时间、单位、障碍与资源约定；A提交命令，B读取结果。
- 开工前补齐：声源／搜索／接触伤害、武器样本、弹种、射程、弹量、装填与伤害参数。

人工重点：

- [ ] 游荡、诱导、近地面目标优先、搜索返回和绕障符合总纲，跨区不丢归属。
- [ ] 各武器有限弹药、独立装填与禁用正确；已核实的并行开火条件生效。
- [ ] 弹丸撞墙；爆炸按距衰减且可隔墙伤害；对地盲射不变成锁定隐藏目标。
- [ ] 连续命中、群体死亡和载具损失只结算一次；拉远、静音和减少特效不改变结果。

## 三 汇总前统一的约定

以下是职责约定，具体字段和函数在开工包中补齐，不代表接口已经实现。

| 交接内容 | 约定 |
| --- | --- |
| 玩家命令 | 镜头、选择和界面状态由A处理；移动、攻击等玩法意图交C检查并执行，界面不直接扣弹、扣血或判死 |
| 规则真值 | C维护载具位置、移动与高度状态，以及真实数量、归属、弹药、耐久及战斗结果；一个命令只执行一次 |
| 画面与声音 | B读取状态与结果；动画完成、声音停止或粒子消失不能触发第二次伤害 |
| 单位身份 | 使用稳定逻辑ID并区分本轮模拟；合批索引不是单位ID，重开后旧事件失效 |
| 时间与坐标 | 共用一套模拟时间、世界尺度与地面坐标约定；屏幕机身选取与地面下令分清，模型朝向先核对 |
| 事件交接 | 包含本轮身份、顺序、时间、相关单位、位置和结果；具体格式从简，由主对话统一 |
| 远近分级 | 只降低表现或更新成本；不改人数、归属、伤害、声音响应，画外战斗持续运行 |
| 敌情权限 | 玩家可见内容、选取、锁定和听感遵守视野／听觉规则；盲射提交地面坐标，不提交隐藏目标 |
| 声音与吸引 | C独立产生玩法声源；B的静音、音源裁剪不能关闭尸群听觉，群声不擅自增加连锁引怪机制 |

爆炸按距衰减是伤害规则，不等于增加定距引爆；引爆和制导条件按具体弹药核实。优先复用现有能力，不建设通用大框架。

## 四 并行开发与汇总顺序

1. **开工包先齐。** 主对话列明接口、参数候选、样本、文件归属、隔离方式与人工条件，工程师可一次批准整批，也可只批准其中一部分。
2. **三线同时推进。** A做G01，B做G02，C做G03规则；G03视听由B承接。用受控样本降低等待，明确哪些尚未接通。
3. **尽早汇总小样。** 主对话先接一辆地面车、一款核实武器／弹药和普通尸群，跑通“命令→结算→表现”，随后补齐G04批准的检查范围。
4. **逐目标人工验。** G01交互与G02基准可先交；G03验真实行为和视听，G04再验实际开火声源、伤害与死亡连接。单个小样通过不代表整项目标通过。
5. **组合再验。** 同一候选中操作、诱导、开火、撞墙、伤害、死亡与远近分级同时运行，核对无重复结算、无敌情泄露，并复测负载。首批通过后进入G05逐车。

各线小步交付，主对话持续集成，避免三份大改最后拼接。某条线受阻时，其依赖项保持待验，其他已批准且独立的工作可继续。

## 五 文件保护与交付

- 主对话独占公共入口、运行循环、共用配置和总文档；A／B／C各有文件白名单。需要改他线文件时先协调，由负责人修改，禁止覆盖式合并整个目录。
- 代码采用隔离目录或分支，具体路径先列入开工包；目前项目未启用Git，本卡不执行初始化。大资源共享只读引用，不复制整库，不改原件。
- 开工前复核[基线与资源问题清单](大地图肃清-基线与资源问题清单.md)：统一库revision7、Airbase地图r14／源码r17、Walker／Runner独立r03候选。身份变化先报告影响，不静默换资源；待验／待修继续保留。
- 各线和集成／服务分别登记读写依赖、独立任务名与输出版本。转交后再结束本线保护，不解除其他会话保护。
- 功能可并行开发；正式性能测试排队进行，暂停其他高负载任务。固定电脑键鼠、Chrome和Edge，先定数量、镜头、画质、指标和时长，记录整帧P95、长帧及必要的GPU成本。
- 最终交付一个固定集成候选入口，附版本身份、短步骤、逐目标清单、已知问题和复验范围；子线演示入口只作辅助，不分别宣称主线通过。

完整人工清单以[开发目标与人工验收](大地图肃清-开发目标与人工验收.md)为准；本卡不缩减G01—G04要求。旧原型和素材继续保护，本轮没有退役或缓存清理范围。
