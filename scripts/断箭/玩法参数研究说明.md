# 玩法参数研究说明

## 职责与输入

[研究三车参数.py](研究三车参数.py)只读既有快照和规则源码，整理M1A2、AH-64D、A-10C参数并生成文档。它不启动原游戏，不读取安装目录，不提取新媒体，不修改模型、声音或游戏玩法。

输入为001批次`证据/装配/源配置核验.json`、`装配映射.json`，003批次`证据/原生方法地址索引.json`，以及当前`src/载具靶场/模拟.mjs`和`飞行.mjs`。五份输入前后核对SHA256，输出保存项目相对路径。原始数据库只选取三款固定配装关联的表行，不复制原始密钥、私人路径或整个数据库。

## 关系限定

固定单位245、19、282及对应模型ID，复用已选选项和挂架槽；子炮塔必须在该单位的TurretUnits中关联到活动父炮塔。武器来自活动炮塔的TurretWeapons或该单位SquadWeapons；弹药要求UnitId、WeaponId同时匹配且Quantity为正。

机动和装甲优先选项覆盖，其次唯一默认，最后唯一关联；不唯一时停止，不按名字相似度猜选。M1A2使用选项597、机动1、装甲198；AH-64D使用141及139、机动7；A-10C使用2056、816、811、1923、机动131和飞行预设8。挂架数量与关系Quantity分别保留，不宣称已确定整机备弹。

## 命令与依赖

```powershell
python -X utf8 -B scripts/断箭/研究三车参数.py
python -X utf8 -B scripts/断箭/研究三车参数.py --verify
python -X utf8 -B scripts/断箭/研究三车参数.py --verify-page
```

默认和`--verify`依赖Python标准库、已有Node.js。Node通过参数列表加载无DOM的真实规则导出，生成当前WEAPONS与FLIGHT，不复制一份手写当前值。地面与旋翼速度从明确源码表达式读取，表达式结构变化时停止并要求重新核对。

`--verify-page`额外使用已安装Playwright和Chrome／Edge；串行启动独立无窗口实例，不控制工程师已打开的页面。页面模板为[三车参数报告模板.html](三车参数报告模板.html)，所有数据内嵌，不依赖CDN。报告使用原生SVG与DOM更新，不依赖游戏模块。

## 输出与验收

研究文档、原始JSON、当前JSON和建议JSON位于[第一版研究目录](../../research/断箭/三车对丧尸研究/第一版-01a1a2af/README.md)；可视化输出位于[第一版报告](../../reports/断箭/三车对丧尸参数研究-第一版-01a1a2af.html)。本地生成回执、数据复核、桌面及390窄屏截图、页面检查位于`local-data/断箭/玩法研究/三车对丧尸-V001-01a1a2af/`。

核验涵盖三车身份、12条数量为正的弹药关系、五份输入身份、重复生成一致性、三车切换、衰减演算、链接、无外部请求、窄屏和打印。仅证明研究数据与页面；不是原作算法还原、游戏战斗实现、60 FPS或工程师平衡验收。

本模块只通过离线Node读取靶场规则导出，形成研究脚本到规则文件的单向工具依赖。靶场和丧尸运行模块不反向读取研究资料，不引入运行时耦合。规则改版时建立新研究版本并重新冻结输入。
