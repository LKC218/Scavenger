# 重复文件依赖审计

## 用途与范围

[审计重复文件依赖.py](审计重复文件依赖.py)只读排查上一阶段盘点的1605份相同内容文件，复核旧文件和正式保留副本的字节及SHA256，输出引用来源与删除候选。不扫描新增未知资产，不执行删除，也不修改其他任务、旧版本或提取证据。

从项目根目录运行，Python 3.11及以上标准库即可：

```powershell
python -B scripts/断箭/审计重复文件依赖.py --output local-data/断箭/维护/重复文件依赖排查/审计001
```

输出必须位于专属审计目录，且为未使用的新目录。重跑时改用新的序号，保留已有清单。输入为`local-data/断箭/维护/模型音效资料整理/重复文件保留清单.json`，当前正式媒体以资料库当前版本为准。

## 依赖判定

扫描源码、维护脚本、文档、研究报告、断箭批次元数据、原型本地路由和临时文本。JSON及CSV解析绝对或相对路径，结合所在目录及明确的输出目录字段；其他文本匹配完整路径线索。目录引用保护其下的候选文件。路径匹配是保守判断，不证明调用一定执行。

项目根目录显式扫描README、AGENTS、当前“打开前线资产库.cmd”和载具靶场快捷文件；资产库快捷入口统一后，审计跟随当前唯一入口，不依赖已退役的兼容文件。

| 判定 | 含义 |
| --- | --- |
| `active_protected` | 载具靶场源码、私有路由或输入记录仍引用，保护其他对话使用范围 |
| `retain_referenced` | 旧快照、历史核验、维护源码或文档仍存在引用，保留并列明来源 |
| `manual_review` | 未发现显式引用，但摘要、二进制依赖、证据范围或扫描异常尚未排除 |
| `safe_candidate` | 本轮摘要相同、没有发现引用，且不在上述保留范围内的WAV候选 |

不解析Blender二进制内部依赖或穷尽动态拼接路径，因此未发现引用的模型、图像不会自动列为安全候选。无法解析的文本和扫描中的变更均记录；存在这些情况时，无引用文件也不自动放行。自己的盘点及审计输出不作为消费者，避免清单互相引用导致错误保留。

## 输出与复核

- `依赖审计.json`：逐文件路径、字节、摘要、正式副本和全部引用字段。
- `文件依赖清单.csv`：便于搜索筛选的完整清单。
- `可安全删除候选.json`：仅包含本轮通过保守判断的候选，可能为空。
- `扫描来源与异常.json`：扫描文本指纹、异常、并发变化及排除范围。
- `清单指纹.json`：上述四份输出的摘要。

精确本机路径仅写入被忽略的本地维护目录。清单只反映扫描时点，不表示删除授权；后续删除前必须重新核对活动任务、引用和文件摘要。不得通过改写历史核验或其他对话的路由来制造无引用结果。

后续退役设计见[旧版本退役与引用迁移方案](../../docs/资源与资料库/旧版本退役与引用迁移-实施方案.md)。工程师已批准阶段一至四。显式传入`--archive-manifest 对照清单`时，审计会核对相符的隔离核验回执、每项来源指纹与字段、当前引用集合及正式副本，满足条件才标记`archive_ready`；活动任务引用仍优先保护。未传入参数时保持原有保守判定。见[归档工具说明](旧版资料归档说明.md)。
