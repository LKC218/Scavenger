# 旧版资料归档说明

## 职责与边界

归档工具按工程师批准的[实施方案](../../docs/资源与资料库/旧版本退役与引用迁移-实施方案.md)完成阶段一至四：刷新保护范围、建立映射、隔离验证和生成精确候选。阶段工具不删除媒体；另行批准冻结清单后才使用独立删除执行器，不重写提取证据、历史快照或其他对话路由。

| 源码 | 职责 |
| --- | --- |
| [历史资源解析.py](历史资源解析.py) | 校验原记录摘要及具体JSON键、字段、CSV单元格或文本线索，显式读取同摘要正式副本 |
| [退役旧版资料.py](退役旧版资料.py) | 维护阶段基线、映射、消费者台账、隔离演练和冻结候选 |
| [核验归档工程.py](核验归档工程.py) | 在独立后台Blender只读检查正式工程的未打包图像、链接库、缓存等依赖 |
| [审计重复文件依赖.py](审计重复文件依赖.py) | 重新扫描引用，逐项验证归档映射覆盖，保护新增活动引用 |
| [删除已批准重复文件.py](删除已批准重复文件.py) | 仅接受当前已批准956份清单的固定SHA256，整批预检后逐文件删除，复核保留资源并保存回执 |

仅使用Python 3.11及以上标准库；工程检查使用本地配置中已有Blender，不安装工具，不连接游戏或声卡。归档解析是显式模式，不改变正式库默认查询和HTTP白名单。

## 阶段命令

先生成新的引用审计，再使用未占用的阶段目录；以下序号为格式示例，已有目录不可重跑覆盖。

```powershell
python -B scripts/断箭/审计重复文件依赖.py --output local-data/断箭/维护/重复文件依赖排查/新审计目录
python -B scripts/断箭/退役旧版资料.py prepare --run local-data/断箭/维护/旧版退役与引用迁移/新阶段目录 --audit local-data/断箭/维护/重复文件依赖排查/新审计目录
python -B scripts/断箭/退役旧版资料.py verify --run local-data/断箭/维护/旧版退役与引用迁移/新阶段目录
python -B scripts/断箭/审计重复文件依赖.py --output local-data/断箭/维护/重复文件依赖排查/最终审计目录 --archive-manifest local-data/断箭/维护/旧版退役与引用迁移/新阶段目录/迁移对照清单.json
python -B scripts/断箭/退役旧版资料.py candidates --run local-data/断箭/维护/旧版退役与引用迁移/新阶段目录 --audit local-data/断箭/维护/重复文件依赖排查/最终审计目录
```

prepare冻结全批次及版本文件，保留639份原始导出、尝试和证据媒体，并刷新原型源码及本地输入中的精确路径。发现新增活动引用就扩大保护；其他任务界面变化只读记录，不恢复成旧基线。无法证明不影响候选的新引用阻止清单生成。

verify执行五类错误拒绝检查、后台Blender外部依赖检查和独立进程回读。独立进程使用Python文件打开审计钩子禁止读取候选旧路径，先验证禁止机制，再从正式保留副本回读；真实文件不改名、不移动。结束时复核原始证据、当前索引和保护项，并检查正式服务与004归档样例媒体路由。

审计新增`archive_ready`状态：原引用仍存在，但已通过精确字段、来源指纹、替代摘要及隔离回读验证。活动任务引用优先保护，不因归档映射而放行。扫描忽略自身维护记录和tmp内历史无头浏览器配置缓存；UTF-8失败的普通日志可尝试GB18030，其他异常仍报告并阻止归档放行。

## 已迁移入口与历史脚本

- `核验音效交付.py --batch 批次 --archive-manifest 对照清单`：只读验证该批次的已映射媒体，不覆盖原验收文件。输出明确标记为归档载荷完整性，不重跑FMOD、字段链、视觉或听审。
- `预览音效索引.py --batch BA-26273833-004 --archive-manifest 对照清单`：保留原路由JSON，显式解析映射中的媒体；未映射的受保护模型仍从保留原路径读取，HTTP边界及Range行为不变。
- 其他历史生成、导出和旧副本校验命令，在本地消费者台账逐项登记。归档回读接替其旧载荷完整性复核；原脚本和当时结果保留，不宣称删除后仍可按原路径运行。原始重提取流程不属于本阶段。

回读已有阶段可运行`退役旧版资料.py replay --run 阶段目录`；它仅更新本阶段的回读轨迹，不更新任何原始验收。正式运行继续使用[正式资料库](../../src/资料库/README.md)；共享音频运行时和其他对话源码保持原样。

删除后回读应增加`--report 阶段目录/删除执行001/新回读报告.json`，新报告须位于原阶段内且不存在，避免覆盖旧的核验证据。

## 批准后的逐文件删除

工程师已批准阶段002冻结清单。执行器只接受该清单的956份媒体、7,374,624,439字节和固定SHA256，不能用它扩展其他删除任务。从根目录运行：

```powershell
python -B scripts/断箭/删除已批准重复文件.py --run local-data/断箭/维护/旧版退役与引用迁移/阶段002 --audit local-data/断箭/维护/重复文件依赖排查/最新审计目录 --manifest-sha 816e7e61e40249dec0048995ffca11be53b055538e8b6169338963d1e26ddfe8
```

先刷新引用审计；可加`--refresh-from 上次审计目录`，重建全部文件列表并校验全部文本来源摘要，仅对内容未变文件复用逐字段解析结果，新文件及变化文件重新扫描。旧副本和正式目标的媒体摘要仍重新核对；活动记录补扫，不以缓存跳过保护验证。

执行器整批核对原文件、保留目标、全部历史基线、来源摘要和活动引用，检查绝对路径及父目录无符号链接或目录联接。通过后才逐文件`unlink`，每50份刷新活动引用及保护摘要，每个文件重新核对身份、内容与正式副本；不删除目录。预检失败时不执行删除，运行中失败时停止并保存部分回执，不默认重试或扩大范围。

完成后，仅允许批准路径缺失；其他7570份历史基线、10份保护资源、635份正式媒体及原快照保持摘要一致。回读956份归档媒体，检查历史预览、正式服务范围请求和Agent检索，回执写入`阶段002/删除执行001/`。该目录已有记录时拒绝再次执行；不要重复删除或覆盖回执。

## 清单与验收

精确本机路径全部保存在被忽略的本地阶段目录：

| 输出 | 内容 |
| --- | --- |
| `迁移对照清单.json` | 原媒体、正式副本、引用来源摘要及精确字段 |
| `证据保护基线.json`、`保留清单.json` | 原始载荷、版本、活动资源的保护依据 |
| `引用消费者台账.json`、`归档版本登记.json` | 显式归档入口、历史命令和旧版本的状态 |
| `隔离核验.json`、`隔离回读轨迹.json`及工程、错误拒绝、并行复核记录 | 实际验证范围、真实读取位置和限制 |
| `精确删除清单.json`、`精确删除清单.csv`、`暂缓与保留清单.json`、`清单指纹.json` | 等待独立删除批准的逐文件清单及摘要 |

冻结清单记录生成时的状态，删除完成以独立执行回执为准，不改写旧清单中的历史状态。后续若正式版本、来源记录、保护范围或任何文件摘要变化，应重新审计并生成新阶段，不能扩大已冻结清单。

956份已经执行完成，回执及逐文件结果位于本地阶段002的`删除执行001/`。原1605份盘点现为历史基线，其中956份旧路径缺失是批准退役结果，不应将旧盘点直接当作正式库缺失清单。日常核验使用`核验正式资料库.py`，历史载荷使用显式归档回读；下一轮去重应独立制定新基线，禁止重跑本次删除清单。
