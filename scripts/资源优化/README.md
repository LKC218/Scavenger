# 整库资源优化

## 当前维护入口

当前运行资源已经迁入`local-data/资源库/`，日常入口见[统一资源维护](../资源库/README.md)。`查询网页资源库.py`、`恢复归档资源.py`、游戏版服务和浏览器验证均优先统一库；旧整库编码与混合历史归档入口已退役。`生成游戏版.mjs`从统一原件／装配源恢复输入，写到待入库，不回写旧目录。当前仅保留256默认、256远景、512回退，骨骼保留完整拓扑的两档贴图。

下文227来源、1354规格、旧运行开关、旧源码锁及旧归档路径是上一轮历史流程，不代表日常维护入口；旧报告保留当时数据，不再用旧实验入口重新生成当前资源。新库发布后的功能验证请运行`python -X utf8 -B scripts/资源库/维护资源库.py verify`。

## 游戏版256及512

`生成游戏版.mjs`只读227份已盘点唯一GLB，在`local-data/网页资源库/游戏版第一版/`生成两档完整几何和静态细节层；骨骼、动作与变形模型保留拓扑。可编辑Blender源工程继续保留，不以静态减面覆盖工程。音效复用第一版已验证派生，不重复编码。

主体底色上限256或512，遮蔽上限128，保留颜色空间、透明与Mip链；移除法线及金属粗糙度贴图，用原图蓝／绿通道均值乘原材质系数代替金属度／粗糙度。512回退只提高底色精度；完整材质回退仍使用全库第一版。

执行顺序：`node scripts/资源优化/生成游戏版.mjs`；`node scripts/资源优化/核验游戏版结构.mjs`；分别运行`python -X utf8 -B scripts/资源优化/核验游戏版.py --browser chrome`和`--browser msedge`。两个浏览器逐版本核验后，再运行`验证游戏靶场.py`的画面对照及`--network`，最后`验证游戏版负载.py`及`生成游戏版报告.py`。这些命令均从项目根目录执行。

`核验游戏版结构.mjs`逐属性核对两档完整几何，并复核全部原始GLB摘要。浏览器脚本检查1354个版本的结构、全部骨骼顶点五时点采样、两档距离轮廓和颜色；自动阈值不等于主观验收。实际靶场对照覆盖640／480、视野58／96、两档朝向与动作，保留原相机、光照和阴影代码。

`游戏版服务.py --app catalog --open`打开新模型库；`--app range --open`打开256及几何层1靶场，可加`--resolution 512`或`--level 0/2`。服务只绑定127.0.0.1，端口随机选择20000至54999且检查占用，避免浏览器禁用端口；不重启其他服务。靶场将源码按摘要冻结至本地目录。

主入口运行覆盖由`local-data/网页资源库/运行接入.json`控制：`game_enabled`开启游戏版，`game_resolution`默认256，`game_level`默认1。每项必须有两浏览器技术与视觉回执且摘要一致，否则逐项回退其他已通过游戏层或全库第一版。骨骼模型使用几何层0。关闭`game_enabled`并重启对应服务可回退原保真压缩版；512版本与完整材质版各自保留，不改正式源索引。已启动服务缓存清单，设置变更不会改变其他会话正在运行的服务。

冷加载测量采用新浏览器上下文、禁用HTTP缓存、CDP 10／50 Mbps及40毫秒延迟，分别3次取中位数。计时到`range.ready`，包括页面、引擎和模型，不包括用户点击解锁后加载的音效；不代表公网或进程／系统完全冷启动。公开部署还需另行制定缓存、传输压缩与资源使用范围。

本流水线不删除文件；版本退役接入[统一清理规则](../../docs/版本退役与缓存清理规则.md)及[维护清理工具](../维护清理/README.md)。后续会话每轮另建任务并核对`status --task`，交付报告旧版清单、缓存登记及暂缓原因；工程师确认具体新版后由负责会话登记`accept`，无依赖后自动进入七天回收并到期复核清除。当前运行派生、仍有用途的材质回退版和必要归档继续保护，未审核存量不自动接管。游戏版生成成功不能替代最终验收或清单确认。

本模块只读输入，派生和验证写入`local-data/网页资源库/全库第一版/`，冷归档写入`local-data/资源归档/全库第一版/`。不执行删除。

## 执行

依次运行`python -X utf8 -B scripts/资源优化/整库流水线.py inventory`、`process`、`archive`。工具依赖在`local-data/tools/网页资源优化/1/`的锁文件中固定；运行需要Node、Sharp、glTF Transform、meshoptimizer、ktx2-encoder、FFmpeg。

`整库流水线.py`按摘要去重、维护正式ID映射、批量编码声音、ZIP64归档和逐条解压摘要核验。`模型批处理.mjs`生成KTX2与Meshopt GLB，不改节点命名、几何拓扑、蒙皮和动画；结构回读失败不会记为通过。贴图上限1024，线性贴图UASTC，颜色ETC1S，带Mip链；压缩贴图仍需浏览器和视觉验证。

音效Opus 96kbps可变码率，保留声道、时长与原始混音增益，完整解码检查。不把有损编码当作听感验收；压缩不能降低AudioBuffer解码后内存。原始静音或模型待修状态不因编码成功而升级。

盘点包括历史重复和可编辑工程。归档去重存储原件，路径映射保留每个原路径；归档压缩和解压摘要校验完成前，任何原件不可删除。活动入口与正式库保持原状，优化库接入另用独立清单。

## 全量验证与交付

| 脚本 | 职责 |
| --- | --- |
| `核验全部音频.py`、`修正音频峰值.py` | 全部素材解码、时间与RMS比较；Opus新增峰值越界时转无损FLAC，不降低整库响度 |
| `生成细节层.mjs` | 静态模型候选细节层；`--repair`收紧不达标层的误差，`--fallback`用于仍无法减面的资源复用基础层 |
| `浏览器整库核验.py` | `--browser chrome`或`msedge`，全量基础层和细节层加载、同镜头图像对照、真实骨骼顶点采样及全部音效解码 |
| `固实归档.py` | 用固定7zip-bin创建固实7z，完整解包所有唯一文件并逐一核对摘要；保留ZIP与恢复临时副本等待清理审批 |
| `恢复归档资源.py`、`核验归档恢复.py` | 按路径映射恢复原件，验证格式与Blender读取；默认写临时目录，`--original`显式恢复原位置且拒绝覆盖不同内容 |
| `运行资源接入.py`、`核验运行接入.py` | 在内存清单接入验证通过的派生；真实三页面回归，可选`--performance`进行双浏览器各180秒100单位有声交战 |
| `查询网页资源库.py` | `--id model:US_M1A2`或`--hash`查询运行派生、源摘要与全部别名；正式资料仍优先用原正式CLI查询 |
| `生成整库报告.py`、`核验整库报告.py` | 重核原件摘要，生成离线报告和精确删除候选；双浏览器断网验证表格、筛选、390窄屏和打印，无删除功能 |

基础层验证使用完整几何、动作采样器和蒙皮摘要；三角形循环排列归一后比较，节点变换容差1e-5。浏览器轮廓比较使用白色覆盖材质，避免把贴图明暗变化误判为几何轮廓变化；图像颜色另以原材质前景平均误差检查。视觉阈值不是人工签收。

原ZIP分包和固实7z都保留在项目内；仅当固实格式更小且完整恢复核验通过时，报告选择它为当前归档，并记录`当前归档.json`。历史冷源（含唯一文件）的删除候选必须有可恢复归档条目；当前正式资源、原型依赖和丧尸工程继续原位保护。清单区分冷源、重复件、被替代ZIP、验证临时副本和旧音频候选，审批前一律不删。

运行开关为`local-data/网页资源库/运行接入.json`的`enabled`。关闭后重启服务即可回到原始资源；开关和派生都在本地忽略目录，不改正式版本指针。服务进程缓存本轮验证后的派生映射，新增或改变资源后需重启。固定Basis转码器需要动态JavaScript生成，当前CSP仅适用于回环验证工具，公开部署应重新制定策略。

执行浏览器性能核验时，服务将实际提供的源码和运行清单复制到本轮HTTP快照后再提供给两个浏览器，避免其他会话改源码造成混合版本。早期混合源码采样仅保留为排障记录，不进入最终性能表。清理审批清单会扫描现存资源路由及原型基线清单，保护独立音效实验和并行任务使用的原路径；历史冷源需要恢复后再供旧维护脚本使用。

游戏派生查询：`python -X utf8 -B scripts/资源优化/查询网页资源库.py --id model:US_M1A2 --game`，可加`--resolution 512`和`--level 0/2`；保留源摘要、质量状态，并返回游戏路径、字节、三角形与双浏览器回执状态。

`核验游戏版交付.py`最后检查主预览服务确实覆盖三款游戏模型，双浏览器载具选择、声音加载与增益正确，并断网验证报告227行、搜索、390宽和打印；不会重启旧服务。

归档工程回读工具的Blender路径通过`--blender`、`BLENDER_EXE`或已忽略的`local-data/网页资源库/归档验证工具.json`设置，正式脚本不保存本机安装绝对路径。

独立游戏预览固定`验证源码锁.json`登记的本轮渐变接触阴影源码。其他会话新增实时阴影实验期间不覆盖该快照；主入口的新进程仍使用实时工作区源码，因此独立预览的性能结论不外推后续阴影改动。
