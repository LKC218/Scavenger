## 检查

### 统一日常入口

统一入口支持下表六条日常用例。第三阶段试运行默认自动登记本轮读写范围，省略 `--run-id` 即生成独立运行 ID。需要人工审看或把结果交给其他消费者时，从开跑时就加 `--retain`：

```powershell
python -X utf8 -B scripts/战术演训/运行日常测试.py --list
python -X utf8 -B scripts/战术演训/运行日常测试.py --case move-v3
python -X utf8 -B scripts/战术演训/运行日常测试.py --case labels-v3 --channel msedge --retain
python -X utf8 -B scripts/战术演训/运行日常测试.py --observation
```

| 用例 | 服务端口 | 浏览器 |
| --- | --- | --- |
| `move-v3`、`labels-v3` | 8813 | 移动选 Edge 或 Chrome；标签可串行 `both` |
| `move-v2`、`altitude-v2` | 8812 | 移动选 Edge 或 Chrome；高度可串行 `both` |
| `move-v1` | 8811 | Edge 或 Chrome |
| `name-8784` | 8784 | 固定串行 Chrome、Edge，不接受单浏览器选项 |

入口使用现有[清理工具](../维护清理/README.md)的 `protect → enroll → close`，只管理本轮独立任务。先保护输出、脚本、候选指针和运行依赖，再按对应指针补齐地图与冻结源码保护，之后才运行浏览器。它在运行前后只读核对现有服务版本、地图和进程；身份不符即失败，不启动、重启或改写服务。默认无窗口，除命名外默认 Edge。

每轮在成功时只留一份 `结果摘要.json`。失败时摘要列出诊断路径；每个失败浏览器最多一张关键图和一份日志，服务预检或浏览器启动失败则只有摘要和日志。失败日志上限32KiB；截图失败仍保留原异常。终端打印检查数、文件数、总字节数、摘要路径和实际登记状态。原检查失败返回非零；测试通过但登记交接失败也返回非零。产物完成即冻结，最终登记状态以终端和清理工具 `status --task` 为准，登记后不回写摘要。

确认退出后，只把本轮可重跑的产物登记缓存；现有定时 `tick` 按闲置七天回收、回收七天复核清除。入口不执行 `tick` 或删除，不处理旧存量。`--retain` 保持本轮任务活动、无缓存条目；复核及消费者完成后，由负责人确认读写状态后手工处理，观察命令不会替其关闭。登记锁占用、冻结文件变化或流程中断时报告具体任务，不自动重试或解除保护；如需回退，先手工登记读写范围，再选 `--manual-registration` 或原直接 `--routine` 命令。

试运行期间用 `--observation` 核对累计文件数、字节数、未交接任务和未归类产物。它只短期保护并读取本入口已登记的范围，不清理，也不生成额外报告文件。按 `America/Los_Angeles` 连续三个工作日（周一至周五）至少五条记录且无异常后，再作为推荐用法；见[实施计划](../../docs/地图与载具/战术演训日常测试-产物留存实施计划.md)。

执行中断或超时只对本次测试派生的进程及浏览器收尾，摘要记录 `cleanup_confirmed`；为 `false` 时须保留任务保护并人工核对，不得关闭登记。进程核对优先用当前 Python 的 `psutil`，缺少时复用已保留的 `local-data/tools/python-unity/Lib/site-packages`；没有可用版本时直接报错，不安装依赖。8784 日常复用调用独立的 `只读核对演训入口.py --check-only`，核对快捷文件身份和现有服务，不执行快捷文件。原启动器受旧候选摘要保护，因此其字节和正式 `--start` 均保留；新开关不传给旧快捷文件。并发运行必须使用不同 ID；同 ID 只允许一个任务创建目录，其他运行报错且不覆盖文件。

离线边界检查可执行 `python -X utf8 -B scripts/战术演训/验证日常运行边界.py --sandbox tmp/运行/战术演训日常测试/本轮边界夹具`。登记及七天验证可执行 `python -X utf8 -B scripts/战术演训/验证日常登记.py --sandbox tmp/运行/战术演训日常测试/本轮登记夹具`。两者只使用自建隔离目录及进程，不触碰游戏或旧回收批次。原 `--routine` 直跑方式、正式验收和单项补证命令保留。

规则专项核对编队、队列、停止、固定翼、精确终点及异步失败隔离。交互脚本用实际鼠标和键盘检查演训候选，并记录公开状态、源码身份与截图；不启动或终止服务。默认无窗口，`--headed`才允许可见测试窗口。两个浏览器串行执行，不抢工程师正在使用的桌面浏览器。

日常浏览器测试显式加 `--routine`，通过只留一份摘要，失败追加一张关键截图（页面还可截图时）和 `失败日志.txt`。每次提供一个尚不存在的输出子目录。

```powershell
python -X utf8 -B scripts/战术演训/验证标签版移动交互.py --channel msedge --routine --output-dir tmp/运行/战术演训移动回归/本轮独立目录
python -X utf8 -B scripts/战术演训/验证镜头版移动交互.py --channel msedge --routine --output-dir tmp/运行/战术演训日常测试/本轮独立目录
```

推广范围：8811 的 `验证移动交互.py`、8812 的 `验证镜头版移动交互.py` 与 `验证高度与镜头.py`、8813 的 `验证标签与过渡.py`，以及 8784 的 [验证战术演训原型命名.py](../验证战术演训原型命名.py)。这些脚本的日常输出放在 `tmp/运行/战术演训日常测试/` 下；原试点 `验证标签版移动交互.py` 继续使用上例中的目录。命名验证仍用 `--output`，日常档无窗口；双浏览器专项共用一份汇总，失败图与日志按浏览器归放。高度、标签专项仍需提供本次冻结摘要；标签的 `--map-command-only` 只用于完整证据补采，不与 `--routine` 混用。

日常档保持同一组判定。端口、浏览器启动或取图失败时，以日志定位。先登记本轮读写范围；无需继续使用的已登记产物按[清理规则](../../docs/版本退役与缓存清理规则.md)交接。不传 `--routine` 时，正式验收的命令、输出目录和证据要求沿用原约定。
