# 维护清理工具

仅使用Python 3.11及以上标准库，从项目根目录运行。规则见[版本退役与缓存清理规则](../../docs/版本退役与缓存清理规则.md)。工程师已批准启用后续自动退役和缓存维护；旧存量、旧登记和旧回收回执不自动接管。Windows Restart Manager查询失败或发现占用时保持保护，不结束任何进程。

## 后续任务的自动流程

1. 新任务开始前运行`protect`登记全部读写路径。任务创建时间须晚于自动策略启用时间；旧任务及未知目录不因本次启用而解除保护。每轮制作使用独立任务名和版本输出路径。
2. 缓存生成后用`enroll --kind cache --note 可重新生成的方法`冻结具体文件。启用时已存在的路径拒绝自动登记；目录里后来出现的文件也不会继承批准。持续变化的缓存不要提前登记，完成写入后再登记。
3. 新版准备好后，用`stage`冻结具体旧文件、新版文件、验收凭证和依赖核查说明，向工程师展示版本、范围、摘要和验收结果。此时不能退役旧版。
4. 只有工程师明确确认该具体新版通过，才运行`accept`，引用实际确认依据。技术检查通过、全局启用授权和聊天空闲都不能代替具体新版验收。
5. 所属任务明确停止使用后运行`close`。每日`tick`检查任务、当前通过版、凭证、冻结文件和占用；无依赖的已验收旧版回收，缓存还须连续七天未使用。
6. 回收逐文件满604800秒后，`tick`重新检查并永久清除。七天内仍占磁盘，可显式恢复；恢复会暂停该条目的自动退役，避免下一次又被回收。

```powershell
# 示例路径须换成真实制作输出；这些命令由任务负责的Agent执行
python -X utf8 -B scripts/维护清理/清理工具.py protect --task 某资源第二轮 --path local-data/制作/某资源 --path tmp/某资源第二轮
python -X utf8 -B scripts/维护清理/清理工具.py enroll --task 某资源第二轮 --kind cache --path tmp/某资源第二轮 --note 可重新运行该轮导出脚本生成
python -X utf8 -B scripts/维护清理/清理工具.py stage --task 某资源第二轮 --asset model:资源ID --version V002 --path local-data/制作/某资源/V001.blend --replacement local-data/制作/某资源/V002.blend --evidence local-data/制作/某资源/V002验收记录.md --note 引用及其他任务依赖已按验收记录核查
# 工程师确认上述具体版本与范围后执行，摘要取stage实际输出
python -X utf8 -B scripts/维护清理/清理工具.py accept --manifest 待确认清单的项目相对路径 --approved-sha 该清单实际摘要 --note 工程师实际确认消息及对应版本
python -X utf8 -B scripts/维护清理/清理工具.py close --task 某资源第二轮 --note 任务明确结束且全部读写依赖已迁移
```

多份旧文件或新版文件重复传入`--path`或`--replacement`。历史旧文件必须逐项指定，不接受整目录。源码、文档、JSON索引和原件凭证不属于通用历史载荷。当前统一库的服务保护继续有效，发布模块必须先完成引用迁移，不能为放行清理关闭仍有用途的保护。

对于完整的丧尸群体候选发布目录，可在`stage`命令显式增加`--release-bundle`。该开关只接受`local-data/丧尸模型/发布/ZOM-SHARE-YYMMDD-NNN/`内的逐文件路径，用于正式版已经接管全部交付和证据后，退役整个重复候选目录中的源码、文档与JSON。普通历史载荷仍执行原扩展名白名单；该模式同样要求冻结完整SHA-256清单、依赖审查和工程师针对清单摘要的确认，回收后仍保留七天。不得用它处理项目源码、`src/`、`scripts/`或正式资料库目录。

启用时的未知目录保护保持原登记；仅在策略授权的精确文件内细化：缓存必须来自启用后的新任务且不在存量边界中，历史文件必须属于新任务并经具体新版验收。新增或修改的未知保护、任何明确活动保护始终阻止清理。工具不推断未登记的第三方读取关系，依赖核查仍由制作任务完成并留证。

当前通过版按资源稳定ID保护。连续验收后，退役检查沿已确认的版本后继关系核对当前通过版；每版必要凭证保留，不要求永久保留每代被替代的大文件。

已登记缓存5GiB、该策略回收区10GiB为初始容量警戒线。只报告超限，不提前清除未到期文件，不扩大到未登记缓存。范围或文件发生变化须重新核查、登记，定时任务不得自行重写快照。

## 日常入口

### 当前策略回执的显式漏标修复

手动调用`quarantine`回收当前自动策略已批准条目时，同样继承该策略身份并执行占用检查，后续每日`tick`才能按原回收时间复核七天清除。不同策略或旧登记不能混入同一回执。

对于本工具此前生成、条目本身已有当前策略授权但回执漏写策略标记的情况，可显式使用`repair-receipt --manifest 回执路径 --approved-sha 修复前回执摘要 --note 原批准与修复依据`。命令在锁内核对实际注册条目、具体验收链、任务结束、冻结文件集合、原路径及回收载荷身份；只补齐策略标记，不改变`created`、逐文件`moved_at`、文件内容或七天期限。旧登记、其他策略、启用前回执、已恢复或中断回执均拒绝处理，定时任务不自动接管漏标回执。

### 跨会话只读核对

```powershell
python -X utf8 -B scripts/维护清理/清理工具.py status
python -X utf8 -B scripts/维护清理/清理工具.py status --task 本轮独立任务名
```

开始新轮次时先查策略，登记保护后核对本轮任务；交付或结束前再次核对。输出包含任务是否具备后续登记资格、缓存及退役条目数、待工程师确认清单和暂停条目数。没有条目可能表示尚未登记或本轮无需退役，必须由负责会话对照实际产物说明原因；不能把查询成功或条目数为0当成完整合规证明。

`status`不扫描制作目录、不计算全部资源摘要、不运行`tick`、不确认验收、不改变任务登记或历史回执。启用前的任务名继续保护；旧会话做新轮次须另建任务名，不能直接复用旧任务接管存量。所有会话的交付清单和确认后的登记责任见项目根`AGENTS.md`。

```powershell
python -X utf8 -B scripts/维护清理/清理工具.py init
python -X utf8 -B scripts/维护清理/清理工具.py inventory
python -X utf8 -B scripts/维护清理/清理工具.py preview
python -X utf8 -B scripts/维护清理/清理工具.py tick
```

`init`只能首次运行，已有登记拒绝覆盖。登记、预览、存量审核和回收位于已忽略的`local-data/维护清理/`；`inventory`无执行能力，不对22GB历史载荷进行无必要的全量哈希。`preview`只为已登记且准入的文件计算摘要。没有登记的旧缓存维持保护。

## 任务占用与缓存登记

```powershell
python -X utf8 -B scripts/维护清理/清理工具.py protect --task 示例任务 --path tmp/示例任务
python -X utf8 -B scripts/维护清理/清理工具.py enroll --task 示例任务 --kind cache --path tmp/示例任务 --note 可重新运行本任务生成
python -X utf8 -B scripts/维护清理/清理工具.py close --task 示例任务 --note 已完成核验且没有服务或其他任务继续使用
```

`protect`重新激活同名任务时合并保护路径并保留最初创建时间；任务读写路径都必须登记，没有自动到期解除。现有`tmp/`整组状态不明保护不直接关闭；后续策略仅在前文规定的准确授权文件内细化原样未知保护，其余范围继续保护。任何明确活动保护、新增或变化的未知保护与候选重叠均阻止回收。

## 历史版本登记

以下为旧手动审核模式的证据契约。自动策略启用后，历史退役使用上面的`stage`和`accept`，不能用旧`enroll --kind history`绕过具体验收。原契约要求证据包含：

```json
{
  "accepted_version": "经确认的新版本标识",
  "accepted_by": "工程师",
  "dependency_review": "依赖检查报告及工程师确认依据",
  "replacement": {"path": "替代文件的项目相对路径", "bytes": 0, "mtime_ns": 0, "sha256": "实际摘要"},
  "evidence": {"path": "验收证据的项目相对路径", "bytes": 0, "mtime_ns": 0, "sha256": "实际摘要"}
}
```

这是登记契约，不会替代模块自身的视觉、听审或引用审计。必须完成这些检查并保留真实记录后填写；工具核对替代件和证据身份，拒绝把它们一同清理。正式资料库、原件、冷归档及工具目录由专项流程维护，通用工具拒绝登记。不要复制旧的删除清单或随意填写验收状态。

## 批准后回收、恢复与永久清除

```powershell
python -X utf8 -B scripts/维护清理/清理工具.py quarantine --manifest 预览清单的项目相对路径 --approved-sha 工程师批准的清单摘要
python -X utf8 -B scripts/维护清理/清理工具.py restore --manifest 回收回执的项目相对路径
python -X utf8 -B scripts/维护清理/清理工具.py purge --manifest 回收回执的项目相对路径 --approved-sha 工程师批准的回执摘要
```

回收使用同项目文件重命名，七天内可恢复；不立即释放磁盘。永久清除只逐文件执行，不删除目录。清单或登记变化、源文件变化、链接/目录联接、活动保护、未到期回收均拒绝。源目录有新文件时，新文件不会继承旧清单的批准。中断回执保留意图和已完成文件，需人工核对，不自动重试。

## 定时任务与启用门槛

每日04:00的Codex自动任务调用`tick`，本地时区为`America/Los_Angeles`。工程师已批准后续自动维护；由`enable-auto --approved-sha 当前登记摘要 --note 工程师批准依据`一次性冻结启用存量边界并建立策略。`first_review`保持原值，不把它改成全部存量审核通过。定时任务只能调用`tick`，不能启用策略、登记新范围、确认验收、解除保护或接管旧回执。

策略与边界见本地`登记.json`及`自动维护/启用存量边界.json`，待确认版本在`验收待确认/`，当前验收头及确认依据保存在登记中。最近一次自动结果固定写入`自动维护/最近执行结果.json`，无变化不重复写入。电脑休眠或应用未运行时不保证准点；恢复后按实际时间戳检查，不缩短七天期限。

定时预览采用固定位置且状态无变化不重复写入；手动预览独立保存供审批。工具执行锁是排他创建的文件，锁存在则失败退出，不自动解除疑似残留锁。任务登记与清理共用锁；外部任务需按项目协作规则先登记再使用文件。

### 本机系统级定时维护与只读体检（`audit`）

结合[项目轻量化与定时清理规范](../../docs/项目轻量化与定时清理规范.md)，新增两个入口（不修改原有七天保护与授权边界）：

```powershell
# 只读防堆积体检（检查僵尸active任务、tmp未登记大目录、>=50MB JSON、多代修订目录）
python -X utf8 -B scripts/维护清理/清理工具.py audit
python -X utf8 -B scripts/维护清理/清理工具.py audit --no-write

# 立即运行一次「tick + audit」，或注册/查看/卸载 Windows 每日定时计划任务
python -X utf8 -B scripts/维护清理/定时清理维护.py --run-now
python -X utf8 -B scripts/维护清理/定时清理维护.py --install --time 04:00
python -X utf8 -B scripts/维护清理/定时清理维护.py --status
python -X utf8 -B scripts/维护清理/定时清理维护.py --uninstall
```

`audit` 严禁删除任何文件或修改 `登记.json`，结果覆写单一文件 `自动维护/最近体检结果.json`（指标无变化不重复写盘）；[定时清理维护.py](定时清理维护.py) 的运行日志写入 `自动维护/定时维护.log` 并在超过 `512 KiB` 时自动滚动截断。

## 验证

```powershell
python -X utf8 -B scripts/维护清理/验证清理工具.py
```

验证在独立临时沙盒中运行，覆盖未登记、活动任务、七天期限、摘要变化、审批摘要、路径越界、回收恢复与永久清除；不会对项目存量调用回收或删除。
