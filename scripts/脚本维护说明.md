## 版本退役与缓存清理

所有制作会话在开始或续接新轮次时重读根指令和维护清理说明，另建本轮独立任务，开始及交付核对`清理工具.py status --task 本轮任务名`。此命令只汇总登记，不推断遗漏产物；交付须说明退役清单、缓存登记、验收及依赖交接状态，或无需处理的原因。工程师具体确认后，由负责会话执行`accept`登记，不能只口头确认；旧会话和旧候选不因此自动获得退役资格。

[维护清理工具](维护清理/清理工具.py)使用标准库完成任务登记、存量审核、冻结预览和回收恢复；[自动维护](维护清理/自动维护.py)处理启用后的新任务缓存及工程师逐版确认的历史退役，每天04:00调用`tick`，到期再次复核后清除。[占用检查](维护清理/占用检查.py)调用Windows Restart Manager，只查询，不关闭进程。旧存量、旧登记和旧回执不自动接管；任务启动及续跑前先登记读写依赖，状态不明时保护，清理登记不修改运行模块。完整丧尸群体候选在正式版接管证据后，可通过受限的`--release-bundle`逐文件登记全目录文件类型；它不适用于`src/`、`scripts/`、正式资料库或任意历史目录。命令、边界和七天规则见[模块说明](维护清理/README.md)，独立沙盒验证入口为[验证清理工具](维护清理/验证清理工具.py)。

当前策略条目的手动回收同样保留策略身份，以便后续`tick`按原回收时间处理。`repair-receipt`只显式修复已经属于当前策略的已完成漏标回执，须核验修复前摘要、实际注册及验收链；不自动接管旧回执，也不重置期限。具体用法见维护清理模块说明。

防堆积只读体检入口为`清理工具.py audit`（检查过期`active`任务、`tmp/`未登记目录、超大JSON与多代重复修订目录），系统级定时串联入口为[定时清理维护](维护清理/定时清理维护.py)（串联执行`tick`+`audit`并管理Windows每日计划任务），边界与SOP见[项目轻量化与定时清理规范](../docs/项目轻量化与定时清理规范.md)。

依赖位于 `local-data/tools/python-unity/` 的独立环境。执行提取脚本时使用该环境的 Python；构建脚本由本地配置中的 Blender 执行。工具源地址与校验值保存在本地工具台账。

场景数据保存每个预制体的原路径、节点变换、材质原字段、选用的最高细节 LOD、游戏状态隐藏规则和跳过原因。蒙皮按序列化初始骨架姿态转换为静态网格；保留骨架节点，但不冒充完整动画导出。单位运行时装配的炮塔与外挂需要另外确认映射。

这里的“骨架节点”在 Blender 中是空对象层级，当前构建器没有恢复 Armature、顶点权重绑定或动画曲线。`检查模型.py` 导出 GLB 时设置 `export_animations=False`；开启该选项无法补回上游未导出的绑定与曲线。动画片段及程序驱动动作需从源资源另行核查，当前静态模型不证明游戏资源缺少动画。故障定位与验收方法见 [资源提取与动画边界经验](../docs/项目开发经验/项目开发经验.md#静态层级与动画能力分别验收)。

虚拟纹理先按材质 `groupName/itemName` 精确关联，确认着色器图层含义后转换。原始贴图保留；派生法线、线性遮罩和每材质 ORM 不覆盖原件。Unity 自定义着色器在 Blender 的表现记录为近似还原，渲染成功与材质完全一致分别判断。

普通材质同时识别已实际出现的 `_BaseColorMap`、`_MainTex` 和乘员使用的 `_Albedo` 底色属性；`_NormalMap` 与 `_Normal` 法线按 Unity RG/AG 打包转换。未知 `_Mask` 不直接套用载具遮罩规则。Granite 提取加跨进程锁，避免两个进程独占打开同一 GTP 而失败；失败目录保留，重试使用新的目录。

批量构建最多两个并发工作进程，空中完成后再进入地面。每件产物拥有独立日志及检查文件；已有成功结果可复用，失败输出保留，修复后使用新输出目录。结构通过并不自动代表视觉通过，必须实际查看多视角及 GLB 回读图像，再写视觉判断记录。

基础预制体位于批次 `场景数据/`，默认装配场景位于 `装配场景/`。批量验证可用 `--scene-root 装配场景 --output-root 默认装配导出` 处理后者。装配矩阵是独立部件整体到目标载具坐标的变换，通过顶层父节点应用一次；保留各源内部骨架，避免再次挂到锚点而重复变换。

装配依据为当前数据库 `Units/TurretUnits/Modifications/Options`、Addressables 正式位置记录与预制体序列化安装字段。无显式默认选项时采用最小 `Order` 再最小 `Id` 的基础预设，记录策略；它不等同玩家已保存配置，也不代表所有改装组合。选项、源路径和锚点矩阵随每个场景保留。

UnitV4_Camo 使用第二 UV 采样迷彩，不能直接将两张图片按像素相加。构建器用临时网格进行 EMIT 烘焙，将线性颜色公式折算到 UV0 底色，保留原网格和双 UV；UV0 重叠导致的颜色非唯一需要视觉检查。ORM 先应用材质标量，再嵌入 GLB，避免导出器丢失复杂节点计算。

### 交付选择与模型库

批次 `交付选择.json` 的每项包含 `name`、`category`（`air/ground`）、`status`（`passed/partial`）、`variant`、批次相对 `source_output`、中文 `observations/limitations` 和路径到 SHA-256 的 `review_evidence`。通过项必须对应当前输出的四张预览与一张独立回读图，审核记录来自实际视觉检查。结构回执与两份载荷指纹同时核对，不能用旧图审核新产物。

生成器只接受批次内路径、拒绝覆盖已有模型库；复制后重新计算每个文件的 SHA-256。通过项按空中、地面分目录，未通过完整视觉检查的项进入 `待修参考/`。离线 HTML 提供型号搜索、分类和状态筛选及静态预览，不提供三维交互。整个模型库目录可一同移动，检查 JSON 中的历史绝对源路径仅用于追溯。

正式重建顺序为：准备缓存 → 导出基础场景 → 解析并合并装配 → 后台构建与结构检查 → 实际视觉审核 → 写交付选择 → 生成模型库。批次报告说明最终选用的版本，保留失败装配作为证据。当前已知缺失不凭名称猜配，不手工移动弹药来掩盖安装点不确定性。

读取游戏目录使用只读方式；输出路径从 `local-data/断箭/本地配置.json` 或明确的命令参数取得，并校验位于所选本地批次目录。每个批次保存输入清单、工具版本、验证结果和日志。调用外部工具使用 `subprocess.run([...])` 等参数列表方式。

[启动规范路由.py](界面规范/启动规范路由.py)保留独立轻测回环能力（默认 `8766`），而正式日常权威入口统一挂载在 [启动主服务.py](启动主服务.py) 的 `http://127.0.0.1:8800/ui-spec` 与 `/ui/*`。

[验证界面规范.py](界面规范/验证界面规范.py)使用 Playwright 串行驱动无窗口 Chrome 与 Edge（`device_scale_factor=2`），支持 `--base-url http://127.0.0.1:8800`，核验 Code SSOT V2.2 全部组件状态机、7 维语义色同源读取、12 类 `evenodd` 剪影＋情景图标、演训调试抽屉开合、680p 暖滤镜模拟下原生 DPR 高清叠加层隔离及密集编队防叠字降级。使用与参数说明见[规范工具说明](界面规范/README.md)。

## 每日工作快照采集与可视化看板

[生成每日工作快照.py](生成每日工作快照.py)仅使用 Python 标准库按北京时间（`UTC+8`）只读聚合 Antigravity/Codex 主会话轨迹、正式目录改动、`local-data/` 交付统计、`登记.json` 与 `验收待确认/` 状态，自动脱敏外部路径并输出 Markdown 或 JSON 草稿。

[生成每日工作日志页面.py](生成每日工作日志页面.py)读取 `reports/开发日志/数据/YYYY-MM/YYYY-MM-DD-开发日志.json` 编译生成 V4 单文件离线看板 [每日开发看板](../reports/开发日志/每日开发看板.html)（跨天唯一编号 `MMDD-01`、默认三列 Kanban 泳道、支持拖拽跨列、右侧滑出详情抽屉、`看板/简报`双视图与`深炭/浅灰`双主题，并支持 `--auto-date` 生成兜底 `auto-draft` 且不覆盖 `curated` 精炼版），日常由对话按需触发，命名规范由[检查项目结构.py](检查项目结构.py)强制校验，维护边界见[报告维护说明](../reports/报告维护说明.md#每日工作成果看板)。
