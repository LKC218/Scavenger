# 十三款丧尸资源制作

## 后续轮次的退役衔接

后续会话每轮重读项目根指令及[维护清理说明](../维护清理/README.md)，另建独立轮次任务，开始与交付运行`清理工具.py status --task 本轮任务名`。技术发布不代表人工外观和动作验收完成；工程师确认具体新版后，负责会话才可登记该轮精确退役清单。新增可再生成缓存冻结登记，交付说明清单、条目及暂缓原因。

原前两批76份候选经工程师另行要求立即清理，已在逐文件核对替代件、引用、任务及Windows占用后永久清除，共173484284字节。本轮只细化这76份的宽泛保护，不关闭其他任务登记。当前13款、双档模型、最新工程、原件及冻结性能交付保留；后续轮次继续遵守七天规则。本模块的制作和发布脚本不执行删除。

原冻结候选CSV／JSON保持原字节；`批次003/待审清单/清理执行引用.json`引用本地`维护清理/十三款立即清理-261103/执行结果.json`及摘要。报告生成器核对完成回执、原清单及旧路径不存在后显示已清除，不重新生成或将零候选写回原清单；不修改历史技术回执中的来源路径。清理执行器只保留在本机凭证目录，不接入定时任务。

本模块按[已批准计划](../../docs/丧尸十三款拆分入库与混合群体-实施计划.md)处理独立角色。输入为统一归档恢复的只读原包，输出为专项递增批次；编号0保留既有稳定ID及资源。原始动作保真检查与项目自制循环分别核验，禁止静态减面。

制作、双档派生、独立回读及双浏览器检查通过后，才允许统一库增量发布。人工外观和动作验收保持待验收。本模块不删除、不回收、不提交Git，不修改群体运行代码。

## 实际入口

| 文件 | 职责 |
| --- | --- |
| `制作角色.py` | 后台Blender按源网格编号拆分，加权骨及祖先闭合，721点原动作保真，身体坐标、自制循环、逐帧落地和内嵌工程 |
| `派生规格.mjs` | 256／512贴图、材质简化、Meshopt；回读比较节点、权重、动作及保绕序拓扑 |
| `回读角色.py` | 新进程只读重开工程及最终双档GLB，检查骨架、权重、内嵌图与循环 |
| `验证角色.py` | Chrome／Edge真实蒙皮顶点、与制作GLB对照、动作混合、资源释放及多视角图 |
| `交付资源.py` | 检查真实回执，冻结12款入库清单及13款唯一交付JSON |
| `回归固定入口.py` | 8767新增卡片双档及8768三模型13声音的串行技术回归 |
| `生成资源报告.py` | 从回执生成离线HTML、技术JSON／CSV及精确候选；已清理时核对执行引用并展示清除结果；只读引用同交付的性能报告，不执行删除或采样 |

运行依赖项目已保留的Blender、Node、Python Playwright及固定Node资源处理库；不安装新依赖。命令由参数数组传入，输出批次必须新建。新12款使用Meshopt和内嵌PNG，支持直接Blender回读；编号0保持既有KTX2资源和稳定ID。动作采用共同来源尺度，保留各款真实身高差异，编号11约0.967米；没有补造头颈骨或足部IK。逐帧落地只处理整体高度，不能称为真实步态捕捉。

## 执行顺序

以下为入口示例，`blender`使用调用方已核对的可执行文件，`新批次`须替换为未使用的批次名；逐角色制作串行执行编号1至12。不要直接重跑已冻结003，避免覆盖既有证据。

```text
blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python scripts/丧尸十三款/制作角色.py -- --index 1 --output local-data/丧尸模型/十三款优化/新批次/角色01
node scripts/丧尸十三款/派生规格.mjs local-data/丧尸模型/十三款优化/新批次
blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python scripts/丧尸十三款/回读角色.py -- --batch local-data/丧尸模型/十三款优化/新批次
python -X utf8 -B scripts/丧尸十三款/验证角色.py --batch local-data/丧尸模型/十三款优化/新批次
python -X utf8 -B scripts/丧尸十三款/交付资源.py prepare --batch local-data/丧尸模型/十三款优化/新批次
```

`prepare`只冻结待入库清单；发布另调用统一库入口并传入该清单的预期版本与指针摘要。发布后运行固定入口回归，再由资源唯一写入方调用`freeze`冻结交付；已有交付拒绝覆盖，更新前需与性能方协调样本失效范围。`生成资源报告.py`只读取最终批次和交付，其待审候选只列本专项001／002历史工程及GLB，不包含当前批次、原件或其他任务。

冻结003交付已被性能对话接收；任何资源或索引改变都需要重新协调，不能静默更新正在采样的文件。规范落实与缺口见本地`规范落实记录.json`，方法依据[模型与音频优化复用指南](../../docs/项目开发经验/模型与音频优化复用指南.md)，其中revision 3案例保持历史口径。
